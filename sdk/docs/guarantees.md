## 02　版

### 変更の 3 つの分類 [P]（DR-092 (2)）

ROM 作りを始める線は、ソフトから見える約束（アドレスマップ、レジスタ、待ち、Data Fabric と ACRTC の時刻のうちソフトが頼るもの、BIOS の約束）が固まったときとした（DR-092 (1)）。その後の SDK とエミュレータの変更は次の 3 つに分ける。

| 分類 | 中身 | 扱い |
|---|---|---|
| 中だけの変更 | ソフトから見える動きが変わらない | 自由に入れる |
| 通常モードの時刻が変わる変更 | ソフトから見える時刻が変わる | DR と変更の記録を書き、ROM の回帰試験を通す |
| 約束が変わる変更 | 上の約束が変わる | SDK の版を上げる |

### 版の番号

| 版 | 見る場所 | 決まり |
|---|---|---|
| BIOS の版 | ROM の $000480 の語 `BIOS_INFO_VERSION`、カートリッジの入口の D0.L、窓口の `info` の `bios_version` | 版 1＝$0001（DR-057）、版 2＝$0002（DR-094・DR-095）。版 n の約束は版 n＋1 からも守り、後の版は足すだけ。ROM の中身の版で、基板やエミュレータの版ではない。約束が変わらなければ上げない [P]（bios-abi.md §11） |
| カートリッジの見出しの版 | 見出しの +$04 | $0001 [P]（bios-abi.md §04） |
| 窓口の手順の版 | `info` の `api_version`（今は 0.1） | 答えに項目を足すだけなら小さい方、要求や答えの形を変えたら大きい方を上げる [P]（emulator-api.md §01） |
| エミュレータ・SDK の版 | `info` の `emulator_version` | 版を付けて配ると決めた（DR-092 (5)）。番号の決まりはまだない |

版 2 の BIOS で足したものを使うときの確かめ方は §03 の「BIOS」。

## 03　ROM が守ること

ソフトの規約と、守らないと結果が決まらないもの。規約に反するアクセスも止まらずに実行される。DR-016・DR-030 の違反は、エミュレータでもどちらのモードでも実機と同じに実行し、通常モードでは一部を警告する（§06。DR-065 (2)）。

### バスとメモリ

1. 16 bit のレジスタは語でアクセスする。バイトのアクセスはバスエラー [P]（仕様書 §05、DR-052 (2)）。
2. 8 bit の IC は上位バイトレーン（偶数番地）。DOC は UDS だけの 1 byte、ACIA は UDS を含むアクセスに答え、LDS だけならバスエラー [P]（DR-052 (2)）。
3. DOC の窓に触る前に、子基板があるかを入口の D1.L か `bios_modules` の bit 2（`FABRIC_MOD_DOC`）で確かめる。子基板がないとき DOC の窓はバスエラー、あるとき本体 DAC の窓（$230010〜）はバスエラー [P]（DR-019、DR-053 (3)）。
4. Staging RAM の上の TAS は Data Fabric に対して不可分にならない。CPU と Fabric の受け渡しは Fabric の状態レジスタで行う [P]（DR-024）。
5. Main RAM は $100800 から先をアプリが使い、スタックは $120000 から下へ。ジャンプ表（$100000〜$1005FF）は項目の番地（＋2 の長語）だけを書き換える [P]（DR-025、bios-abi.md §03）。

### ACRTC（HD63484）

6. AR/STATUS とデータポートに、CLR・TAS などの読み書き一体の命令を使わない [P]（仕様書 §05、DR-016）。
7. FIFO は SR の WFR（`ACRTC_SR_WFR`、書ける）・RFR（`ACRTC_SR_RFR`、読める）を見てから読み書きする [P]（仕様書 §07、DR-033、DR-096 (1)）。FIFO は 8 語なので [D]（台帳 [HD63484.md](../../docs/parts/HD63484.md)）、WFE（空）を見たら 8 語を続けて書ける（BIOS の書き方 [P]。bios-abi.md §05、DR-094 (5)）。
8. Data Fabric の port 1 で DMA している間は、CPU から FIFO にアクセスしない [P]（仕様書 §05、DR-016）。
9. port 1 でデータを DMA するときは、CCR の DDM を立て、転送の前に DWT・DRD・DMOD を AX・AY とともに出す。矩形（x 語×y 行）の形はこのコマンドで決まり、チャネルの COUNT は x·y にする [D]（[15]）[P]（仕様書 §06、DR-022、bios-abi.md §06）。DONE と COUNT が合わなければチャネルは ERROR になり、CPU が CCR の ABT で ACRTC を止める [P]（DR-022）。
10. コマンドの DMA（CCR の CDM＝1）では、チャネルは最後の要素で ERROR になる（受けた語は全部実行する）。CPU が CDM を 0 にして終える。コマンドの列に DWT・DRD・DMOD を入れない [D]（[15]）[P]（仕様書 §06、DR-093）。
11. WSS＝0 のウィンドウを DISP2 にそろえるときは、HWS を 1 小さくし、ウィンドウの左の 1 語を捨てる [P]（仕様書 §07、DR-096 (3)）。基本画面で横のズームを使うと、同じラスタのウィンドウも横に伸びる [P]（DR-069）。

### DOC（ES5503）

12. DOC の窓（$210000〜$2101FF）は MOVE.B の 1 回の読みか 1 回の書きだけで触る。読み書き一体の命令（メモリ形式の CLR・Scc・NBCD・NEG・NEGX・NOT・TAS、BSET・BCLR・BCHG、メモリを宛先にする算術・論理命令）と MOVEM・MOVEP を使わない [P]（仕様書 §05、DR-030）。
13. 0xE0（`DOC_IRQ`）と 0xE2（`DOC_ADC`）は読むと状態が変わる。TST・BTST・CMP で読まない [P]（DR-030）。
14. DOC の割込み（レベル 4）を使うアプリは、オシレータの IE を立てる前に、ジャンプ表のベクタ 28 の項目を書き換える [P]（DR-076 (4)、bios-abi.md §03）。
15. 走査の数（0xE1、`DOC_OSC_ENABLE`）を増やすときは、増やすオシレータの制御を H＝1・IE＝0 で書き、続けて 0xE1 を書く（割込みを止めて続けて書く）。周波数・音量・波形の番地と大きさは走査に入れた後で書き、最後に H を下ろす。走査の外のオシレータのレジスタは崩れているため [P]（DR-094 (7)、DR-074、bios-abi.md §06）。
16. 鳴らさないオシレータは、鳴らすオシレータと別のチャンネル（CA）に置く（BIOS は CA 15 に置く）[P]（bios-abi.md §06）。理由の動き（止めたオシレータも走査の中で中央の値を出す）は [V]（OI-062）。
17. 波形のデータの 0 はオシレータを止める印で、使える値は $01〜$FF [D]（台帳 [ES5503.md](../../docs/parts/ES5503.md) §4.4）。

### ADPCM（MSM5205）

18. RESET を外すのは、STATUS の bit 10（`ADPCM_ST_VCK`、V̄C̄K̄ のピンのレベル）の立下りから 16 µs（取込み）より後、次の立上りの前（8 kHz で約 47 µs の間）にする。立上りと取込みの間に外すと、RESET の前のニブルが 1 つ復号される [P]（仕様書 §05、DR-096 (4)）。
19. または DR-060 の手順を使う：鳴らす前にチャネルを STOP し、STATUS を W1C し、CTRL に RESET と S1・S2 を書き、PORT_RESET の bit 5 で FIFO を空にして 1 フレーム置く。START の後、FIFO に 16 byte たまってから UNDERRUN を消し、RESET を外す。DONE が立って FIFO が空になったら STOP し、RESET に戻す。鳴っている音を替えるときは、RESET をかけずに FIFO を空にする [P]（DR-060 (2)、DR-096 (4)）。
20. CTRL の S1・S2 を両方 1 にしない。データシートで禁止で、本機では Bend の操作 [D]（台帳 [MSM5205.md](../../docs/parts/MSM5205.md)）[P]。

### Data Fabric

21. レジスタは 16 bit の語のアクセスだけ。8 bit のアクセス、チャネル 2・3 の窓、各チャネルの $20〜$3E、$250106 から先はバスエラー [P]（DR-046 (10)、fabric.md §07）。
22. 設定のレジスタはチャネルを止めてから書く。動作中の書換えは Bend の操作 [P]（仕様書 §06、DR-046 (4)）。
23. STATUS の DONE・ERROR・MISS は W1C でだけ消え、START では消えない。START の前に消す（`FAB_ST_W1C`）[P]（impl/emulator.md §03 の Data Fabric、DR-060 (2)）。
24. TRIGGER の発生源を替えてから START するときは、TRIGGER の書込みの S0 から START の S0 まで 4 スロット（1 µs）以上あける。選んだ入力が High なら立上りとして伝わるためで、TRIGGER と CTRL を MOVE.L で続けて書くと 3 スロットになり、最初の立上りを数えるかは決まらない [P]（仕様書 §06「CPU のアクセスの時刻」、DR-098）。
25. START で ERROR になる組合せを使わない：実装されていないポート（`FABRIC_MODULES` で確かめる。DR-019）、向きや幅が FORMAT と合わないもの（例：port 3 から読む、8 bit のポートに 16 bit の FORMAT）、FORMAT 6・7 [P]（DR-046 (9)、fabric.md §06 の表）。
26. TRIGGER の発生源 6・7 は予約で、トリガは来ない [P]（DR-046 (8)）。
27. 動作中に、ポートのアクセスが 32 クロック（4 µs）以内に終わらないとき、port 1 の DONE と COUNT が合わないときも ERROR。チャネルは止まり、動いている要素は捨てる [P]（DR-046 (9)）。

### DSP（TMS32010）

28. プログラム RAM（$280000〜、`DSP_PROGRAM`）は、CTRL の RESET を 1 にし、STATUS の PRGBUS が 1 になってから読み書きする。それ以外はバスエラー。ロードは約 6 ms [P]（仕様書 §05、DR-029）。
29. DSP のプログラムは TBLW で 0〜7 番地に書かない（OUT と同じになる。SDK で禁じ、エミュレータが警告する）[P]（仕様書 §07、DR-029）。

### 割込みと入力

30. INPUT_IRQ_STATUS の bit 0・1・3 は W1C。bit 2（MIDI）は ACIA の IRQ̄ の写しで読み専用。ACIA の状態→受信データの順に読んで消す。bit 4（カートリッジ）は読み専用で割込みにならない。INPUT_IRQ_ENABLE の bit 2 は使わない [P]（仕様書 §09、DR-028、DR-053 (5)、DR-095）。
31. レベル 2・3（DSP・Data Fabric・ADPCM）の割込みを許可する前に、ジャンプ表の項目を書き換える。BIOS の既定の処理は致命的な例外で止まる [P]（bios-abi.md §03）。
32. ジャンプ表の項目は、割込みのマスクを上げて書き換え、前の番地を残す。BIOS の処理へつなぐときは、レジスタとスタックを入ったときの形（SP の上に例外の枠）に戻して前の番地へ飛ぶ。レベル 6 を BIOS へつながないと、`bios_frame` が進まず `BIOS_WAIT_VBL` が戻らない [P]（bios-abi.md §03、DR-094 (1)）。

### BIOS

33. 呼出しは JSR で、スーパバイザで呼ぶ。1 回の呼出しで SSP の下へ 256 byte まで使う（割込みの処理の分は別）[P]（bios-abi.md §05）。
34. ACRTC を使う呼出し（`BIOS_ACRTC_SEND`・`BIOS_CLS`・`BIOS_PUTS`・`BIOS_PUT_HEX`・`BIOS_PUTS_KUTEN`）は再入できない。割込みの処理（VBlank のフックを含む）から呼ぶのは、割り込まれた側が ACRTC を使っていないときだけ [P]（bios-abi.md §05）。
35. 0.4 秒より長くかかる正しいコマンドは `BIOS_ACRTC_SEND` で送らず、自分で FIFO に書く。BIOS の見張りが打ち切る [P]（DR-080、DR-082、bios-abi.md §05）。
36. 版 2 で足したもの（`BIOS_PUTS_KUTEN`、`BIOS_GLYPH`、`bios_acrtc_aborts`、`bios_acrtc_abort_sr`、ACRTC を使う呼出しの Z、INPUT_IRQ_STATUS の bit 4）を使う ROM は、使う前に `CMPI.W #2,BIOS_INFO_VERSION` で確かめ、小さければ自分の画面で知らせるか、版 1 の呼出しだけで動く道に分ける [P]（bios-abi.md §11）。
37. BIOS の変数は「書いてよい」もの（`bios_vbl_hook`、`bios_input_status`、`bios_midi_tail`）だけを書く。VBlank のフックは D0–D1/A0–A1 のほかを壊さない [P]（bios-abi.md §03）。
38. カートリッジの見出しは $400000 の 32 byte（印 `'CART'`、版 $0001、入口は $400000〜$4FFFFF の偶数番地）。外れると BIOS は内蔵のデモへ進む [P]（bios-abi.md §04）。

## 04　頼ってよいこと

ソフトに約束したもの。変えるときは SDK の版を上げる（DR-092 (2)）。BIOS の約束は後の版でも守る（bios-abi.md §11）。

- **アドレスマップ**：仕様書 §05 の表 [P]。未割当の番地と不正な幅はバスエラー（AS↓ から 64 クロック）、Boot ROM とカートリッジの窓への書込みは DTACK を返して捨てる [P]（DR-052）。外部クロックで遅くした DOC・ACRTC・パレットの窓は、時間切れを DTACK で終え、書込みは届かず $FFFF を読む [P]（DR-079）。
- **レジスタとビット**：仕様書 §05・§06・§09、DR-046、DR-053 [P]。書込み専用のレジスタは読むと 0、読出し専用への書込みは捨てる [P]（DR-053）。名前は fc85.inc。
- **割込み**：すべてオートベクタ。6＝映像（VBlank・HBlank、ACRTC の IRQ）、5＝ACIA、4＝DOC、3＝Data Fabric・ADPCM、2＝DSP、1＝入力。レベル 7 には要因がない [P]（DR-028、DR-095）。
- **映像**：256×192・4 bpp、262 ライン・342 ドット、約 59.92 Hz [P]（DR-002）。語の中の画素は左端が LSB 側 [D]（仕様書 §07）。パレットは `$0RGB`×16 の書込み専用の語で、次のラインから効く [P]（DR-027、DR-053）。描いている途中が画面に出る [P]（DR-070）。
- **ACRTC のコマンドの DMA** が使える [P]（DR-093）。port 1 の速さの目安は、Staging RAM から 1 語 6 か 8 スロット（1.5〜2.0 µs）、Temporal RAM から 6 か 7 スロット、全画面（12,288 語）で約 18〜25 ms で、1 フレームに入らない [P]（仕様書 §07、DR-096 (2)）。
- **Data Fabric のレジスタへのアクセスの時刻** [P]（仕様書 §06「CPU のアクセスの時刻」、DR-098）：待ちの数と、書いたことが効くスロットは、バスサイクルの S0 のスロットと位相だけで決まり、転送の状態に左右されない（たとえば CTRL と STATUS の W1C はスロット n+3 から効く）。この時刻にサイクル単位で頼ってよいかは未決（OI-100）。
- **Data Fabric の決めた動き** [P]（DR-046）：変換は FORMAT と SHIFT → AND MASK → XOR の順。COUNT＝0 の START は転送せずに DONE。STOP は次のスロットから効き、書込みの済んでいない要素を捨てる。トリガは 1 件だけ保留し、保留中の分は MISS に記録。MASK・XOR はリセットでは変わらない（BIOS が起動時に $FFFF・0 を書く）。port 0 は 500 ns ごとに 1 語を保証する（DR-024）。
- **待てない IC の側の FIFO** [P]（DR-017、DR-019）：DSP が空の入力 FIFO を読むと最後の語、満杯の出力 FIFO への書込みは捨てる。ADPCM の FIFO が空なら 0x08 を供給する。本体 DAC の FIFO が空なら直前の値を保つ。どれも UNDERRUN／OVERRUN を記録する。
- **入力**：PORT_A・PORT_B は active-high で、bit 0 上、1 下、2 左、3 右、4 A、5 B、6 C、7 START [P]（DR-055）。カートリッジの有無は INPUT_IRQ_STATUS の bit 4 [P]（DR-095）。
- **BIOS の保証すること**（bios-abi.md §11）[P]：Main RAM の分け方とジャンプ表の形、表にある BIOS の変数、割込みの既定の処理が消す保留とつなぎ方（BIOS の処理はすべてのレジスタを保ち、USP を使わない）、見出しと入口の条件（§04）、呼出しの番地・入力・出力・共通の約束（出力のほかの D0–D7・A0–A6 と USP を保つ、割込みのマスクを変えない）と FIFO の打切りの返し方（Z）、初期状態（ACRTC、座標、パレット、黙らせた音）、DOC の走査を増やす順、区点から字形への引き方と〓。BIOS の呼出しは、MASK・ORG・パターン RAM・ACRTC の CCR・OMR・DCR を、打切りの ABT のほか変えない。
- **文字 ROM の配置**：英数かな 256 字枠、非漢字 1〜8 区、第一水準 16〜47 区の offset と、CPU の番地 $010000＋offset×2（上位レーン）[P]（仕様書 §08、DR-031）。

## 05　頼ってはいけないこと

### BIOS の内部と時間（bios-abi.md §11 の要約）

- 呼出しの入口の先の番地、ROM の中の表、§03 の表にない変数の番地、BIOS が使うスタックの中身、予約の番地（$000436〜$00047F、$000482〜$0004FF）。
- 呼出しと割込みの処理にかかる時間（bios-abi.md §07 の表は参考の [V]）、起動のフレーム数、打切りの見張りの正確な長さ。時間に頼るなら VIDEO_LINE や `bios_frame` で測る。
- CCR（Z を出力とする呼出しのほか）、ACRTC を使う呼出しの後の RWP・描画の点（CP）・CL0・CL1、打ち切った（Z＝0）呼出しの描画の中身。
- 起動の画面と音、内蔵のデモ、入口のときの VRAM の画面の外と $100800 から先の Main RAM。
- 割込みの処理が保留を見る順、レベル 7、電源を入れたままのカートリッジの抜き差し、ユーザーモードからの呼出し。

### 待ちと時間

- 68000 から ACRTC へのアクセスの待ち（2〜4 ウェイト）の数 [P]（DR-096 (1)）。
- 動作中のチャネルの設定のレジスタを書いたとき、スロット n+3 の中ほどから n+4 の頭までに古い値と新しい値のどちらが使われるか [V]（仕様書 §06、OI-092）。止めてから書けば影響はない（§03 の 22）。文字 ROM と port 9 の取り合いの待ち（3〜5 クロック）[P][V]（DR-031。エミュレータは数えない）。
- Data Fabric の理論予算（最大 4 MB/s）は上限の試算で、実効帯域を保証しない [P]（仕様書 §07）。全画面を 60 Hz で描く・送る運用は成り立たない見込み [V]（仕様書 §07）。

### 決めていない状態と、使えない機能

- ACRTC の満杯の FIFO への書込みと、空の FIFO からの読出しの結果。エミュレータは書込みを捨て、0 を読む [P]（DR-096 (1)）。
- ACRTC の文字画面とブロックカーソル、ライトペン、インタレース（RSM≠00）、重ね合せの表示（ACM＝11）、ウィンドウのスムーズスクロール（WSS）。本機の回路で使えず、設定したときの画面は決めない [P]（仕様書 §07、DR-093）。
- 電源投入時の値：ACRTC の DCR（不定。BIOS が $4000 を書く。DR-071）、本体 DAC のラッチ [V]（OI-061）、MSM5205 の中の状態 [V]（CTRL の RESET は電源投入時 1。DR-053）、TMS32010 の内部 RAM [V]、Temporal RAM の書いていない番地 [P][V]（DR-067）。
- 走査の外の DOC のオシレータのレジスタ。更新されないと崩れる [D]（台帳 ES5503.md、DR-074）。保持時間（25 °C で最短 2 ms）と崩れた値（1）は [P][V]（DR-074、OI-071）。
- RESET 命令が Data Fabric と ACIA を変えないこと [V]（DR-052 (3)）。
- 拡張バスの割込みのレベル。未決 [O]（OI-091）。

### Bend の操作

仕様書が Bend の操作・材料とするもの。通常の動きとしては約束しない：動作中の Data Fabric の設定の書換え（DR-046 (4)）、PAL_CTRL の DIRECT（ライン途中の色替えと点状のノイズ。見え方は [V]。DR-027）、ADPCM の置換しない動作（`ADPCM_CTL_NO_REPLACE`。DR-017）と S1＝S2＝1、DSP の TBLW の 0〜7 番地（Bend の候補。DR-029）、仕様書 §11 のベンド点 [P]。

### 実チップと照合していない動き

エミュレータの IC のコアは、単体試験（V2）と MAME との照合（V3）まで。68000 は SingleStepTests と 99.43% 一致。実チップでの確認（V4）はどの IC もまだで（OI-085）、ES5503 は MAME が IIGS で測った動きに合わせた（DR-087）。次の [V] の動きはソフトに効くので頼らない（[impl/emulator.md](../../docs/impl/emulator.md) §03）。

| IC・回路 | 頼らない動き [V] |
|---|---|
| HD63484 | 未定義のコマンドの後（CER。エミュレータは ABT まで何もしない）。領域モードで止まった後の CP。CPY・SCPY で転送元と転送先が重なるときの順。CLR・SCLR の後の RWP。直線・円・弧の画素の選び方（1 画素ずれうる）。終点が曲線の外にある弧。塗った色が縁にならない PAINT（実チップは終わらないかもしれない）。DMA の DRD の終わりの CED。バーストの DMA（DRC＝0）。コマンドの DMA の方式（資料の中で食い違う。OI-085）。ラスタの途中で書いたレジスタが効く時期（1 ラスタずれうる）。WSS＝0 のウィンドウの 4 ドットのずれ（§03 の 11 はこれによる）。描画の時間が表示との取り合いを含むか |
| ES5503 | 止めたオシレータの出力（OI-062）。割込みの規則（IE＝0 で終わったオシレータに後で IE を立てても割込みは来ない）。0xE1 を書いた後の走査の始まり（BIOS は 32 個の制御を書いてから 0xE1 を書く）。レジスタの保持時間（OI-071）。音量の特性（非線形。DR-087） |
| MSM5205 | 電源投入時の状態。短い RESET のパルス |
| TMS32010 | 電源投入時の RAM（初期化してから使う）。144〜255 番地。スタックの 5 回目からの POP。未定義の命令と SACH の未定義のシフト。LAR・LST を間接で使い同じ AR・ARP を変えるとき |
| HD68000 | グループ 0 の例外の枠の PC と I/N の極性（枠を見てバスエラーから再開する処理は実機と違いうる）。0 除算で資料が不定とするフラグ |
| Data Fabric | 67401 の通り抜けの時間（空の FIFO に書いてすぐ読む転送が実機より早い可能性）。LOOP で COUNT の設定値が 0。AUDIO_N の 0（エミュレータは 4096 として数える）と、2 以下でトリガの立上りが出ないこと |
| 本体のバス | ACRTC の FIFO が満杯のときの DTACK の遅れ。文字 ROM と port 9 の取り合い |

## 06　エミュレータが約束すること

### 決定的

- 同じ ROM・同じ設定・同じ要求の列なら、同じ結果になる。`run` は、止める条件に当たらなければ、ホスト（`fc85`）で同じフレーム数を同じ入力で進めたときと同じ状態になる [P]（emulator-api.md §01、DR-097 (3)）。窓口で見つけた不具合をホストでそのまま再現できる。
- ブレークポイントで止めた後は基板を追いつかせる区切りがずれるので、止めずに進めたときとクロック単位で同じとは限らない。同じ要求の列なら同じ結果になる（emulator-api.md §04）。
- 調べる手順は仮想機を変えない。`peek` はバスを通さず、時刻も状態も変えない（`poke` もバスを通さずに書く試験の道具で、ROM も書ける）。発音の記録、見張り、命令の記録を取っても状態は同じ。`bus_read`・`bus_write` だけは CPU と同じバスサイクルで、I/O の副作用が起き、バスエラーを数える（emulator-api.md §03・§04）。

### 通常モードと Bend モード [P]（DR-065）

- 通常モードは工場出荷の機械で、ベンド点に何もつながない。Bend モードのときだけベンド点の設定を回路に入れる。設定はモードを切り替えても残り、状態の保存に入る。今のモードは `info` の `mode`。
- ソフトの規約の違反（DR-016、DR-030）は、どちらのモードでも実機と同じに実行する。警告は通常モードだけ。
- エミュレータだけの内部介入は Bend モードのときだけ効かせる。DRAM と DOC のレジスタの保持の模型は、通常モードでは個体 0・25 °C（DR-074 (3)）。

### 窓口の数字の意味（emulator-api.md §04）

| 数字 | 意味 | 意味しないこと |
|---|---|---|
| `bus_errors`・`bridge_timeouts`・`doc_rule_warnings` | その `run` の間のバスエラー、DTACK で終えた時間切れ（DR-079）、DOC の窓の規約（DR-030）の警告の数 | ACRTC の規約（DR-016・DR-033）の違反は数えない。TST・BTST・CMP で 0xE0・0xE2 を 1 回読む違反も見分けない [V]（impl/emulator.md §03） |
| `budget` の `cpu_busy` | 68000 が STOP で待つ間と、`idle` で示した番地の命令を空きとして数えた残りの割合 | 自分で VBlank のフラグを回して待つループは、`idle` で示さないと働いた時間に入る |
| `budget` の `acrtc_busy` | ACRTC がコマンドを実行している時間の割合（命令の切れ目ごとに見る） | 描画の時間は U85 の式と表示との取り合いの模型 [P] で、式が表示との競合を含むかは [V] |
| `budget` の `fabric_busy` | Data Fabric のどれかのチャネルが動いている時間の割合 | — |
| `budget` の `_max` | いちばん重いフレームの値（`_max` のないものは実行全体の値） | — |
| `screen_hash` | 表示の範囲（256×192）の画素の FNV-1a（64 bit） | 暗号の強さはない |
| `voices` | 64 クロック（8 µs）ごとに見た、有効なオシレータの停止ビットの変化（最大 2,000 件） | 8 µs より短く鳴って止まった音、止めずにレジスタだけを替えた音は出来事にならない |
| `audio` | 溜めた音（最大 60 秒）の `peak`・`rms`、WAV は 48 kHz・16 bit・ステレオ | — |
| `watch_hit` | 命令ごとに見た見張りの範囲の中身の変化と、変化を見つけた命令 | 同じ値の書込みと読出しは拾わない。DMA が書いた変化も次の命令に付く |

予算は、仕様書の時刻（多くは [P]）をエミュレータで数えた値。§02 の「通常モードの時刻が変わる変更」で変わりうる。

## 07　確かめ方

ROM の回帰試験の要点。手順の詳細は [emulator-api.md](emulator-api.md)。

1. 組むときにリストを作る（ひな形の `build.py` は `build/rom.lst` を書く。m68kasm を直に使うなら `-l`）。カートリッジの横の `.lst` は `load` が自動で読み、番地をラベルで書ける。新しい ROM は `py sdk/tools/new_rom.py` でひな形（[sdk/template/](../template/AGENTS.md)）から作ると、組立てと試験の形がそろう（DR-102）。C の ROM では `build.py` が GCC の出力から同じ形の記号の表を書く（[c.md](c.md) §09、DR-103）。
2. `fc85-api`（JSON の手順か `--mcp`）で `load`（`cart`。`doc` を false にすると DOC の子基板なし）し、`run`（`frames`、入力の台本 `input`、`stop_on_bus_error`）で進める。
3. `stop` が `frames`、`bus_errors`・`bridge_timeouts`・`doc_rule_warnings` が 0、`info` の `mode` が `normal` であることを見る。§06 のとおり、ACRTC の規約は窓口が数えないので、コードで守る（§03 の 6〜8）。
4. 画面は `screenshot`（PNG）と `screen_hash`、音は `audio`（WAV、`peak`、`rms`）と `run` の `voices` で比べる。
5. 予算は `run` の `budget`。自分の待ちのループは `idle` で示す。BIOS の `BIOS_WAIT_VBL` は STOP なので示さなくてよい。
6. 不具合は `save_state`・`load_state`、`break`、`watch`（メモリの中身が変わったら止める）、`trace`（最後に実行した命令）、`regs`、`peek` で追う。同じ要求の列で再現する（§06）。Python の試験からは `sdk/tools/fc85emu.py` で同じ手順を呼べる。
7. BIOS の版は `info` の `bios_version` で見る。子基板のあり・なしは MODULES で変わるので、両方で動かすと §03 の 3 を確かめられる。
