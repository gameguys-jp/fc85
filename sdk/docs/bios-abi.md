## 02　起動の順

リセットで SSP＝$120000、PC＝$000500 を読む。ベクタ 2〜255 は ROM の中で Main RAM のジャンプ表（$100000＋6n）を指す [P]（DR-025）。

| 順 | すること | 状態 |
|---|---|---|
| 1 | SR＝$2700。BIOS の変数（$100600〜$1007FF）を 0 にし、ジャンプ表の 256 項目を `JMP abs.L` で埋める（§03） | [P]（DR-025） |
| 2 | Data Fabric の両チャネルを止め、MASK＝$FFFF、XOR＝0、SHIFT＝0、FORMAT＝0、TRIGGER＝0 にし、STATUS の DONE・ERROR・MISS を消す。AUDIO_N＝500（16 kHz）。MODULES を `bios_modules` に写す | MASK・XOR は仕様書 §06（DR-046）。ほかは [P] |
| 3 | ACRTC：CCR に ABT を立てて打ち切り、案B のタイミング（§06）、CCR＝$0200、OMR＝$C008 で表示を始める。パターン RAM を 0、MASK＝$FFFF、ORG を基本画面の語番地 0 にする。パレットを既定の 16 色にし、画面を色 0 で消す | 値は台帳 HD63484.md §3.4。CCR の DDM＝0 は [P] |
| 4 | 音を黙らせる：DOC の子基板があれば（MODULES の bit 2）32 個のオシレータを止めてチャンネル 15 に置き、音量 0、0xE1＝$1E（16 個を走査）。なければ本体 DAC を DIRECT にし、DATA＝$8080（中央） | [P]（DR-019。§06） |
| 5 | ACIA に $03（マスタリセット）、続けて $95（÷16＝31.25 kbit/s、8N1、受信の割込み）。INPUT_IRQ_STATUS を消し、INPUT_IRQ_ENABLE＝PORT_A・PORT_B の変化 | ACIA の値は [D]（HD6850）。許可の選び方は [P] |
| 6 | VIDEO_IRQ に VBL_EN（古い保留も消す） | レベル 6（DR-028、DR-053） |
| 7 | SR＝$2000（割込みを受ける） | — |
| 8 | INPUT_IRQ_STATUS の bit 4（/CART）でカートリッジを差しているかを見る。差していれば $400000 の見出しを調べ、正しければその入口へ飛ぶ（§04）。見出しを読む間だけバスエラーの項目を差し替える（接触の不良などで窓がバスエラーになっても止まらないため）。差していなければ窓を読まないので、バスエラーは出ない | [P]（DR-095） |
| 9 | なければ内蔵のデモ（§08） | [P] |

### 最初の画面（カートリッジなし）

エミュレータで見ると、1 フレーム目は表示が途中のラインから始まり（上は黒、下はデモの背景の色 1）、2 フレーム目に帯と見出し、3〜4 フレーム目に線・文字・円と箱が描かれ、5 フレーム目からは次の絵がそろう。

- 上の 16 ラインは青い帯で、左に `BOOT ROM DEMO`、右に `ﾊﾛｰ`（白）。
- その下に `FRAME`（VBlank の数、16 進 8 桁）、`PAD`（PORT_A、16 進 4 桁）、`SOUND DOC`（子基板がないときは `SOUND DAC`）、ボタンの 8 つの箱と `U D L R A B C S`、`ABC ｷｰ ｦ ｵｽ`。
- 真ん中は水色の枠と、下の真ん中から上へ広がる紫の 9 本の線。中を淡い黄の円が回り（約 1 秒で 1 周）、赤い 10×10 の箱がある。
- 下はパレットの 16 色の帯。背景は濃い紺（色 1）。
- 起動の直後に C5、約 0.2 秒後に G5 が鳴り、約 0.5 秒で消える。

### ジャンプ表の既定の中身 [P]

| ベクタ | 処理 |
|---|---|
| 0・1 | 使わない（止まる先） |
| 2〜23、32〜255 | 致命的な例外：ROM の小さな入口がベクタ番号を積み、SR・PC と（バスエラー・アドレスエラーなら）アクセスの番地を BIOS の変数に残し、ACRTC を初期化し直して、赤い画面に `EXCEPTION`・`PC`・`SR`・`ADDR` を 16 進で出し、`STOP #$2700` で止まる |
| 24（スプリアス）、31（レベル 7） | 数えて RTE。レベル 7 は予約（DR-028）で、本機にレベル 7 の要因はない（DR-095） |
| 25（レベル 1：入力） | INPUT_IRQ_STATUS の bit 0・1・3 を消して `bios_input_status` に貯め、数える |
| 26・27（レベル 2・3） | 致命的な例外（許可していない要因なので、来れば誤り）。DSP・Fabric・ADPCM の割込みを使うアプリは、許可する前に項目を書き換える |
| 28（レベル 4：DOC） | DOC の割込みには基板の許可がないので、既定の処理で受ける（DR-076）。`DOC_IRQ` を読んで要求を 1 つ取り、そのオシレータの制御の IE を落とし、`bios_spurious` を数える。要求が読めない（bit 7＝1。DOC のクロックが遅すぎて、ブリッジが時間切れで $FF を返すときも。DR-079）ときは、戻る先の SR の割込みのマスクを 4 以上にする。DOC の割込みを使うアプリは、IE を立てる前に項目を書き換える |
| 29（レベル 5：ACIA） | 状態を読み、IRQ なら受信データを読んで（DR-028 の順）、RDRF ならリングに入れる |
| 30（レベル 6：映像） | VIDEO_IRQ の保留のうち立っているものを消す。VBlank なら `bios_frame` を 1 足し、PORT_A・PORT_B を読み、フックを呼ぶ。ACRTC の IRQ は使わない（CCR の下位 8 bit は 0） |

### 割込みを受けて BIOS の処理へつなぐ [P]（DR-094）

アプリは、ジャンプ表の項目の番地（項目の＋2 の長語）を自分の処理の番地に書き換えて割込みを受ける。書き換えは割込みのマスクを上げて（`MOVE.W #$2700,SR` など）行い、前の番地を残しておく。

BIOS の処理へつなぐときは、自分の処理の最後で、レジスタとスタックを入ったときの形（SP の上に例外の枠）に戻し、前の番地へ飛ぶ。たとえば `MOVE.L prev,-(SP)` と `RTS`、または `MOVEM.L (SP)+,…` の後に `JMP` で飛ぶ。BIOS の処理は RTE で割り込まれたところへ戻る。BIOS の処理の後で何かをしたいときは、レベル 6 なら VBlank のフック（`bios_vbl_hook`）を使う。レベル 6 を BIOS へつながないと、`bios_frame` が進まず、`BIOS_WAIT_VBL` が戻らない。

| ベクタ | BIOS の処理が消す保留 | レジスタ |
|---|---|---|
| 30（レベル 6） | VIDEO_IRQ の VBL（bit 8）と HBL（bit 9）のうち、読んだときに立っていたもの（W1C）。許可のビットは変えない。HBlank を使うアプリは、BIOS へつなぐ前に自分で処理する（BIOS は HBL を消すだけ） | すべて保つ（フックが壊してよい D0–D1/A0–A1 も保つ） |
| 29（レベル 5） | ACIA の状態→受信データの順に読む（ACIA の IRQ が消える。DR-028） | すべて保つ |
| 28（レベル 4） | `DOC_IRQ` を 1 回読む（要求を 1 つ取る）。そのオシレータの制御の IE を落とす。要求が読めないときは戻る先の SR のマスクを 4 以上にする（例外の枠の SR を書き換えるので、枠は SP の上になければならない） | すべて保つ |
| 25（レベル 1） | INPUT_IRQ_STATUS の bit 0・1・3（W1C）。bit 4（カートリッジ）は割込みにならない | すべて保つ |
| 24・31 | なし（数えるだけ） | すべて保つ |

BIOS の割込みの処理は USP を使わない。処理にかかる時間と保留を見る順は約束しない（§11）。

## 04　カートリッジ [P]

### 見出し（$400000、32 byte）

| offset | 大きさ | 中身 |
|---|---|---|
| +$00 | L | 印 `'CART'`（$43415254） |
| +$04 | W | 見出しの版（$0001） |
| +$06 | W | 予約（0） |
| +$08 | L | 入口の絶対番地。$400000〜$4FFFFF の偶数番地 |
| +$0C | L | ROM の大きさ（byte、参考。BIOS は見ない） |
| +$10 | 16 B | 題名（JIS X 0201、空白で埋める。BIOS は見ない） |

印は製品名や社名を含まない中立の語にした。BIOS は印・版・入口の 3 つを確かめ、1 つでも外れればデモへ進む。検査和は置かない（版 2 で足すなら [O]）。

### 入口の条件

- スーパバイザ、SR＝$2000（割込みを受ける）、SSP＝$120000。
- A0＝$400000（見出し）、D0.L＝BIOS の版（版 2 の BIOS では 2）、D1.L＝FABRIC_MODULES。ほかのレジスタと USP は不定。
- INPUT_IRQ_STATUS の bit 4（/CART）は 1（版 2。DR-095）。
- 画面は色 0 に消してあり、パレットは既定（§06）。ACRTC は案B で表示中、AR は r00（FIFO）。
- ジャンプ表は既定。VBlank・入力・ACIA の割込みは BIOS の処理で動いている。
- 音は黙らせてある（§02 の 4）。Data Fabric の両チャネルは止まっている。

## 05　呼出し [P]

ROM の固定番地に `JMP abs.L`（6 byte）を並べる。`JSR` で呼ぶ。スーパバイザで呼ぶ。ACRTC を使う呼出しは AR を r00 にしてから使い、r00 のまま戻る。

呼出しの共通の約束（版 2 で文書にした。DR-094）：

- 出力と書いたレジスタのほかは、D0–D7・A0–A6 と USP を保つ。BIOS は USP を読みも書きもしない。
- 割込みのマスク（SR の上位 byte）は変えない。`BIOS_WAIT_VBL` だけは待つ間マスクを 0 にし、戻るときに元に戻す。
- CCR は、出力に Z と書いた呼出しのほかは不定。
- 1 回の呼出しで SSP の下へ 256 byte まで使う（割込みの処理の分は別）。
- ACRTC を使う呼出し（`BIOS_ACRTC_SEND`・`BIOS_CLS`・`BIOS_PUTS`・`BIOS_PUT_HEX`・`BIOS_PUTS_KUTEN`）は再入できない。割込みの処理（VBlank のフックを含む）から呼ぶのは、割り込まれた側が ACRTC を使っていないときだけにする。`BIOS_GLYPH`・`BIOS_READ_PAD`・`BIOS_SET_PAL` は ACRTC を使わない。

| 番地 | 名前 | 入力 | 出力・動作 |
|---|---|---|---|
| $000400 | `BIOS_WAIT_VBL` | — | 次の VBlank まで `STOP #$2000` で待つ。SR は元に戻る |
| $000406 | `BIOS_ACRTC_SEND` | A0＝語の並び、D1.W＝語数（0〜65535） | 語を FIFO に書く（下の「FIFO への書き方と打切り」）。A0 は次の語。Z＝1 なら打ち切らなかった、Z＝0 なら途中で打ち切った（版 2） |
| $00040C | `BIOS_CLS` | D0.W＝色（0〜15） | 画面（256×192）を CLR で塗る。Z は `BIOS_ACRTC_SEND` と同じ（版 2） |
| $000412 | `BIOS_PUTS` | A0＝文字列（JIS X 0201、0 で終わる、32 字まで）、D0.W＝x（4 の倍数）、D1.W＝y、D2.W＝前景、D3.W＝背景 | 画面の左上を (0,0) とした位置に描く（§07 の方法）。Z は `BIOS_ACRTC_SEND` と同じ（版 2） |
| $000418 | `BIOS_PUT_HEX` | D4.L＝値、D5.W＝桁（1〜8）、D0〜D3 は `BIOS_PUTS` と同じ | 16 進で描く。Z は `BIOS_ACRTC_SEND` と同じ（版 2） |
| $00041E | `BIOS_SET_PAL` | A0＝16 語（$0RGB） | パレットに書く（次のラインから効く） |
| $000424 | `BIOS_READ_PAD` | — | D0.W＝PORT_A、D1.W＝前の呼出しから新しく押したビット |
| $00042A | `BIOS_PUTS_KUTEN`（版 2） | A0＝語の列（$00xx は JIS X 0201 の符号 xx、$KKTT は区 KK・点 TT。0 で終わる、32 字まで）、D0〜D3 は `BIOS_PUTS` と同じ | 区点の字を描く（§07）。文字 ROM にない区点は〓（2 区 14 点）で描く。Z は `BIOS_ACRTC_SEND` と同じ |
| $000430 | `BIOS_GLYPH`（版 2） | D0.W＝符号（`BIOS_PUTS_KUTEN` と同じ） | A0＝字形の 1 行目の CPU 番地（文字 ROM の上位レーン。行は +2 ずつ、8 行）。Z＝1 なら文字 ROM にある区点、Z＝0 なら〓の番地を返した。字形をアプリが自分で描くときに使う |
| $000436〜$00047F | 予約 | — | 後の版の呼出し。版 2 の ROM では消去したまま（$FFFF）で、呼ぶと F ライン例外（ベクタ 11）で止まる |
| $000480 | `BIOS_INFO` | — | 語：BIOS の版（`BIOS_INFO_VERSION`）。$000482〜$0004FF は予約 |

### FIFO への書き方と打切り [P]（DR-080、DR-082、DR-094）

- BIOS は ACRTC の SR を読み、WFE（FIFO が空）なら 8 語を続けて書き、WFR（空きがある）だけなら 1 語を書いて、また SR を読む（FIFO は 8 語。台帳 HD63484.md）。版 1 は 1 語ごとに WFR を読んでいた。
- 待つ間に CER（コマンドの誤り）が立つか、SR を 40960 回（工場出荷のクロックで約 0.4 秒）読んでも空きがなければ、CCR の ABT でコマンドを打ち切り（FIFO も空になる）、残りの語を続けて送る。CCR のほかのビット（DDM など）は保つ。版 1 は WFR だけを 65536 回読んだ（読む処理が長くなったので回数を減らし、時間をそろえた）。
- 打ち切ると `bios_acrtc_aborts` を 1 足し、`bios_acrtc_abort_sr` に打ち切る前の SR を残す。ACRTC を使う呼出しは、その呼出しの中で打ち切れば Z＝0 で戻る。Z＝0 のとき、その呼出しの描画は途中で欠けているか、ずれた語をコマンドとして読んだ形で描かれている（中身は約束しない）。戻ったときの ACRTC は、次のコマンドを受けられる。
- 0.4 秒より長くかかる正しいコマンドを `BIOS_ACRTC_SEND` で送るアプリは、自分で FIFO に書く（DR-080 のまま）。

PORT_A・PORT_B のビットは DR-055：bit 0 上、1 下、2 左、3 右、4 A、5 B、6 C、7 START、15–8 予約（0）。active-high（仕様書 §09）。

## 06　ハードウェアの初期状態

### ACRTC

| レジスタ | 値 | 状態 |
|---|---|---|

### 音 [P]

- DOC：止めたオシレータも、走査の中にあれば CA のチャンネルに中央の値を出し、そのチャンネルのサンプルホールドを引き戻す（エミュレータのモデル。ES5503 の試験 `halted_oscillator_still_fetches_and_outputs_center`）[V]。同じチャンネルに鳴らすオシレータと止めたオシレータがあると、鳴る音が小さくなる（16 個の走査で約 1/9 になった）。そこで BIOS は、使わないオシレータを CA 15 に置く。アプリも、鳴らさないオシレータを鳴らすオシレータと別のチャンネルに置く。
- DOC の走査は 16 個（0xE1＝$1E）。標本化は 1 MHz÷18＝55.6 kHz。
- 本体 DAC：DIRECT で $8080。電源投入時の DAC の値は 0（エミュレータ。両方の出力が下に振れる）[V]。BIOS が書くまでの約 1 ms は音が下に寄る。
- ADPCM、DSP には触らない（電源投入時の RESET のまま）。
- DOC の走査の数（0xE1）を増やすアプリへの約束 [P]（DR-094、OI-075）：走査の外のオシレータのレジスタは崩れて 1 になり（DR-074）、制御は IE＝1・H＝1 になりうる。そのまま走査に入れると、要求を出すか、崩れた周波数と音量で鳴るかが決まらない。そこで、増やすオシレータの制御を H＝1・IE＝0 で書き、続けて 0xE1 を書く（割込みを止めて続けて書く。DR-074 の保持時間は 25 °C で最短 2 ms）。周波数・音量・波形の番地と大きさは、走査に入れた後で書き、最後に制御の H を下ろす。BIOS の既定のレベル 4 の処理は、来た要求の IE を落とすだけで、崩れた値は直さない。

## 07　文字の描き方と文字 ROM のイメージ

### 描き方 [P]

`BIOS_PUTS` は、文字 ROM の字形（CPU 番地 $010000＋(符号×8＋行)×2、上位レーン）を CPU が 1 byte ずつ読み、1 行 1 byte を 4 bpp の 2 語に広げて、文字列全体を 1 本の DWT（AX＝2n−1、AY＝−7、RWP を文字列の左上）で送る。字形の 4 bit（bit 3 が左）を、左の画素が下位ニブルになる語のマスクに変え、(マスク∧前景)∨(¬マスク∧背景) を書く。x は語の境目（4 画素）に合わせる。1 文字は 16 語。Fabric の port 9 で字形を運ぶ方法は、アプリの側の [O]。

版 2（DR-094）：字形の 1 byte を、ROM の中の 256 項目の表で 2 語のマスク（長語）に引き、((前景 XOR 背景)∧マスク) XOR 背景 を長語で作る。FIFO が空なら 8 語を続けて書く（§05）。文字列はまず字ごとの字形の番地の表にし、`BIOS_PUTS_KUTEN` も同じ描き方を使う。区点から文字 ROM の offset へは仕様書 §08 の配置で引く：$00xx は xx×8、1〜8 区は $0800＋((区−1)×94＋点−1)×8、16〜47 区は $1F80＋((区−16)×94＋点−1)×8。9〜15 区、48 区から上、点が 1〜94 の外は ROM にないので〓（2 区 14 点、offset $0B58）にする。ROM にある区点でも、まだ描いていない字は市松模様（下の表）。

エミュレータで測った時間（ACRTC が止まっているときに、VBlank の割込みの直後から呼出しが戻るまで。`console_boot.rs` の `the_bios_keeps_its_promises` が出す。版 1 は同じカートリッジを版 1 の ROM で動かした）[V]：

| 呼出し | 版 1 | 版 2 |
|---|---:|---:|
| `BIOS_PUTS` 1 字 | 16 ライン | 7 ライン |
| `BIOS_PUTS` 10 字 | 110 ライン | 37 ライン |
| `BIOS_PUT_HEX` 6 桁（描き終わるまで） | 70（70）ライン | 25（25）ライン |
| `BIOS_PUTS_KUTEN` 6 字 | — | 27 ライン |
| `BIOS_ACRTC_SEND` 64 語（WPR を 32 回） | 24 ライン | 9 ライン |

版 2 は 1 字あたり約 3.3 ラインで、ほとんどが CPU の時間（1 行 2 語で約 190 クロック）。6 桁の描き直しは VBlank（70 ライン）に入る（OI-065）。時間は参考の値で、約束しない（§11）。

### 文字 ROM のイメージ [P]

`firmware/charrom/build.py` が、仕様書 §08 の配置（英数かな 256 字枠、非漢字 1〜8 区、第一水準 16〜47 区、予約）で、[glyphs-v0.1.tsv](../../docs/design/glyphs-v0.1.tsv) の 168 字を置く。仕様書が決めていない点は次のとおり。

| 点 | 決めたこと |
|---|---|
| 枠の種類 | glyph（字形がある）、blank（空白の字：0x20 と 1 区 1 点。0x00×8）、missing（規格に字があるが、まだ描いていない）、empty（規格の空き枠。0x00×8）、reserved（$7D80〜$7FFF。消去した EPROM と同じ 0xFF） |
| 描いていない字 | 市松模様 `AA 54 AA 54 AA 54 AA 00`。右の列と下の行を空ける字の規則（design/main.md §02）を守り、字と見分けやすい |
| 英数字とカナ | JIS X 0201 の符号の枠と、JIS X 0208 の区点の枠の両方に同じ字形を置く |
| 規格の割当て | JIS C 6226-1978 の書き起こし：JIS X 0201 は 0x20〜0x7E と 0xA1〜0xDF。1 区は全部、2 区は 1〜14 点、3 区は 16〜25・33〜58・65〜90 点、4 区は 1〜83 点、5 区は 1〜86 点、6 区は 1〜24・33〜56 点、7 区は 1〜33・49〜81 点、8 区は空き、16〜46 区は全部、47 区は 1〜51 点。一次資料での確認は [V] |

今のイメージは glyph 254 枠（168 字と、その英数かなの枠の写し 86）、blank 2、missing 3,320、empty 440、reserved 80。字形の表には小文字、句読点のほとんど（`:` `-` `.` など）、濁点・半濁点がないので、BIOS の文字列は大文字・数字・空白・カナ（濁点なし）・`ー。、` だけで書いた。

| 部分 | 内容 |

| 描画 | CLR（背景）、AFRCT（帯、ボタンの箱、パレットの帯）、ALINE（枠と扇）、CRCL（円）、DWT（文字）。動く円と箱は OPM＝011（XOR）で描き、次のフレームに同じ図形を XOR で描いて消す。下の絵を壊さない |

## 09　未確定・仕様との隙間 [V]

1. **ACRTC の DCR（r06）**：2026-11-26 に解決。ビットの割当てを U85 p.75–78 で確かめ（台帳 HD63484.md 追補 4 の (1)）、BIOS は $4000（基本画面だけ）を書く（DR-071）。分割画面とウィンドウはアプリが DCR を書いて使う（`sdk/samples/video`）。
2. **OMR の値**：台帳 §3.4 は $C008（GAI＝000、ACM＝10）。エミュレータの試験 `board/tests/console.rs` の `acrtc_case_b` は OMR＝$C020（GAI＝010、ACM＝00）と CCR＝$2200 を使う。BIOS は台帳に従った。
3. **止めた DOC のオシレータの出力**（§06）：エミュレータのモデルで、ES5503 の資料では未確認。アプリの規約（使わないオシレータの置き場所）に効くので、確かめたい。
4. **レベル 7 の要因の止め方**：仕様書 §05 は「表を埋めるまで回路で止めておく」とするが、BIOS が表を埋めたことを回路に知らせるレジスタがない。BIOS 版 1 は何も書かない。2026-11-27 に解決（DR-095）：本機はレベル 7 に要因をつながない（IPL の符号器のレベル 7 の入力は使わない）。止める回路も、解くための書込みも要らない。拡張バスの IRQ もレベル 7 にしない（どのレベルにするかは OI-091）。BIOS はベクタ 31 を数えて RTE のまま置く。
5. **カートリッジの有無**：見る手段がバスエラーしかなく、起動のたびにバスエラーが 1 回記録される。カートリッジの /PRES を MODULES などのビットで読めるようにする案 [O]。2026-11-27 に解決（DR-095）：カートリッジの端子 /CART を INPUT_IRQ_STATUS の bit 4 で読む（§02 の 8）。
6. **本体 DAC の電源投入時の値**：仕様書に書かれていない（エミュレータは 0）。リセットで $8080 にする回路か、BIOS の規約にするかを決めたい。
7. **文字 ROM の字形**：§07 のとおり、記号と濁点がない。BIOS の画面の文言はこれに合わせた。
8. **`BIOS_PUTS` の時間**（エミュレータで測った [V]）：1 字ずつなら約 12 ライン、10 字の列なら 1 字あたり約 8.5 ライン。VBlank（70 ライン）の中で描き直すなら 6 字程度まで（OI-065）。2026-11-27 に解決（DR-094）：版 2 で 1 字あたり約 3.3 ラインになり、6 桁の描き直しが 25 ラインで入る（§07 の表。表の版 1 の値は、同じ試験のカートリッジで測り直したもの）。

## 11　版と保証 [P]（DR-094）

### 版の確かめ方

BIOS の版は、ROM の $000480 の語（`BIOS_INFO_VERSION`）に置く。カートリッジの入口の D0.L にも同じ値が入る。版 1（DR-057）は $0001、版 2（DR-094、DR-095）は $0002。

- 版 n の約束は、版 n＋1 からもすべて守る。後の版は呼出し・変数・ビットを足すだけで、番地と意味を変えない。
- 版 2 で足したもの（`BIOS_PUTS_KUTEN`、`BIOS_GLYPH`、`bios_acrtc_aborts`、`bios_acrtc_abort_sr`、ACRTC を使う呼出しの Z、INPUT_IRQ_STATUS の bit 4）を使うカートリッジは、使う前に `CMPI.W #2,BIOS_INFO_VERSION` で確かめ、小さければ自分の画面で知らせるか、版 1 の呼出しだけで動く道に分ける。版 1 の ROM では、版 2 の呼出しの番地は消去したまま（$FFFF）で、呼ぶと F ライン例外の赤い画面で止まる。
- 確かめ方を呼出しにせず固定の番地の語にしたのは、版 1 の ROM にも同じ番地に版の語があり（DR-057）、呼出しを持たない版でも読めるから。
- 版の語は ROM の中身の版で、エミュレータや基板の版ではない。BIOS の中身を直しても約束が変わらなければ、版は上げない。

### 保証すること

- §03 の Main RAM の分け方、ジャンプ表の形（DR-025）、表の BIOS の変数の番地・大きさ・意味と、書いてよいもの。
- §03 の割込みの既定の処理が消す保留、つなぎ方、レジスタを保つこと。BIOS が USP を使わないこと。
- §04 の見出しの形と入口の条件。
- §05 の呼出しの番地、入力、出力、共通の約束（保つレジスタ、マスク、Z、スタック 256 byte、再入しないこと）、FIFO の打切りと、その返し方。
- §06 の初期状態（ACRTC のレジスタ、座標、パレット、音を黙らせた状態）と、DOC の走査を増やす順。
- §07 の区点から字形への引き方と〓。

### 保証しないこと（ROM はこれに頼らない）

- BIOS の内部：呼出しの入口の先の番地、ROM の中の表（字形のマスクの表など）、§03 の表にない変数の番地（$10065A、$100668〜$100677、$10067C〜$1007FF）、BIOS が使うスタックの中身。予約の番地（$000436〜$00047F、$000482〜$0004FF）の中身。
- 時間：呼出しと割込みの処理にかかる時間（§07 の表は参考）、起動にかかるフレーム数、打切りの見張りの正確な長さ。時間に頼るなら VIDEO_LINE や `bios_frame` で測る。
- CCR（Z を出力とする呼出しのほか）と、ACRTC を使う呼出しの後の ACRTC のパラメタのうち RWP・描画の点（CP）・CL0・CL1。BIOS の呼出しは、MASK、ORG、パターン RAM、ACRTC の CCR・OMR・DCR を、打切りの ABT のほか変えない（`BIOS_ACRTC_SEND` で送った語がするものは別）。
- 打ち切った（Z＝0）呼出しの描画の中身。
- 起動の画面と音、内蔵のデモ（§02、§08）の中身と動き。入口のときの VRAM の画面の外と、Main RAM の $100800 から先の中身。
- 割込みの処理が保留を見る順と、同時に来た保留をどの処理で消すか（§03 の表にあるもののほか）。
- レベル 7。本機に要因はなく（DR-095）、BIOS は数えるだけ。NMI としての使い方はない。
- 電源を入れたままのカートリッジの抜き差し。INPUT_IRQ_STATUS の bit 4 は差しているかを読むだけで、抜き差しを割込みで知らせない。
- ユーザーモードからの呼出し、割込みの処理の中からの ACRTC を使う呼出し（§05 の条件の外）。
