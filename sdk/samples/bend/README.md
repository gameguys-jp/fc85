# SAMPLE 5（ベンド点を試す試験信号のカートリッジ）

**v0.1**  
2026年11月26日

> 状態：作業中の版。仕様書 §11 のベンド点（クロックのジャンパ、DOC 子基板のバスの線、文字 ROM の線、FIFO のテストピン、Main RAM のリフレッシュ）を試すときに鳴らしておく、止まらない試験信号のサンプル。機械仕様は [仕様書](../../../docs/spec/hardware.md)、BIOS の約束は [bios-abi.md](../../docs/bios-abi.md)、エミュレータのベンド点の命令は `emulator/crates/board/src/bend.rs` が正。このサンプルで決めた値はすべて [P] で、エージェントが決めた（ユーザーが判断を任せた。要見直し）。題名の `SAMPLE 5` は中立な仮の名前で、製品名ではない。

記述ステータス：`[D]` 原典に根拠のある IC の仕様、`[P]` 本機独自の暫定設計値、`[O]` 代替・拡張候補、`[V]` 要検証（ここではエミュレータで測った値も [V] とする）。

## 01　概要

ベンドの結果を耳と目で比べられるように、いつも同じ音と絵を出し続ける。遊ぶものではない。

| 出すもの | 中身 |
|---|---|
| DOC の音（子基板があるとき） | A2（110.2 Hz）ののこぎり波の持続音、矩形波の低音、三角波と正弦波の分散和音（16 分音符、L と R に交互）。Am・F・C・G の 4 小節を繰り返す。約 120 BPM |
| ADPCM の音 | キック・スネア・ハイハットの 8 分音符の型（MSM5205、8 kHz）。子基板がないときは、これだけが鳴る |
| 静止画 | パレットの 16 色の帯、1 画素の市松と 8 画素の方眼、文字 ROM の字の表（字形のある 86 字）、題名 |
| 毎フレーム描くもの | 帯の中を往復する白い箱、状態の行（回数・歩・FC・誤り）、文字 ROM から描き直す 1 行 |

- 像は約 12 KB。`$400000` から置く。子基板がないときは題名の右に `NO DOC BOARD` と出す（あれば `DOC BOARD`）。
- 静止画は起動と START のときだけ描く。ベンドで崩れた絵はそのまま残り、比べられる。
- どの待ちにも上限がある。映像のクロックを止めても DOC のクロックを下げても止まらず、戻せばリセットなしで続く（Main RAM の中身が崩れたときを除く。§04）。
- 外の音源・画像は使わない。波形と太鼓は `build.py` が式から作る。

## 02　組み方と動かし方

リポジトリの根で：

```
py firmware/charrom/build.py
py firmware/boot/build.py
py sdk/samples/bend/build.py
```

`sdk/samples/bend/build/` に `bend.bin`（像）と `bend.lst`（リストと記号の表）ができる。途中のもの（`waves.bin`、`pattern.bin`、`drums.bin`、`tables.inc`、`song.inc`）と、太鼓を復号した確かめ用の `drum-*.wav` も同じフォルダに置く。

窓で動かす（`emulator/` で）：

```
cargo run --release -p fc85-host -- --cart ../sdk/samples/bend/build/bend.bin
cargo run --release -p fc85-host -- --cart ../sdk/samples/bend/build/bend.bin --no-doc
```

画面なしで、ベンドの台本（「フレーム 命令」の行）を流して WAV と画面を書き出す：

```
cargo run --release -p fc85-host -- --headless --frames 900 --cart ../sdk/samples/bend/build/bend.bin \
    --bend-script <scratchpad>/doc4.txt --wav <scratchpad>/doc4.wav --dump <scratchpad>/doc4.ppm --dump-at 290,400
```

台本の例（`<scratchpad>/doc4.txt`）：

```
0 mode bend
300 clock doc 4e6
600 clock doc off
```

試験は `py -m unittest discover -s sdk/samples/bend`（見出し、大きさ、波形に 0x00 がないこと、FC の表と式、太鼓の ADPCM の byte の列、格子のデータ）と、エミュレータの `the_bend_cartridge_plays_and_draws`（`emulator/crates/board/tests/console_boot.rs`）。

## 03　操作

| 釦（ホストのキー） | 働き |
|---|---|
| A（Z） | 波形 RAM を埋め直す（16 フレームかかる。その間、釦の行の `A WAVE` が黄色）。DOC の線や遅いクロックで波形 RAM が崩れたあとに押す |
| B（X） | 持続音だけにする・戻す（低音と分散和音は次の音から音量 0）。音程を測るときに使う。`B SOLO` が黄色 |
| C（C） | 太鼓を止める・戻す。`C DRUM` が暗い灰色 |
| START（Enter） | 静止画を全部描き直す（約 16 フレーム） |

状態の行：`FR` 主ループの回数（16 進）、`ST` 次に鳴らす歩（0〜3F）、`FC` 最後に書いた分散和音の FC、`ER` Data Fabric の誤りと時間切れの数、`NV` VBlank を待って時間切れになった数。

## 04　ベンドの試し方

ベンド点は Bend モードでだけ効く（DR-065）。窓では F2 で切り替え、クロックのつまみを回すと Bend モードに入る。台本と `--bend` では `mode bend` を先に書く（`--bend` を 1 つでも付けると Bend モードで始まる）。「確かめた値」は §07 の測り方で、DOC の子基板ありの値 [V]。

| 操作 | 何が起きるか | 戻し方 | 確かめた値 |
|---|---|---|---|
| ホストのつまみ：F3 で回すクロックを選ぶ（起動したときは DOC。押すたびに映像、DSP、ADPCM、音声、DOC の順）。PageUp・PageDown で半音ずつ、Shift を押しながら 1/8 半音ずつ。押し続けると回り続ける | DOC：すべての DOC の声が一緒に動く（標本化の周波数が CLK に比例する）。太鼓と拍の速さは変わらないので、太鼓に対して音程だけがずれる。ADPCM：太鼓の高さと長さ。下げると次の太鼓の前に切られ、`ER` が増える。映像：下の `clock video` の行 | Home で基板の発振器に戻す | — |
| `clock doc 4e6` | DOC の声がすべて 1 オクターブ下がる | `clock doc off` | 持続音（L）の一番強い周波数 110.25 Hz → 55.00 Hz |
| `docbus A0=1` | A のバスの 0 番の線。68000 が書くレジスタの番号の bit 0 が 1 になり、偶数のオシレータ（L）への書込みが奇数（R）に入る。L の声は最後に書いた音のまま鳴り続け、R の声が L の値で上書きされる。DOC が読む波形は奇数番目の標本だけになる | `docbus normal`。次の音の頭（持続音は 1 秒以内）で戻る | L の RMS 1,556 → 1,124。戻すと 1,513 |
| `docbus D5=1` | AD のバスの D5（行の番地の bit 5 と兼ねる）。68000 の書く値の bit 5 が 1 になる：FREQ_HI（FC が $2000 上がり、高い音に跳ぶ）、CONTROL の CA の bit 1（声が別のチャネルに移る）、0xE1（$1E → $3E で 32 個を走査し、標本化が 29.4 kHz に下がる）。リフレッシュの行も変わるので、行の bit 5 が 0 の行が保たれず、波形 RAM が崩れる（DR-075）。偶数の頁（正弦とのこぎり）は 0 に落ち、0x00 でオシレータが止まる | `docbus normal` のあと A。A を押すまで持続音は止まったまま | L の 110 Hz の強さ（Goertzel）約 750 → 2〜30。戻して A を押すと 680〜760 |
| `clock doc 10e3` を 1 秒、続けて `clock doc off`（つまみなら DOC で PageDown を押し続け、Home） | 下げている間、68000 の DOC へのアクセスは時間切れで DTACK で終わる（DR-079）。レジスタと波形 RAM が崩れる（DR-074、DR-075）。戻すと、次の歩の音の頭から曲が戻る | `clock doc off`。波形が崩れて音色がおかしければ A | 1 秒でブリッジの時間切れ 178 回、`ER` は 0。戻した次の 1 秒で L の 110 Hz の強さ 728（ふだんは約 750）、RMS 1,499/1,636 |
| `clock video 21.4785e6` | 色副搬送波が約 205 Hz ずれる。テレビの色の引込み（±500 Hz）の中なので色は出るが、色相が asin(205÷500)≈24° ずれる（DR-078） | `clock video off` | 色の帯の赤が桃色に、緑が青緑寄りに。音は変わらない |
| `clock video 20.5e6` | 水平の同期が外れて絵が流れ、色が消える（カラーキラー）。フレームが長くなり、拍が約 5 % 遅くなる | `clock video off` | 絵は横に裂けた白黒の縞。音は途切れない |
| `clock video 0`（窓では、止めたあと F2 で通常モードに戻すと動き出す） | 表示が止まり、VRAM のリフレッシュがなくなって崩れる（DR-077）。68000 の ACRTC へのアクセスは時間切れ（DR-079）で、BIOS_ACRTC_SEND は CER を見てすぐ打ち切る（DR-080、DR-082）。VBlank が来ないので、主ループは 25 ms で待ちを切り、描画を飛ばして音だけ進める（拍は約 2/3 の速さ）。`NV` が増える | `clock video off` か F2。戻した次のフレームから箱と状態の行が動き、崩れた静止画は START で描き直す | 0.5 秒止めて、VRAM は点と縦の縞（色 0 と 15）。`NV` 16、バスエラー 0。音は途切れない |
| `char A1=A2,A2=A1`（文字 ROM の線） | 黄色の 1 行と状態の行の数字は、すぐ崩れた字形で描かれる。上の白い字の表は、描いたときの字形のまま残るので比べられる | `char normal`。START で表も描き直す | 崩れた字形を画面で確かめた。音は変わらない |
| `fifo adpcm full=1`・`fifo adpcm empty=1` | ADPCM の FIFO の状態のピン。太鼓が鳴らなくなる。13 フレームで終わらない太鼓は止めて数える | `fifo adpcm open`。次の 8 分音符から鳴る | 5 秒で `ER` 19（$13）。太鼓が止まり、山が 5,494 → 4,309〜4,450 |
| `dram refresh hsync`、続けて `clock video 0` | 見張りのカウンタを切ったので（DR-081）、映像を止めると Main RAM のリフレッシュがなくなり、変数とスタックが崩れる | `clock video off`、`dram refresh auto`。崩れたら電源を入れ直す（F2 では戻らない） | 0.5 秒の停止は戻った。1 秒ではバスエラー 2 回で止まり、DOC は最後の音のまま鳴り続けた |

- `clock video` は 0 か、`bend.rs` の範囲の周波数。`--video-clock`・`--doc-clock` は `--bend "clock …"` の短い形。
- ほかのベンド点（`sig one`、`fifo dac`、DSP と音声のクロック）でも止まらないが、このサンプルは DSP も本体の DAC も使わないので、音は変わらない。

## 05　仕組み

### 音

| 声 | オシレータ（CA） | 波形の頁 | 音量 | 書く時 |
|---|---|---|---|---|
| 持続音 A2 | 0（L）・1（R） | 2 のこぎり | 48 | 8 歩（約 1 秒）ごと。0xE1 と、使わないオシレータも書き直す |
| 低音 | 2（L）・3（R） | 3 矩形 | 56 | 8 分音符ごと。休みは音量 0 を書く |
| 分散和音 | 4（L、偶数の歩）・5（R、奇数の歩） | 1 三角・0 正弦 | 64 | 16 分音符ごと。次の同じ側の音まで鳴る |
| 使わない | 6〜15（CA 15） | — | 0 | 止める（HALT） |

- 声ごとに CA を分け、チャネルの S/H を声の間で取り合わせない。偶数の CA は L、奇数は R（DR-054）。
- 音の頭では、そのオシレータの 6 つのレジスタ（FREQ_LO、FREQ_HI、VOLUME、POINTER、SIZE、CONTROL の順）を全部書く。CONTROL は自走（mode 0）で、IE は立てない。アキュムレータを戻さないので、書き直してもクリックが出ない。
- DOC の窓は、MOVE.B の 1 回の書込みだけで触る。読まない（0xE0・0xE2 も読まない。DR-030）。`CLR.B` は使わず `MOVE.B #0` で書く。
- FC は `build.py` が MIDI の音ごとに計算した表（128 語）を引く。8 MHz、走査 16 個（標本化 55,555.6 Hz）、256 byte の表（T＝0、R＝0）で FC＝round(f×2^17÷55,555.6)（台帳 ES5503.md §4.3）。曲で鳴らす 21 音の平均律からのずれは最大 +5.9 セント（G1）。
- 波形は 256 byte で、値は 0x20〜0xE0（中央 0x80、±0x60）。0x00 はオシレータを止めるので使わない。
- 波形 RAM：1 KiB（4 頁）を Staging RAM の $0000〜$0FFF に 4 回写し、Data Fabric のチャネル 1 で波形 RAM に 4 KiB ずつ 16 回運ぶ（1 フレームに 1 回）。全 256 頁が「頁 p は波形 p&3」になるので、AD のバスの線（頁の番地を兼ねる）を崩しても、読む頁は空ではない。起動時は最初の 4 KiB（使う頁 0〜3 を含む）が終わるまで待つ。
- 拍：8 分音符を 15 フレーム（59.92 Hz で 119.8 BPM）。16 分音符の歩は 0 と 8 のフレーム。主ループが遅れたら（描画が長引いたとき）、待ちのあとで遅れたフレームの数だけ拍を進める（1 回に 4 まで）。

### 太鼓（ADPCM）

`sdk/samples/game/sfx.s` と同じ手順。8 分音符ごとに 1 つ鳴らす。

1. フレーム 13：まだ鳴っていれば、チャネル 0 を止め、FIFO を空にし（port の RESET）、`ER` に数える。
2. フレーム 14：ADPCM を RESET にし、次の太鼓を選ぶ（C で止めているときは選ばない）。
3. フレーム 0：チャネル 0 で Staging RAM（$1000〜）から port 5 へ送り始め、FIFO に 16 byte たまるまで（上限 400 回）待って RESET を外す。
4. ほかのフレーム：DONE で FIFO が空になったら、止めて RESET にする。ERROR なら `ER` に数える。

太鼓の byte の列は、頭に 5 byte、後ろに 4 byte の $08（予測値を動かさない符号）を付け、本体のあとに 20 ms の無音を置く。予測値の山は 1,800、符号器の範囲は ±1,950。どれも 0.2 秒以内（キック 0.172 秒、スネア 0.162 秒、ハイハット 0.072 秒）。

### 絵

| y | 中身 |
|---|---|
| 0 | 題名 `SAMPLE 5  BEND TEST`。右に `DOC BOARD`（緑）か `NO DOC BOARD`（赤） |
| 10、53 | 白い線 |
| 12〜51 | 16 色の帯（パレット 0〜15、16 画素ずつ） |
| 56 | 帯の番号 `0`〜`F` |
| 66〜113 | 左半分は 1 画素の市松（色 15 と 0）、右半分は 8 画素の方眼（色 14）。`pattern.bin` を DWT で 12 行ずつ |
| 118〜134 | 字の表（3 行、BIOS_PUTS で 16 字ずつ） |
| 144 | 字の表の 1 行を毎フレーム 8 字ずつ描き直す（黄色）。4 回で 1 行、16 回ごとに次の行 |
| 154〜167 | 暗い灰色の帯。白い箱（12×10）が 2 画素ずつ往復する。前の位置を帯の色で塗ってから描く |
| 172 | 状態の行 |
| 184 | 釦の行（色で状態） |

- パレット：0 黒、1〜12 は赤から色相を 30° ずつ回した飽和色、13・14 灰、15 白。
- 静止画は 16 の段に分け、1 フレームに 1 段描く（パレットと消去、題名、帯、番号 2 回、格子 4 回、字の表 6 回、箱の帯と名前）。
- 毎フレームは、箱、`FR`、そのほかの字の 1 つ（歩と FC、誤りの数、釦の行の 1 項目、描き直す行の 8 字のどれか）だけを描く。BIOS_PUTS は 1 字に約 9〜12 ライン使うので、1 フレームに描く字を 16 字ほどにとどめる。
- 描画はすべて BIOS の呼出し（BIOS_SET_PAL、BIOS_CLS、BIOS_PUTS、BIOS_PUT_HEX、BIOS_ACRTC_SEND）。ACRTC の FIFO に直接は書かない（DR-033 の WFR の確認と、DR-080・DR-082 の打ち切りを BIOS に任せる）。図形のコマンド（WPR で CL0・CL1、AMOVE、AFRCT、RWP と DWT）は Main RAM の並びに作って BIOS_ACRTC_SEND で送る。ACRTC の AR・SR に読み書き一体の命令は使わない（DR-016）。

### 待ち

| 待ち | 上限 | 時間切れのとき |
|---|---|---|
| VBlank（`bios_frame` が変わる） | 6,250 回（約 25 ms） | `NV` に数え、そのフレームは描かずに拍だけ進める |
| 波形 RAM の 4 KiB の転送 | 4 フレーム | `ER` に数え、チャネルを止めて次へ |
| 起動時の最初の 4 KiB | STATUS を 40,000 回 | そのまま進む（以後はフレームごとの見張り） |
| 太鼓の転送 | 13 フレーム | `ER` に数え、止めて FIFO を空にする |
| 太鼓の FIFO の 16 byte | 400 回 | そのまま RESET を外す |
| ACRTC の FIFO | BIOS（CER ですぐ、WFR は 65,536 回） | BIOS が ABT で打ち切る |

## 06　[P] の決めごと

| 項目 | 値 | 理由 |
|---|---|---|
| 速さ | 8 分音符 15 フレーム（119.8 BPM） | フレームの整数倍で約 120 BPM。16 分音符は 8・7 フレーム |
| 持続音 | A2（FC 260、110.2 Hz）、のこぎり波 | 音程の変化が聞き取りやすく、測りやすい低い音。倍音が多く、線のベンドで音色の変化が分かる |
| 和音 | Am・F・C・G、分散和音は A3〜C5 | 4 小節で一回り。持続音の A と重なる |
| 音量 | 持続音 48、低音 56、分散和音 64 | 太鼓（山 1,800）が聞こえる釣り合い。全体は LINE OUT で RMS 約 1,600 |
| 波形の振幅 | 0x80±0x60 | 0x00 を避け、線のベンドで上下に振れる余地を残す |
| 波形 RAM の埋め方 | 全 256 頁に 4 頁を繰り返す | 頁の番地の線を崩しても、波形のある頁を読む |
| 声と CA | 声ごとに別の CA、使わないオシレータは CA 15 | チャネルの S/H を取り合わない |
| 持続音の書き直し | 8 歩（約 1 秒）ごと | 崩れたレジスタを聞かせる時間を残し、1 秒以内に戻す |
| 太鼓 | 8 kHz、山 1,800、長さ 0.2 秒以内 | 8 分音符のうち、次を準備するまでに終わる |
| VBlank の待ち | 約 25 ms | 1 フレームより長い。映像のクロックを約 14.3 MHz まで下げても時間切れにならない（20.5 MHz で 1 フレーム 17.5 ms） |
| 遅れの取り戻し | 1 回に 4 フレームまで | 長い停止のあとに拍が駆け足にならない |
| 波形 RAM の転送 | 4 KiB を 1 フレームに 1 回、上限 4 フレーム | 1 回は工場出荷のクロックで約 4〜6 ms |
| 画面の配置とパレット | §05 の表 | 帯・格子・字の表を 1 画面に収める |

## 07　確かめたこと

エミュレータの試験 `the_bend_cartridge_plays_and_draws`（`emulator/crates/board/tests/console_boot.rs`）が、DOC の子基板ありで 10 秒動かし、次を確かめる [V]。

- バスエラー 0、DOC の窓の規約違反（DR-030）0、`ER` 0、`NV` 0。
- 10 秒の 1 秒ごとに、L と R のどちらも RMS が 300 より大きい（無音の区間がない）。
- 続く 2 つのフレームの画面が違う（箱と状態の行が動く）。
- B で持続音だけにし、L の一番強い周波数（30〜300 Hz）が約 110.2 Hz。`clock doc 4e6` で、その比が 0.5±0.03（測った値は 110.25 Hz → 55.00 Hz）。
