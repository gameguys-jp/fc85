# SAMPLE 6（通常モードの映像と描画の予算を見せるカートリッジ）

**v0.1**  
2026年11月26日

> 状態：作業中の版。ベンドを使わない通常モードで、本機の映像の表現（ラスタのパレット、DSP と ACRTC の線画、ソフトのスプライト、文字 ROM の漢字）を見せ、1 フレームの描画の予算を測るサンプル。機械仕様は [仕様書](../../../docs/spec/hardware.md)、BIOS の約束は [bios-abi.md](../../docs/bios-abi.md)、68000 と DSP の約束は `protocol.inc` が正。このサンプルで決めた値はすべて [P] で、エージェントが決めた（ユーザーが判断を任せた。要見直し）。題名の `SAMPLE 6` は中立な仮の名前で、製品名ではない。画面の配置と色は試験用の仮のもので、本機の UI の意匠ではない。

記述ステータス：`[D]` 原典に根拠のある IC の仕様、`[P]` 本機独自の暫定設計値、`[O]` 代替・拡張候補、`[V]` 要検証（ここではエミュレータで測った値も [V] とする）。

## 01　概要

ファミコンのようなスプライトとタイルの専用回路を持たない本機が、何を代わりにできるかを 1 画面で見せる。遊ぶものではない。

| 見せるもの | 中身 |
|---|---|
| ラスタのパレット | 基本画面の 160 ラスタで毎ライン HBlank の割込みを受け、パレット 1（空と海）と 2（立方体と波頭）を書き換える。空のグラデーション、虹色の立方体、海の色の変化、コッパーバー 2 本。1 フレームに 16 色を大きく超える色が出る |
| DSP と ACRTC の立体 | 68000 が角と頂点を Data Fabric の port 3 で DSP に送り、DSP が回して透視した画面の座標を port 4 で返す。68000 はそれを ACRTC の折れ線のコマンドにして描く。2 頁を交互に描き、VBlank の中で見せる頁を替える |
| ソフトのスプライト | 16×16 の玉を N 個（初め 16、0〜96）。模様のある海の上で、背景を VRAM の表示しない行に置いた元の絵から CPY で戻し、型（AND）と絵（OR）の SCPY で描く。1 ラインに並ぶ数の制限はない |
| 文字 | 上画面に、半角カナ（`BIOS_PUTS`）と、文字 ROM の区点の字形から描いた漢字とかなの行「日本の文字を出す」 |
| 時間の帯と予算 | B で、段（処理の区切り）の始まりごとにパレット 0（画面の縁）を段の色にし、1 フレームのどこで何をしているかを画面に出す。下画面に段ごとのライン数 |

- 像は約 19 KB。`$400000` から置く。DOC の子基板がなくても動く（音は出さない）。
- ベンドを使わない。BIOS は変えず、BIOS の約束（bios-abi.md）の範囲で割込みを差し替える（§04）。
- どの待ちにも上限があり、時間切れと誤りは数えて下画面の `ERR` に出す（§05 の表）。
- 外の画像は使わない。グラデーション、海、玉、表は `build.py` が式から作る。

## 02　組み方と動かし方

リポジトリの根で：

```
py firmware/charrom/build.py
py firmware/boot/build.py
py sdk/samples/showcase/build.py
```

`sdk/samples/showcase/build/` に `showcase.bin`（像）と `showcase.lst`（リストと記号の表）ができる。DSP のプログラムの `xform.bin` と `xform.lst`、途中のもの（`sea.bin`、`bank.bin`、`consts.inc`、`tables.inc`、`dsptab.inc`）も同じフォルダに置く。

窓で動かす（`emulator/` で）：

```
cargo run --release -p fc85-host -- --cart ../sdk/samples/showcase/build/showcase.bin
cargo run --release -p fc85-host -- --cart ../sdk/samples/showcase/build/showcase.bin --no-doc
```

画面なしで、釦の台本（「フレーム PORT_A の値（16 進）」の行）を流して画面を書き出す：

```
cargo run --release -p fc85-host -- --headless --no-doc --frames 200 --cart ../sdk/samples/showcase/build/showcase.bin \
    --pad-script <scratchpad>/bars.txt --dump <scratchpad>/s.ppm --dump-at 120,199
```

`<scratchpad>/s-120.ppm` と `s-199.ppm`（320×240）ができる。台本の例（`<scratchpad>/bars.txt`。100 フレームで B を押して離し、時間の帯を出す）：

```
100 20
104 0
```

試験は `py -m unittest discover -s sdk/samples/showcase`（見出し、大きさ、グラデーションの表とその滑らかさ、色の数、コッパーバー、正弦と透視の表、回転と透視の式を浮動小数点の計算と比べる、立方体が空に収まる、DSP のプログラムと表、海と玉の絵、玉の初めの位置、漢字の行の字形、段の色）と、エミュレータの `the_showcase_cartridge_draws_beyond_sixteen_colours`（`emulator/crates/board/tests/console_boot.rs`）。

## 03　操作

| 釦（ホストのキー） | 働き |
|---|---|
| A（Z） | 立体の計算を DSP と 68000 で切り替える。上画面の `DSP`・`68K`。起動時に DSP を読み込めなかったときは 68000 のまま |
| B（X） | 時間の帯を出す・止める（`BAR`） |
| C（C） | 玉を出す・消す（`SPR`）。消しても数は保つ |
| START（Enter） | ラスタのパレットを止める・戻す（`RAS`）。止めると、パレット 1・2 は固定の 2 色になり、HBlank の割込みも止まる |
| 上・下 | 玉の数を 1 つ増やす・減らす（0〜96） |
| 右・左 | 玉の数を 8 つ増やす・減らす |

方向は押し続けると、20 ループ後から 4 ループごとに繰り返す。上画面の印は、入っていれば白、切ってあれば灰色（計算の印は `DSP` と `68K` の文字で分ける）。

下画面の 2 行（値はどれも直前の 16 ループの最大。16 ループごとに描き直す）：

- `OBJ` 玉の数（消していれば 0）、`HZ` ループの速さ（60＝毎フレーム、30＝2 フレームに 1 回）、`BUSY` ループの始まりから段 T の終わりまでのライン数、`ERR` 誤りの数の和（§05 の表の 6 つ）。
- `K` `R` `E` `X` `C` `S` `T`：段ごとのライン数（§04 の表）。

A を頁の切替えに使う案もあったが、見せるものを 1 画面に収めたので頁がなく、A は DSP と 68000 の比較に使った。

## 04　画面と仕組み

### 画面の分け方

ACRTC の分割画面（DCR で上画面・基本画面・下画面を出す。SSW と SAR は画面ごと）で、案B の 192 ラスタを 3 つに分ける。どの画面も 1 行 64 語（256 画素、4 bpp）。

| 画面 | ラスタ | VRAM（行） | 中身 |
|---|---|---|---|
| 上画面 | 43〜58（16） | 0〜15 | 題、印、漢字とかなの行 |
| 基本画面 | 59〜218（160） | 頁 0：16〜175、頁 1：192〜351 | 上の 96 行が空（立方体）、下の 64 行が海（玉）。左右の 1 語は縁（色 0） |
| 下画面 | 219〜234（16） | 176〜191 | 数の 2 行 |

VRAM の残り：海の元の絵（352〜415 行）、玉の型と絵（416〜431 行）、数字の帯「0123456789 」（432〜439 行。下画面の数はここから CPY する）。

### ラスタのパレット

1. 起動時に、ジャンプ表のレベル 6（ベクタ 30）の項目の番地を、自分の処理 `irq6` に書き換える（元の番地は残す）。`bios_vbl_hook` に `vbl_hook` を置く。
2. VBlank の割込みは、`irq6` から元の BIOS の処理へ同じ例外のフレームのまま進み（`MOVE.L 元の番地,-(SP)`、`RTS`）、`bios_frame` を数え、パッドを読み、フックを呼ぶ。
3. フックは、ラスタの表の頭を USP に置き、VIDEO_LINE_CMP を 57 にして、VIDEO_IRQ を VBL_EN・HBL_EN・LINE_CMP にする。続けてコッパーバーの行を表に塗る。
4. ラスタ 57 の HBlank で最初の割込みが来る。`irq6` は表の 1 行（パレット 1、パレット 2、VIDEO_IRQ に書く語）を書く。表の最初の行の VIDEO_IRQ の語が LINE_CMP を下ろすので、そこからは毎ラインの HBlank で割込む。最後の行の語が HBL_EN を下ろす。
5. HBlank の保留はラスタ r の表示の終わり（ドット 320）で立ち、書いた色はラスタ r＋2 の頭の写しから効く（DR-053）。ラスタ 57 で書く行が、基本画面の最初のラスタ 59 の色になる。

表は 160 行×3 語（Main RAM）。空のグラデーション（96 行、上の黒に近い紺から地平の明るい水色へ）、地平の 1 行、海（63 行、青緑から暗い紺へ）。パレット 2 は、空では立方体の線の色相を行ごとに回し、海では波頭の色を海の色より明るくする。コッパーバーは 2 本（15 行。赤から黄の 1 本と、紫から桃の 1 本）で、位相を 2 ずつ進めて空の中を上下に回り、余弦の符号で前後を入れ替える。VBlank のフックが前のフレームの行を空の色に戻してから塗る。

USP をラスタの表の指し手に使った。割込みの中で RAM の変数を読み書きするより短い。BIOS は USP を使わない（`firmware/boot/boot.s` を読んで確かめた。bios-abi.md には書かれていない）。

### 立方体（DSP と ACRTC）

| 段 | すること |
|---|---|
| K | Staging RAM に入力の塊（`protocol.inc`：頭の語、3 つの角、頂点の数、頂点）を置き、Fabric のチャネル 1（port 4→Staging RAM）とチャネル 0（Staging RAM→port 3）を始める |
| R・E | DSP が計算している間に、ACRTC で玉の背景を戻し、立方体を消す |
| X | チャネル 1 の DONE を待って、座標と尾の語（番号つき）を確かめる。68000 の版では、ここで同じ式を MULS で計算する。座標から、4 本の道（辺の折れ線）の AMOVE と APLL のコマンドを作る |
| C | 線の色（2）で描く |

- DSP（`xform.dsp`）は TMS32010 の 16×16 bit の積と和で、X・Y・Z 軸の順に回し、透視の表（Q15、256 項目）を引く。正弦の表と透視の表は DSP のプログラム RAM に置き、TBLR で読む。入力 FIFO の語は BIOZ で確かめてから IN で読み、出力は状態ポートの空きを確かめてから OUT で書く（DR-017）。頭の語の印が合わなければ、合うまで読み捨てる。
- 起動時に、決めた 4 組の角で DSP と 68000 の結果を突き合わせ、食い違った語を数える（§05 の表の +8。`ERR` に出る）。2 つの版は同じ式で、端数の切り捨てまでそろえてあるので、0 になるはず。
- 頁の切替え：基本画面の 2 頁を交互に描き、描き終えたら VBlank の中で SAR1 を替える。消すのは、その頁に 2 ループ前に描いた線のコマンドの並び（頁ごとに RAM に残す）を、空の色（1）でもう一度送るだけ。空は色 1 の一色の画素で、グラデーションはラスタのパレットが付けるので、線を色 1 で描き直せば元に戻る。
- 線は AREA（AREA＝010、領域の外は描かずに進む）で空の 96 行に閉じ込める。

ちらつきを避ける方法として、頁の切替えと、前の線だけを消すことの両方を使った。1 頁だけで前の線を消して描き直すと、電子線が描きかけの立方体を通るときに、消えた線や半分の線が見える（テアリング）。頁を切り替えれば、見えるのはいつも描き終えた頁になる。消すのを空全体の CLR（62 語×96 行、式で約 37 ライン、表示との競合を入れるとさらに長い）でなく線の描き直し（約 10 ライン）にしたのは、予算を玉に回すため。代わりに、頁ごとに線と玉の記録を持つ。VRAM は 2 頁で 320 行（40 KiB）使う。

### 玉

- 海の元の絵（64 行×64 語）を VRAM の表示しない行（352〜415 行）に置き、頁の海の 64 行は起動時にそこから CPY する。
- 玉の型と絵（416〜431 行）：16×16 の玉を、横に 0〜3 画素ずらした 4 通りを、それぞれ 5 語（20 画素）の幅で置く。型は玉の外が $F・中が 0、絵は玉の外が 0。玉は 2 種類（赤、黄）で、それぞれ暗・中・明の 3 色。
- 段 R：その頁に 2 ループ前に描いた玉の場所へ、海の元の絵から 5 語×16 行を CPY する（9 語のコマンド）。
- 段 S：玉を動かし（縁で跳ね返る）、x の下位 2 bit で型と絵を選び、型を SCPY の AND、絵を SCPY の OR で描く（18 語）。描いた先と元の番地を頁ごとに記録する。
- コマンドの語の並びは RAM に型を置き、玉ごとに変わる語（RWP、元の番地）だけを書いて送る。
- FIFO への書込みは、SR の WFE（FIFO が空）が立っていれば 8 語（FIFO の深さ、台帳 HD63484.md §4.1）まで確かめずに続けて書き、そうでなければ語ごとに WFR を確かめる。WFR を待つ間に CER が立つか、65536 回読んでも空かなければ、CCR の ABT で打ち切って数える（DR-080、DR-082 と同じ方法）。
- 1 つの玉は CPY 1 つと SCPY 2 つ。台帳 HD63484.md §3.8 の式（(6x＋10)y＋12、x＝5、y＝16）では 1 つが 652 サイクル（2CLK）、3 つで約 5.7 ライン（表示との競合なし）。

### 文字

- 上画面の 1 行目（題と印）と下画面の文字、半角カナの「ﾊﾝｶｸ ｶﾀｶﾅ」は `BIOS_PUTS`。
- 漢字とかなの行「日本の文字を出す」は、`BIOS_PUTS` が JIS X 0201 の符号しか受けないので、アプリが描く。文字 ROM の区点の字形の offset を仕様書 §08 の式で `build.py` が求めて表にし、68000 が字形（8 行×8 bit）を読んで 4 bpp の語に広げ、1 本の DWT で送る。
- 文字 ROM の字形 v0.1 で使える漢字は 30 字（第一水準。`docs/design/glyphs-v0.1.tsv`）。`BIOS_PUTS` で描ける字は、JIS X 0201 の枠のうち字形のある数字、英大文字、カタカナ（清音とッ）と、。、ー（英小文字と記号はない）。

### 時間の帯と段の長さ

| 段 | 色（パレット 0） | すること |
|---|---|---|
| K | シアン | DSP に送る |
| R | 青 | 玉の背景を戻す |
| E | 紫 | 前の立方体を消す（ORG と色、線の描き直し） |
| X | 黄 | DSP の結果を受け取る（68000 なら計算する）。コマンドを作る |
| C | 緑 | 立方体を描く |
| S | 赤 | 玉を動かして描く |
| T | 橙 | 入力、印、下画面の数（1 ループに 2 欄まで） |
| 待ち | 黒 | 次の VBlank まで |

- 段の始まりの時刻は、`bios_frame`×262＋（VIDEO_LINE を VBlank の始まりから数えたライン）。VBlank の割込みが `bios_frame` を足す前なら（VIDEO_IRQ の VBL の保留）、足した後の値にする。
- ACRTC を使う段は、終わりに ACRTC が止まる（FIFO が空でコマンドが終わった）のを待つ。段のライン数に ACRTC の時間が入るように、段の間では 68000 と ACRTC を重ねない。そのぶんループは少し長くなる（§05）。
- 時間の帯は、上画面と下画面の地と、基本画面の左右の縁に出る。段の始まりで 1 回書くだけなので、帯の境目は 68000 がパレット 0 を書いたラスタ。

## 05　測った値

### 試験と測定が読む番地

`APP_RAM`（$100800）からの offset。番地を変えない。

| offset | 中身 |
|---|---|
| +0 | 主ループの回数 |
| +2 | Fabric の時間切れと ERROR |
| +4 | DSP の読込みの誤り、UNDERRUN・OVERRUN |
| +6 | 尾の語の食い違い |
| +8 | 起動時の DSP と 68000 の突合せの食い違い |
| +10 | ACRTC の打切り（CER か時間切れ） |
| +12 | VBlank の待ちの時間切れ |
| +14 | DSP を読み込んで確かめた（1） |
| +16 | 玉の数 |
| +18 | 最後のループのフレーム数（1 は 60 Hz、2 は 30 Hz） |
| +20〜+37 | 最後のループの段ごとのライン数（K、R、E、X、C、S、T）、BUSY、フレーム数 |
| +38 | 1：DSP、0：68000 |
| +40 | ラスタのパレット（1：入） |
| +42 | 時間の帯（1：入） |
| +44 | 玉を出す（1：出す） |

### 1 ループの予算

エミュレータ（board 層、DOC の子基板なし）で、§05 の表の番地を書き換えて条件を替え、90 フレームの間の段ごとのライン数の最小〜最大を読んだ [V]。1 ラインは約 63.7 µs（68000 の約 509 クロック）、1 フレームは 262 ライン。玉は 16。

| 段 | DSP・ラスタのパレット入（既定） | DSP・ラスタのパレット切 | 68000 の計算・ラスタのパレット入 |
|---|---|---|---|
| K | 1 | 1 | 1 |
| R（玉 16 の背景） | 40 | 40 | 39〜40 |
| E | 9〜11 | 9〜11 | 9〜11 |
| X | 4〜5 | 4〜5 | 21〜25 |
| C | 10〜13 | 9〜11 | 14〜18 |
| S（玉 16） | 114〜117 | 102〜103 | 118〜121 |
| T | 11〜30 | 5〜14 | 11〜26 |
| BUSY | 191〜214 | 171〜182 | 217〜237 |
| 速さ | 60 Hz | 60 Hz | 60 Hz |

- 玉が 0 なら BUSY は 32〜42 ライン（DSP）、51〜63 ライン（68000）。
- 玉 1 つは、R で約 2.5 ライン、S で約 7 ライン（ラスタのパレットを切ると約 6.4 ライン）。台帳 HD63484.md §3.8 の式（表示との競合なし）では CPY 1 つが約 1.9 ライン、SCPY 2 つが約 3.8 ライン。差は、基本画面の表示中に描画のメモリサイクルが減ること（エミュレータの表示との競合のモデル）と、68000 が玉を動かしてコマンドを送る時間。
- ラスタのパレットの割込みは、1 回が約 210 クロック（命令の表からの数え。割込みの受付を含む）で、160 ラスタで 1 フレームに約 34,000 クロック（約 66 ライン、68000 の時間の約 25%）。玉 16 で BUSY が 20〜30 ライン延びる。
- DSP は、段 K で送ってから段 X で受け取るまで（R と E の間）に計算を終えている。X の 4〜5 ラインは、DONE と尾の語を確かめてコマンドの並びを作る時間。68000 で同じ式を計算すると X は 21〜25 ライン。
- BUSY が約 245 ラインを超えると 30 Hz に落ちる。残りの約 17 ラインは、VBlank の割込み（BIOS の処理とフック、コッパーバーを塗る）、頁の切替え、段の長さの計算。
- 段の間で 68000 と ACRTC を重ねない（§04）ので、ここの数は、重ねて組んだときの上限より少し悪い。

時間の帯（B）で見ると、既定では K・R・E・X が VBlank の中に収まり、C が上画面のあたり、S が基本画面の大半、T が基本画面の終わりのあたりで、そのあと VBlank まで待つ。

### 玉の数の上限

玉の数を 1 つずつ増やし、20 フレーム慣らしてから 60 フレームの間のループのフレーム数を数えた [V]。60 Hz はどのループも 1 フレーム、30 Hz はどのループも 2 フレーム以内。

| 条件 | 60 Hz | 30 Hz |
|---|---|---|
| DSP、ラスタのパレット入（既定） | 20 | 48 |
| DSP、ラスタのパレット切 | 24 | 56 |
| 68000 の計算、ラスタのパレット入 | 17 | 44 |

- 既定で 21 にすると、ときどき 30 Hz に落ちる。初めの 16 は、境目から 4 つ空けた。
- 玉を 1 つ足すと、BUSY は既定で約 9.6 ライン、ラスタのパレットを切ると約 8.3 ライン延びる（16 個と 48 個の差から）。
- 1 フレームの画面の色は、ホストの 320×240 の画面の書き出しで 112〜121 色、エミュレータの試験で 119 色。ラスタのパレットを切ると 12 色。

### 他機との比べ

16×16 の動く物を、同じ年代の家庭用の機械と比べる。他機の値は一般に知られた仕様で、本リポジトリの台帳に出典を置いていない [V]。

| | 本機（このサンプル） | ファミコン（1983） | セガ・マークIII（1985） | MSX2（1985） |
|---|---|---|---|---|
| 動く物の作り方 | ACRTC で背景を戻して描く（専用の回路なし） | スプライト 64 枚（8×8 か 8×16） | スプライト 64 枚（8×8 か 8×16） | スプライト 32 枚（8×8 か 16×16） |
| 16×16 の物の数 | 60 Hz で 20、30 Hz で 48（描く時間で決まる） | 32（8×16 を 2 枚で 1 つ） | 32（同） | 32 |
| 1 ラインに横に並ぶ数 | 制限なし（描く時間に入る） | 4（1 ラインに 8 枚） | 4（同） | 8 |
| 1 つの物の色 | パレットの 16 色のどれでも（型を別に持つので透明に色を取らない）。背景と同じ 16 色を分け合う | 3 色＋透明 | 15 色＋透明 | 1 ラインに 1 色＋透明（重ねて増やす） |
| 1 画面の色 | 16 色のパレットを毎ライン書き換えて 119 色 | 25 色。表示中にパレットを書き換える手段がない（描画を止めれば書けるが、その間は画面が出ない） | 64 色のうち 32 色。ライン割込みでパレットを書き換えられる | 512 色のうち 16 色（256×212 の 16 色の画面）。ライン割込みでパレットを書き換えられる |
| 線と矩形の転送 | ACRTC のコマンド（直線、折れ線、論理演算つきの CPY） | なし | なし | VDP のコマンド（直線、論理演算つきの転送） |

- 数だけなら、ファミコンとマークIII のスプライトは 16×16 で 32 個を毎フレーム出せ、本機の 60 Hz の 20 個より多い。本機は 1 ラインに並ぶ数の制限がなく、1 つの物に 16 色を使え、30 Hz なら 48 個まで出せる。
- 本機の玉の時間は、背景を戻す時間を含む。ハードのスプライトは背景を壊さないので、この時間がいらない。
- 毎ラインのパレットの書き換えは、本機だけのものではない（マークIII と MSX2 もライン割込みを持つ）。ファミコンにはできない。本機では、HBlank の割込みを 1 フレームに 160 回受けても、68000 の時間の約 75% が残る。
- 立体の座標の計算を DSP に任せられるのは、この 4 つの中では本機だけ。68000 で計算するのと比べて、60 Hz の玉の数で 3 つ（17→20）の差になる。

## 06　[P] の決めごと

| 項目 | 値 | 理由 |
|---|---|---|
| 画面の分け方 | 上 16・基本 160・下 16 ラスタ | 文字の 2 行ずつを上下に置き、残りの 160 行を絵に使う |
| 基本画面の中 | 空 96 行、海 64 行、左右の縁 1 語 | 立方体は空、玉は海。縁は時間の帯を出す場所 |
| ラスタの表 | 160 行×（パレット 1、パレット 2、VIDEO_IRQ の語） | 1 回の割込みで書くのは 2 語と 1 語。最後の行で HBL_EN を下ろす |
| ラスタの表の指し手 | USP | 割込みの中の命令を減らす。BIOS は USP を使わない（bios-abi.md に書かれていない） |
| コッパーバー | 2 本、15 行、位相を 1 フレームに 2（256 で 1 回り） | 空の 96 行の中を約 2 秒で回る |
| 立方体 | 辺 128（模型の単位）、視点まで 330、焦点 128、角を 1 ループに 2・3・1（256 で 1 回り） | 回しても空の 96 行に収まる（中心からの広がりは最大 45.6 画素） |
| 頁の切替え | 基本画面を 2 頁、VBlank の中で SAR1 を替える | 描きかけを見せない |
| 立方体を消す方法 | 前の線のコマンドを空の色で送り直す | 空全体の CLR より短い |
| 玉の大きさと数 | 16×16、初め 16、0〜96 | ファミコンの 8×16 のスプライト 2 枚ぶん。初めの数は、ラスタのパレットを入れたまま 60 Hz で動く数 |
| 玉の動ける範囲 | 海の 64 行の中、縁の内側 | 背景を戻す元の絵が海だけで済む |
| 玉の型と絵 | 横に 4 通りずらし、5 語の幅で置く | 語の境目にそろえた CPY と SCPY だけで描ける（AGCPY を使わない） |
| FIFO への書込み | WFE なら 8 語続けて、そうでなければ語ごとに WFR | 語ごとに確かめるより 68000 の時間が短い |
| 待ちの上限 | VBlank 約 25 ms、DSP の結果 約 25 ms、ACRTC 65536 回 | 1 フレームより長い。ACRTC は DR-080 と同じ |
| 段の長さの出し方 | 16 ループの最大、16 ループごと | 数がちらつかない。予算の端を見られる |
| 下画面の描き直し | 1 ループに 2 欄まで | 段 T の長さをそろえる |
| 漢字の行 | 「日本の文字を出す」 | 文字 ROM の字形 v0.1 にある字で、漢字とかなを混ぜる |
| DSP と 68000 の約束 | `protocol.inc` | 頭と尾の語に番号を付け、ずれたら読み捨てて合わせる |
