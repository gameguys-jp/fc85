## 02　組み方と動かし方

リポジトリの根で：

```
py firmware/charrom/build.py
py firmware/boot/build.py
py sdk/samples/game/build.py
```

`sdk/samples/game/build/` に `game.bin`（像）、`game.lst`（リストと記号の表）、`sfx.bin`・`sfx.inc`（ADPCM の byte の列と EQU）、`sfx-<名前>.wav`（復号した効果音。確かめ用）ができる。

窓で遊ぶ（`emulator/` で）：

```
cargo run --release -p fc85-host -- --cart ../sdk/samples/game/build/game.bin
cargo run --release -p fc85-host -- --cart ../sdk/samples/game/build/game.bin --no-doc
```

キーは、方向キー、Z＝A、X＝B、C＝C、Enter＝START（ホストの割当て）。`--no-doc` は DOC の子基板がない機械で、低音が本体 DAC になる。

画面を見ずに確かめる（`<scratchpad>` は作業用の一時フォルダ）：

```
cargo run --release -p fc85-host -- --headless --cart ../sdk/samples/game/build/game.bin --frames 1200 --pad-script ../sdk/samples/game/pad-demo.txt --dump <scratchpad>/g.ppm --dump-at 30,60,200,664,1060 --wav <scratchpad>/g.wav
```

試験：`py -m unittest discover -s sdk/samples/game`（見出しと効果音）、`py -m unittest discover -s sdk/tools`（ADPCM の符号器と復号器）。

## 03　遊び方

| 操作 | 働き |
|---|---|
| START | 題名の画面で始める。終わりの画面でも、1.5 秒の後に START で始め直す |
| 方向キー | 自機（水色の輪）を 1 フレームに 2 画素動かす。斜めも可 |
| C | デバッグの行を出し入れする（§06） |
| B | デバッグの行を出している間だけ：石を 1 個足す（試験用） |
| A | デバッグの行を出している間だけ：拍の低音を止める・戻す（効果音だけを録るため） |

- 黄の菱形を拾うと 10 点。拾った菱形は 0.5 秒後に自機から離れた所に出る。
- 赤の石は壁で跳ね返る。最初は 2 個で、菱形を 5 個拾うごとに 1 個増える（8 個まで）。
- 石に当たると残りが 1 減り、背景が 8 フレーム赤くなり、2 秒は当たらない（自機が点滅する）。残り 0 で終わり。
- 最高点は電源を切るまで残る。点数は BCD で持ち、`BIOS_PUT_HEX` の 16 進の表示がそのまま 10 進になる。
- 最初の配置は決まっている。乱数（xorshift の 16 bit）の種に START を押したフレームを混ぜる。

## 04　効果音：Fabric から ADPCM へ

### 道

```
カートリッジ ROM ─(起動時に CPU が写す)→ Staging RAM（port 0）
  ─(Fabric のチャネル 0)→ ADPCM の FIFO（port 5、64 byte）
  ─(bridge が V̄C̄K̄ ごとにニブルを置く)→ MSM5205 → DAC
```

Fabric はカートリッジを読めない（ポートがない）ので、起動時に CPU が ADPCM の byte の列を Staging RAM の $1000〜（port 0 の番地。CPU からは $121000〜）に写す。CPU は MOVE.L で写す。port 0 の 8 bit の読出しは偶数番地が上位 byte なので（DR-046）、byte の順は ROM と同じになる。

### byte の列（build.py）

| 部分 | 中身 |
|---|---|
| 頭 | 0x08 を 5 byte（ニブル 0000 と 1000 の交互。予測値は 0 と 2 を行き来し、ステップ番号は 0 のまま） |
| 本体 | 合成した音。予測値（12 bit）の山を 1500 にそろえ、符号器には ±1800 を超えるニブルを選ばせない。回り込まないことを build.py と test_build.py が確かめる |
| 終わり | 無音を 20 ms 符号にして予測値を 0 の近くに戻し、0x08 を 4 byte |

ニブルは上位から（ADPCM の CTRL の bit 3＝0）。符号は、RESET の直後の状態（予測値 0、ステップ 0）から頭を復号した状態から作る。

| 番号 | 音 | 標本化 | byte | 長さ |
|---|---|---|---|---|
| 0 | 始まり（C5・E5・G5・C6 の分散和音） | 8 kHz | 1,929 | 0.48 s |
| 1 | 拾う（E6 から B6） | 8 kHz | 969 | 0.24 s |
| 2 | 当たる（雑音と、220 Hz から 55 Hz へ下がる低音） | 6 kHz | 969 | 0.32 s |
| 3 | 終わり（G4・E4・C4 と、C4 から C3 へ下がる音） | 4 kHz | 2,529 | 1.26 s |

### 手順（sfx.s）

起動時（`sfx_init`）：

1. `ADPCM_CTRL` ← RESET｜S1（電源投入時と同じく RESET。RESET の間、bridge は FIFO から取り出さない）
2. チャネル 0 の `CTRL` ← STOP、`STATUS` ← $1A（DONE・ERROR・MISS を消す。W1C）
3. ADPCM の byte の列を Staging RAM の $1000〜に写す
4. `FABRIC_PORT_RESET` ← bit 5（port 5 の FIFO を空にする）、`ADPCM_STATUS` ← UNDERRUN（W1C）

鳴らすとき（`sfx_play` で求め、`sfx_update` を 1 フレームに 1 回呼ぶ）：

1. **RESET をかける**（ARMED）。チャネル 0 を止め、`STATUS` を消し、`ADPCM_CTRL` ← RESET｜（この音の S1・S2）、`FABRIC_PORT_RESET` ← bit 5。
2. **次のフレームで送り始める**。RESET を 1 フレーム保ったので、取込み（V̄C̄K̄ の立下りの 6 クロック後）が何度か起き、MSM5205 は予測値 0・ステップ 0 になっている。チャネル 0 を次のとおりにして START：

   | レジスタ | 値 | 意味 |
   |---|---|---|
   | `SRC` | 0 | port 0（Staging RAM） |
   | `DST` | 5 | port 5（ADPCM の FIFO） |
   | `SRC_ADDR_L` | $1000＋offset | Staging RAM の byte 番地 |
   | `DST_ADDR_L` | 0 | port 5 は逐次（番地は使わない） |
   | `COUNT` | byte 数 | |
   | `SRC_STEP`・`DST_STEP` | 1・0 | |
   | `FORMAT` | 0 | 8 bit → 8 bit |
   | `MASK`・`XOR`・`SHIFT` | $FFFF・0・0 | 変換しない |
   | `TRIGGER` | 0 | 即時、ブロック、LOOP なし、割込みなし |
   | `CTRL` | START | |

3. `ADPCM_STATUS` の byte 数が 16 以上になるまで待つ（約 16 µs。上限あり）。UNDERRUN を消し、`ADPCM_CTRL` ← この音の S1・S2（RESET を外す）。PLAYING にする。
4. **終わりを待つ**。チャネル 0 の STATUS が DONE（全部を FIFO に書いた）になり、`ADPCM_STATUS` の byte 数が 0 になったら、チャネル 0 を止め、`ADPCM_CTRL` ← RESET｜S1 にして IDLE に戻す。ERROR なら同じく止める。送っている間に UNDERRUN が立ったら数える（デバッグの行の `UR`）。

鳴っている音をもっと強い音（始まり 4 ＞ 終わり 3 ＞ 当たる 2 ＞ 拾う 1。同じ強さも替える）に替えるとき：

0. **FLUSH**。チャネル 0 を止め、`STATUS` を消し、`FABRIC_PORT_RESET` ← bit 5。RESET はまだかけない。FIFO が空なので bridge は 0x08 を置き、MSM5205 は今の値の近くにとどまる。次のフレームで 1. に進む。

求めから音が出るまでは、IDLE からは 1〜2 フレーム、鳴っている音を替えるときは 2〜3 フレーム。

### 決めたことの理由

- **TRIGGER 0（即時）**：チャネルは FIFO が満杯の間は STALL で待つので、ブロックを 1 回で始めれば、FIFO の空きに合わせて送り続ける（DR-018 の「ADPCM への供給は FIFO の満杯待ちで足りる」）[P]。V̄C̄K̄（TRIGGER 5）で 1 byte ずつ送ると、1 byte に 2 ニブルあるので、送る速さが使う速さの 2 倍になり、FIFO が満ちた後は引き金の取りこぼし（MISS）が続くはず（試していない）[V]。
- **RESET は FIFO が空のときだけかける**：RESET の間、bridge はニブルを置かないので、MSM5205 の D3〜D0 には RESET の前に置いた最後のニブルが残る。RESET を外したのが V̄C̄K̄ の立上りと次の取込みの間なら、そのニブルが 1 つ復号される。外す時点を V̄C̄K̄ に合わせる手段は CPU にない（§09 の 1）。FIFO が空のとき（bridge が 0x08 を置いている）にだけ RESET をかければ、残るニブルは 0 か 8 で、ずれは予測値の ±2（10 bit の DAC のコードで 0 か 1）にとどまり、ステップ番号は 0 のまま [P]。鳴っている音を替えるときの FLUSH はこのため。頭の 0x08 は、それでも大きなニブルが残ったときにステップ番号を 0 にそろえる保険 [P]。
- **16 byte ためてから RESET を外す**：最初の数ニブルで FIFO が空にならないように [P]。Fabric は 1 byte を約 1 µs で書くので、すぐにたまる。

## 05　拍の低音（music.s）

A2・G2・F2・E2 を 1 拍ずつ繰り返す。間隔は 36−3×（石の数）フレーム（12 まで）で、石が増えると速くなる。包絡は打った後、毎フレーム 7/8 にして 1 を引く [P]。BIOS と同じく `bios_modules`（起動時の `FABRIC_MODULES`）の bit 2 で道を分ける（DR-019、bios-abi.md §06）。

- **DOC の子基板がある**：256 byte の矩形波（$C0 と $40。0 はオシレータを止めるので使わない）を Staging RAM の $0000〜に置き、チャネル 1（port 0 → port 2、FORMAT 0、即時）で波形 RAM の頁 0 に運ぶ。オシレータ 0（L）と 1（R）を自走させ、FC で音程、VOLUME で包絡。DOC の窓には MOVE.B の 1 回の書込みだけを使う（DR-030）。
- **ない**：本体 DAC。Staging RAM の $0100〜の 64 語（1 周期の矩形波、上位 L・下位 R）を、チャネル 1 が LOOP で port 2 の FIFO に送り続ける。音程は `FABRIC_AUDIO_N`（f＝8 MHz÷N÷64）、包絡は CPU が 64 語を書き直す（振幅は 8 bit の DAC の ±7 段まで）。

## 06　描画

- ACRTC だけを使う。動く物は XOR（OPM＝011）で描き、次に動いたときに、描いた位置へ同じ図形を XOR で描いて消してから、新しい位置に描く。下の絵を壊さないので、物が重なっても離れれば戻る（重なっている間は色が混ざる。例：石と菱形で緑）。
- 主ループは「`BIOS_WAIT_VBL` → 描く（ACRTC の仕事はここだけ）→ 入力 → 計算 → 音」。描く物は前のフレームで計算した位置なので、表示は入力の 1 フレーム後になる [P]。
- 1 フレームの ACRTC の仕事は VBlank（70 ライン）の中で終える。エミュレータで、VBlank の直後から ACRTC が空になるまでのライン数を測った [V]：石 2 個で 10〜11 ライン、石 8 個で 28〜29 ライン、遊んでいる間の最大は 46 ライン。
- `BIOS_PUTS` は 1 字に約 12 ライン（1 字ずつ呼んだとき。CPU が字形から 16 語を作る）[V]。6 桁を描き直すと VBlank を超える（2 個の石で 82 ライン）ので、点数と最高点は変わった桁だけ描く [P]。
- 終わりの枠は 3 フレームに分ける：①枠（縁と中を別に塗る、約 49 ライン）と残り、②最高点（変わった桁）と「GAME OVER」、③「PUSH START」。②と③は VBlank を超える（最大 85 ライン）が、表示がその行に来る前に描き終わるので裂けない [P]。
- 画面を作るとき（題名、始め直し）は、パレットを黒にしてから描き、ACRTC が空になったら次の VBlank でパレットを戻す [P]。
- 「PUSH START」の点滅はパレットの 14 番を書き換えるだけで、描き直さない。
- 矩形（`rect`）は 6 語を FIFO に書く。毎フレーム何十回も呼ぶので、書込みを開いて書く。どの語も SR の WFR を確かめてから書く（DR-033）。
- デバッグの行（C）：`LN`（このフレームの ACRTC の仕事のライン数）、`MX`（その最大。始めるたびに 0）、`UR`（効果音を送っている間の UNDERRUN の数）、`SE`（鳴らし始めた効果音の数）。すべて 16 進。数は 16 フレームごとに、測った後で描く。

## 07　エミュレータで確かめたこと [V]

`pad-demo.txt` で 1200 フレーム、子基板ありと `--no-doc` の両方。

- バスエラーは 0（カートリッジがあるので $400000 の見出しを読んでもバスエラーにならない）。DR-030 の注意も出ない。
- 画面：題名（30）、始まり（60）、石 8 個とデバッグの行（200）、当たった後（500）、終わりの枠が 3 フレームで描かれる（661〜664）、始め直し（1010）、拾った後（1060）を見た。物の跡や欠けはない。
- 音：WAV（48 kHz）の左を、`sfx.bin` を [adpcm.py](../../tools/adpcm.py) で復号した値（4×DAC のコード。エミュレータの混ぜ方）と比べた。低音を止めた後の「当たる」2 回と「終わり」1 回は、予測値のずれを −2・0・+2 から選ぶと全標本が一致した（ずれは回ごとに違う。§04）。低音が鳴っている間の「始まり」「拾う」は、正規化した相関 0.98 以上で見つかり、差は低音の大きさ（最大 880〜896）に収まる。子基板ありでもなしでも同じ。
- 鳴っている音を替える道（FLUSH）は、A で「当たる」を鳴らすように一時的に替えた像で確かめた：「拾う」が FIFO を空にした所で止まり、約 1 フレーム今の値の近くにとどまり、RESET で 0 になり、次のフレームに「当たる」が全標本一致で始まった。
- `UR` は 0 のまま（送っている間に FIFO が空にならない）。

## 09　仕様との隙間・気づいたこと

1. **ADPCM の RESET を外す時点を合わせられない** [V]。RESET は取込みの時点で効き（台帳 MSM5205.md §3.3）、RESET の間、bridge はニブルを置かない（emulator の `adpcm.rs`）。RESET を外したのが V̄C̄K̄ の立上りと次の取込みの間なら、RESET の前に置いた最後のニブルが 1 つ復号される。どのニブルでも予測値は 2 以上動くので、ずれは音の終わりまで残る。`ADPCM_STATUS`（DR-053）には V̄C̄K̄ のレベルも取込みの印もなく、CPU は時点を選べない。
   - 再現：FIFO を空にして RESET を外しておき（0x08 が流れる）、RESET｜S1 を書き、1 フレーム待ち、Fabric で FIFO を満たしてから S1 だけを書く。何回か繰り返して WAV を見ると、音全体が予測値の +2・0・−2 のどれかだけずれる（このサンプルで観測）。音の途中で RESET をかけると、残るのはデータのニブルで、ずれは最大 ±30、ステップ番号は最大 +8。
   - 案：RESET の解除を V̄C̄K̄ の立上りに合わせるフリップフロップを bridge に置く（解除の後の最初の取込みは必ず新しいニブル）か、STATUS に V̄C̄K̄ のレベルを出す（台帳 §4.6 の案の STATUS にはあったが、DR-053 の STATUS にはない）。レベルが見えれば、CPU は立下りの後の取込みを待ってから、次の立上りの前に外せる。
2. **本体 DAC のラッチが電源投入時に 0** [V]。`--no-doc` で、BIOS が中央（$8080）を書くまでの最初の 135 標本（約 2.8 ms）が −16384（負の最大）になる。電源投入のときに大きな音が出る。エミュレータの `audio.rs` でも [V] とされている。ラッチをリセットで $80 にするか、ミュートが要るかは仕様で決めること。
3. **m68kasm：末尾の EVEN はバイトを出さない**。番地は進むが、像は最後に出したバイトで終わるので、見出しの大きさ（`rom_end−CART`）が像の長さより 1 大きくなった。仕様どおり（m68kasm.py の冒頭の説明）だが、見出しの大きさを末尾のラベルで書くと間違えやすい。このサンプルは `IF` で 1 byte を足し、`ASSERT` と試験で確かめる。
4. **`BIOS_PUTS` は遅い** [V]。1 字に約 12 ライン（1 字ずつ）、10 字の文字列で 1 字に約 8.5 ライン。VBlank の中で描けるのは 5〜6 字まで。ゲームの表示に使うなら、bios-abi.md に 1 字の時間を書くか、ACRTC の文字の描き方（パターン RAM など）を BIOS の版 2 で考える。
