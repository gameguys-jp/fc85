# SAMPLE 9（MIDI で弾く DOC のシンセのカートリッジ）

**v0.1**  
2026年11月27日

> 状態：作業中の版。MIDI IN のノートを DOC（ES5503。子基板）で鳴らす C のサンプル（DR-128）。SDK の C の関数（`midi.h`・`doc.h`・`acrtc.h`。[c.md](../../docs/c.md) §09、DR-127）だけで書く。機械仕様は [仕様書](../../../docs/spec/hardware.md)、BIOS の約束は [bios-abi.md](../../docs/bios-abi.md)、DOC の動作は [台帳 ES5503.md](../../../docs/parts/ES5503.md) が正。このサンプルで決めた値はすべて [P] で、エージェントが決めた（ユーザーが方向を承認。要見直し）。題名の `SAMPLE 9` は中立な仮の名前で、製品名ではない。

記述ステータス：`[D]` 原典に根拠のある IC の仕様、`[P]` 本機独自の暫定設計値、`[O]` 代替・拡張候補、`[V]` 要検証（ここではエミュレータで測った値も [V] とする）。

## 01　概要

| 出すもの | 中身 |
|---|---|
| 8 声のシンセ | MIDI IN のノートオンを空いた声に割り当てる（空き → 離した音のうち古いもの → いちばん古いもの）。チャンネルは問わない。ベロシティは音量 |
| 声ごとのチャンネル | 声 v の鳴るオシレータを DOC の出力のチャンネル CA v（0〜7。偶数が L、奇数が R）に置き、鳴らさないオシレータ（止めたもの、SYNC の親、AM の変調）は CA 15 に置く。本機の DOC の子基板は CA ごとにサンプルホールドを持ち、同じチャンネルの止めたオシレータは中央の値を出して音を小さくする（bios-abi.md §06）。声ごとにチャンネルを分けると、声が重なっても 1 声の大きさが変わらない |
| 音色（5 つ） | TRI・SAW・SQUARE：声に 1 つのオシレータ。SYNC：偶数番を同期のモード（音量 0）にし、テーブルの頭に戻るたびに上の奇数番（のこぎり波）を頭から始める DOC のハードの同期（台帳 §4.2）。上の音程は鳴らし始めに 18 半音上から下りてくる。AM：奇数番を AM のモードにし、その波形（三角波）の値で上の偶数番（のこぎり波）の音量を書き換える（7 声）。AM の組は音量のレジスタを無視するので、ベロシティと包絡が効かず、離すとすぐ止める |
| 包絡とビブラート | 68000 が 1 フレームに 1 回、音量（立上り・減衰・持続・離し）と周波数を書く。60 Hz の段が付く。ビブラートは約 5.4 Hz の三角波で、深さはモジュレーション（CC 1）。SYNC と AM では CC 1 が上のオシレータの音程（0〜約 24 半音上） |
| MIDI OUT | THRU を入れると、受けたメッセージ（リアルタイムを含む）をステータスを付け直して送る。パッドで弾いた音、C のプログラムチェンジ、START の CC 123 はいつもチャンネル 1 で送る |
| 画面 | 音色、オクターブ、THRU、モジュレーション、ベンド、子基板の有無、8 声のノートとベロシティ、最後に受けたメッセージ、受けたメッセージの数、送った byte の数、受信のリングで捨てた数。下に 3 オクターブの鍵盤（押さえている音が赤）と、パッドの位置（水色の線） |

- 周波数：波形は 1024 byte のテーブル（T＝R＝2）。f＝SR×FC÷2^19、SR＝1 MHz÷18（DOC 8 MHz、走査 16。bios-abi.md §06）。ノート 120〜131 の FC を表に持ち、下のオクターブは右へずらす（ノート 69＝440 Hz は FC 4152）。ピアノの音域（ノート 21〜108）で平均律から 4 セント以内（試験が確かめる）。半音の間（ベンド、ビブラート）は隣の FC の間を直線で埋める。
- DOC の外部クロックのジャンパ（ベンド点 `clock doc`）を回すと、表を変えずに全体の音程が動く（仕様書 §11）。
- 子基板がなければ `DOC NONE` と出し、音は出さない。MIDI の受信、THRU、画面は動く。
- 像は約 7 KB。`$400000` から置く。

## 02　組み方と動かし方

リポジトリの根で：

```
py sdk/samples/midi/build.py
cd emulator
cargo run --release -p fc85-host -- --cart ../sdk/samples/midi/build/midi.bin --midi-list
cargo run --release -p fc85-host -- --cart ../sdk/samples/midi/build/midi.bin --midi-in 0 --midi-out 1
```

68000 の GCC が要る（[c.md](../../docs/c.md) §02）。GCC がなければ `build.py` は組まずに 2 を返し、試験は飛ばす。

| 場所 | MIDI のつなぎ方 |
|---|---|
| ホスト（`fc85`） | `--midi-list` で装置の番号を出し、`--midi-in N`・`--midi-out N` |
| Web の試しの頁 | `py emulator/embed/build.py`、`py emulator/embed/serve.py` で `http://127.0.0.1:8000/?sample=midi` を開き、「MIDI」の釦で使い始めて、IN と OUT を選ぶ（Chrome など Web MIDI のあるブラウザ。[emulator-api.md](../../docs/emulator-api.md) §08） |
| libretro | フロントエンドの MIDI の設定（RetroArch なら設定の「MIDI」） |
| 窓口 | JSON の手順 `midi`（試験と同じ。[emulator-api.md](../../docs/emulator-api.md) §03） |

| キー | 働き |
|---|---|
| 左・右 | 鍵盤の位置（3 オクターブ）。A を押したまま動かすと弾き直す |
| A | 弾く（押している間鳴る。MIDI OUT にも送る） |
| 上・下 | 鍵盤のオクターブ（0〜6。鍵盤の左端は C(オクターブ)） |
| B | THRU の入切 |
| C | 次の音色（MIDI OUT にプログラムチェンジ） |
| START | 全部止める（MIDI OUT に CC 123） |

| MIDI IN | 扱い |
|---|---|
| ノートオン・オフ（9n・8n、ベロシティ 0 のノートオン） | 弾く・離す |
| ピッチベンド（En） | ±2 半音 |
| CC 1 | モジュレーション |
| CC 120・123 | 全部止める |
| プログラムチェンジ（Cn） | 音色（番号を 5 で割った余り） |
| そのほか | THRU のときに送り直すだけ。SysEx は送り直さない（組立てで読み飛ばす） |

## 03　試験

`py -m unittest discover -s sdk/samples/midi`。FC の表が DOC の式と平均律から計算した値と同じかを確かめる。GCC があれば組んで見出しを確かめ、エミュレータの窓口（`fc85-api`）と Boot ROM もあれば、窓口の `midi` の手順で MIDI IN に byte を置いて動かし、次を確かめる：起動では 16 のオシレータが CA 15 で止まっている。ノートオンで声 0 が CA 0（L だけに音）、ランニングステータスの次のノートが CA 1（R）、ノート 69 の FC が 4152。ベンドで 1 半音上の FC。離すと止まって CA 15 に戻る。SYNC では偶数番が同期のモード・音量 0・CA 15 で、上の奇数番が掃引から同じ音程に下り、CC 1 の 127 で約 24 半音上。AM では奇数番が AM のモードで、上の偶数番の音量が動き、離すとすぐ止まる。THRU で受けたメッセージが 320 µs 以上の間で送り直され、パッドの A で C4 のノートオン、離してノートオフ。画面の鍵盤の押さえた音が赤。子基板なしでも THRU が動き、例外で止まらない。

## 04　確かめていないこと

- 実物の MIDI の装置（鍵盤、音源）とのやりとり [V]。ホスト・Web・libretro は、受けた byte をフレームの頭で MIDI IN の線に置くので、弾いた時刻は最大 1 フレーム遅れる（DR-126）。
- THRU は送る間（3 byte のメッセージで最長約 0.64 ms。ACIA は 2 byte まで待たずに受ける）戻らない。MIDI IN が線の上限で続くと、送り直しに 1 フレームのほとんどを使う [V]。
- AM の音量の書換えと、SYNC の頭に戻す時刻は、台帳の MAME の解釈（E10）に合わせたエミュレータの動作で、実物の DOC では確かめていない [V]（台帳 §4.2 の資料間の食い違い）。
