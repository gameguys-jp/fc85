# SAMPLE 10（Audio IN を録って弾くサンプラーのカートリッジ）

**v0.1**  
2026年11月28日

> 状態：作業中の版。背面の Audio IN（DR-129）の音を DOC（ES5503。子基板）の A/D で録り、波形 RAM に置いて MIDI とパッドで弾く C のサンプル（DR-131）。SDK の C の関数（`doc.h` の `doc_adc_record`・`midi.h`・`acrtc.h`。[c.md](../../docs/c.md) §09）だけで書く。機械仕様は [仕様書](../../../docs/spec/hardware.md)、BIOS の約束は [bios-abi.md](../../docs/bios-abi.md)、DOC の動作は [台帳 ES5503.md](../../../docs/parts/ES5503.md) が正。このサンプルで決めた値はすべて [P] で、エージェントが決めた（ユーザーが方向を承認。要見直し）。題名の `SAMPLE 10` は中立な仮の名前で、製品名ではない。

記述ステータス：`[D]` 原典に根拠のある IC の仕様、`[P]` 本機独自の暫定設計値、`[O]` 代替・拡張候補、`[V]` 要検証（ここではエミュレータで測った値も [V] とする）。

## 01　概要

| 出すもの | 中身 |
|---|---|
| 録る | B で、Audio IN の (L＋R)/2 を DOC の A/D で 16,384 標本録る（`doc_adc_record`）。標本の時刻はラスタの変わり目で、ラスタ 1・2・4 本ごと（15.7・7.85・3.93 kHz、1.04・2.09・4.17 秒。C で選ぶ）。TRIG が入っていれば、|値−128| が 12 以上になるまで 5 秒まで待ち、その標本から録る。来なければ `NO INPUT` と出して、前の音を残す。足りない分は 128（無音）で埋める |
| 録った音の色 | A/D の前の LPF は 7.9 kHz で固定（DR-129）なので、7.85・3.93 kHz で録ると折返しが残る。値は 8 bit で、0 は 1 にする（波形の 0 はオシレータを止める印）。鳴らすときも補間しない |
| 弾く | 録った音を Staging RAM（`$8000`）から Fabric で波形 RAM の頁 0 に運び、16 KiB のテーブル（T＝6、R＝7）にする。MIDI IN のノートとパッドの A を 8 声に割り当てる（空き → 離した音のうち古いもの → いちばん古いもの）。ノート 60 が録った高さ。ベロシティの 2 倍が音量。声 v はオシレータ v で、DOC の出力のチャンネル CA v（偶数 L、奇数 R）。鳴らさないオシレータは CA 15 |
| 鳴らし方 | ワンショット：テーブルの終わりで DOC が止める（離しても終わりまで鳴る）。LOOP（上で切り替える）：テーブル全体をくり返し、離すと 1 フレームに 24 ずつ音量を下げて止める。どちらも、H＝1・M0＝1 を書いてアキュムレータが 0 に戻るのを待ってから（ラスタ 3 本）鳴らすので、テーブルの頭から始まる（台帳 §4.2） |
| 画面 | 録る周波数、LOOP、TRIG、入力の大きさ（1 フレームに 1 回 A/D を読んだ値の山。少しずつ下げる）、パッドの音程（KEY）、状態、録った長さ（16 進）、録った音の波形（横 256 ドットに 64 標本ずつの最小と最大）、8 声の印（鳴っている声が赤）、受けた MIDI のメッセージの数 |

- 走査：DOC は 32 のオシレータを走査する（1 MHz÷34＝29.4 kHz）。1 標本で FC÷2^10 byte 進む（台帳 §4.3）ので、ラスタの周波数 15,699.76 Hz（21.47727 MHz÷4÷342）の標本を録った高さで鳴らす FC は 546.6（表は 256 倍の 139,930）。半音は 2^(k/12) の表（Q12）で、半音の間（ピッチベンド）は直線で埋める。FC の分解能で、録る周波数が低いほど低い音が外れる（ノート 36〜96 で、15.7 kHz は 6 セント、3.93 kHz は 16 セント以内。試験が確かめる）。
- 録る前のテーブルは、68000 が作る減衰するのこぎり波（15.7 kHz で 60 標本の周期、C4）。
- 録る間（最長 5 秒の待ちと 4.17 秒）は割込みを止めるので、画面、パッド、MIDI の受信が止まる。そのあいだに来た MIDI の byte は失う（ACIA のあふれ）。録った後、波形 RAM へ運んで波形を描く間（約 0.15 秒）も主のループは回らない。
- 子基板がなければ A/D の道も DOC もないので、`NO DOC` と出し、録らず、音も出さない。MIDI の受信と画面は動く。
- 像は約 5 KB。`$400000` から置く。

## 02　組み方と動かし方

リポジトリの根で：

```
py sdk/samples/sampler/build.py
cd emulator
cargo run --release -p fc85-host -- --cart ../sdk/samples/sampler/build/sampler.bin --audio-in voice.wav
cargo run --release -p fc85-host -- --cart ../sdk/samples/sampler/build/sampler.bin --audio-in-device default --midi-in 0
```

68000 の GCC が要る（[c.md](../../docs/c.md) §02）。GCC がなければ `build.py` は組まずに 2 を返し、試験は飛ばす。

| 場所 | 音の入れ方 |
|---|---|
| ホスト（`fc85`） | `--audio-in FILE.wav`（ファイルは始めから流れるので、先に B で待たせるか、TRIG で頭を待つ）か `--audio-in-device N|default`（`--audio-list` で番号）。MIDI は `--midi-in N` |
| Web の試しの頁 | `http://127.0.0.1:8000/?sample=sampler` を開き、「Audio IN」の欄でマイク・ライン入力か音のファイルを選ぶ（DR-130） |
| libretro | 選択肢 `fc85_audio_in` を enabled にする（フロントエンドのマイク。DR-130） |
| 窓口 | JSON の手順 `audio_in`（試験と同じ。[emulator-api.md](../../docs/emulator-api.md) §03） |

| キー | 働き |
|---|---|
| A | 弾く（KEY の音程。A を押したまま左・右で弾き直す） |
| 左・右 | KEY（ノート 60 から ±24 半音） |
| B | 録る |
| C | 録る周波数（15700・7850・3925 Hz） |
| 上 | LOOP の入切 |
| 下 | TRIG の入切 |
| START | 全部止める |

| MIDI IN | 扱い |
|---|---|
| ノートオン・オフ（9n・8n、ベロシティ 0 のノートオン） | 弾く・離す（チャンネルは問わない） |
| ピッチベンド（En） | ±2 半音 |
| CC 120・123 | 全部止める |
| そのほか | 使わない |

## 03　試験

`py -m unittest discover -s sdk/samples/sampler`。半音の表と録った高さの FC が、DOC の式とラスタの周波数と平均律から計算した値と同じかを確かめる。GCC があれば組んで見出しを確かめ、エミュレータの窓口（`fc85-api`）と Boot ROM もあれば、次を確かめる：起動では 32 のオシレータが止まって CA 15 で、波形 RAM の頁 0 から 16 KiB がのこぎり波。A で声 0 がワンショット・FC 547・CA 0（L だけに音）で鳴り、約 63 フレームで止まって CA 15 に戻る。窓口の `audio_in` で 440 Hz・±0.5 V の正弦波を入れて B で録ると、最初の標本がしきい値を超え、値が 75〜80 から 176〜181（式では 76〜179）、4,096 標本に上へ 128 を横切る数が 114〜115（1 周期 35.68 標本）、波形 RAM が録った音と同じ、画面の波形の縦の幅が式どおり。MIDI のノート 72 で声 1 が CA 1（R）・FC 1,093 で鳴り、R の音が 880 Hz（±2%）。LOOP では 90 フレームたっても鳴り、離すと 12 フレームで止まる。7.85 kHz で TRIG なしに録ると、何も来ない Audio IN は 128 で、A の FC は 273。TRIG で何も来なければ 5 秒で `NO INPUT`。子基板なしでも MIDI を受け、録らず、例外で止まらない。

## 04　確かめていないこと

- 実際のマイク・ライン入力からの録音 [V]（ホスト・Web・libretro の入れ方は DR-129・DR-130 で確かめたが、このサンプルでは窓口の正弦波だけ）。
- ES5503 の A/D が変換のどの時点で入力を取るか（エミュレータは変換の終わりに取る）[V]（DR-129）。標本の時刻のゆれ（ラスタの変わり目を見る間の数 µs）[V]。
- H＝1・M0＝1 でアキュムレータが 0 に戻る時期は、台帳の MAME の解釈（E10）に合わせたエミュレータの動作で、実物の DOC では確かめていない [V]（台帳 §4.2、§5）。
