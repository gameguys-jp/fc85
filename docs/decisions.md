# 決定記録

> 決めたことを、理由と却下した案とともに残す。未決の課題は [open-issues.md](open-issues.md) に書く。新しい決定は末尾に追加し、過去の決定を書き換えない（覆すときは新しい DR で「DR-xxx を置き換える」と書く）。

## DR-001　基準年は1985年のまま。主要ICを代替品に置き換えない

| 項目 | 内容 |
|---|---|
| 日付 | 2026-11-25 |
| 決定 | 基準年を1985年（T2:1985）のまま維持する。HD63484 と ES5503 を他のICに置き換えない |
| 理由 | T2 は「入手可能な部品・技術に限定。予算・商業性は緩和可」。HD63484 は1984年7月に公表され、1985年1月の米国広告、6月の採用ボード発表、8月の正式データシートがある（[supply-HD63484.md](parts/supply-HD63484.md)）。ES5503 は1985年に Mirage の量産品に載り、同年6〜8月の Apple 社内文書にも現れる（[supply-ES5503.md](parts/supply-ES5503.md)）。問題は「存在」ではなく「入手経路」で、これは物語で扱う（DR-006） |
| 却下した案 | 1986年に移す：HD63484 は量産品扱いになるが、ES5503 は1986年でも Apple 以外の採用例がなく弱点が残る。「1985年に完成」の前提も崩れる。代替品（µPD7220、V9938、ヤマハ FM、個別部品の音源）：COPY による描画、任意データの波形再生という本機の骨格が崩れる |
| 影響 | OI-011、OI-028 |

## DR-004　ACRTC は HD63484-8 を 2CLK 5.369 MHz で使う

| 項目 | 内容 |
|---|---|
| 日付 | 2026-11-25 |
| 決定 | HD63484-8（1985年後半の量産初期品）を 2CLK 5.369318 MHz で使う。-4／-6 品は使わない |
| 理由 | 1985年に出回ったのは -8 品だけで、-4／-6 品が開発中でなくなるのは1987年の資料から（[supply-HD63484.md](parts/supply-HD63484.md)）。2CLK の周期 186 ns は -8 品の下限 125 ns に収まる。日立自身の設計例も -8 品を 5.03 MHz で使う（[HD63484.md](parts/HD63484.md)） |
| 却下した案 | 2CLK 8 MHz：256 画素が画面幅に収まらず、1985年の DRAM で VRAM を組めない。エンジニアリングサンプルという設定：1985年の市場流通の証拠があり不要 |
| 影響 | spec/hardware.md §04・§07、OI-027、OI-028 |

## DR-005　VRAM は 64K×1・120 ns ×16、読みと書きで CAS を分ける

| 項目 | 内容 |
|---|---|
| 日付 | 2026-11-25 |
| 決定 | VRAM 128 KiB を日立 HM4864A-12（64K×1、120 ns）×16 で組み、読み出しと書き込みで CAS の時刻を分ける回路にする |
| 理由 | 2CLK 5.369 MHz で読み書き共通の CAS にすると tCAC 46 ns 以下が要り、1985年の DRAM にない。CAS を分ければ -12 品で余裕がある（[review-digital.md](parts/review-digital.md) §5.1）。64K×4 品は1985年には予告だけ |
| 却下した案 | HM50464（64K×4）×4：1985年の日立メモリ資料に載っていない。-15 品：成り立つが余裕が薄い（[O]） |
| 影響 | spec/hardware.md §05、OI-032 |

## DR-007　ヤマハ FM を採らず、DSP には TMS32010 を使う

| 項目 | 内容 |
|---|---|
| 日付 | 2026-11-25 |
| 決定 | 音源にヤマハ FM を使わない。DSP は TMS32010 を維持し、富士通 MB8764 を代替候補 [O] とする。NEC µPD7720 は使わない |
| 理由 | 1985年の国産機ではヤマハ FM が標準だった（[baseline-1985.md](parts/baseline-1985.md)）。本機は「媒体を作り・変換し・交換する装置」で、録音した音や文字・画像のデータをそのまま波形として鳴らす必要がある。FM はこれができない。DSP はプログラムを RAM に読み込んで差し替える必要があり、外部メモリのプログラムを全速で実行できる1985年以前の DSP は TMS32010 と MB8764（1985年12月）だけ。µPD7720 と HD61810 は内蔵 ROM 方式（[review-signal.md](parts/review-signal.md)） |
| 却下した案 | ヤマハ FM：上記の理由。µPD7720：プログラムを差し替えられない |
| 影響 | spec/hardware.md §04、story/sound-redesign.md |

## DR-011　音源部は子基板。差し替えの跡を残す

| 項目 | 内容 |
|---|---|
| 日付 | 2026-11-25 |
| 決定 | DOC、波形 RAM 64 KiB、アダプタ、出力アンプを子基板に載せる。DOC のクロックは既存の 16 MHz を 2 分周して流用する。出力回路は差動出力の両側にアンプを入れ、初期の片側配線をジャンパで選べる形で残す（Bend モードの材料）。DOC の子基板を外しても、DSP のソフト合成で音が出る構成を残す [P] |

## DR-013　本体では外部映像との重ね合わせを使わない。ゲンロックは映像拡張基板の候補

| 項目 | 内容 |
|---|---|
| 日付 | 2026-11-25 |
| 決定 | 本体の映像クロックは固定の水晶（21.47727 MHz）のままとし、外部映像に同期させる回路（ゲンロック）を載せない。BA7230LS の重ね合わせ（スーパーインポーズ）機能は本体では使わない。ゲンロック（ACRTC の外部同期と、映像系クロックを外部映像にロックする VCXO／PLL）は映像拡張基板の候補 [O] とする。BA7230LS の採用は維持する。DR-009 の採用理由のうち「重ね合わせ機能が本機の映像入力と合う」を、この決定で置き換える |
| 理由 | 重ね合わせには、RGB が外部映像に同期している必要がある（[review-signal.md](parts/review-signal.md) §3）。本体の固定クロック（DR-003）のままでは使えない。外部映像の取り込み（§10）と Composite feedback（§11）は取り込み経路で成り立ち、重ね合わせに依存しない。BA7230LS は、国産・+5 V 単一・1985年の家庭用機での採用という理由だけで選ぶに足りる（DR-009）。仕様書 v0.1 から、外部映像入力は基板の分離を許容している |
| 却下した案 | 本体にゲンロックを載せる：映像系クロック全体を外部映像に追従させる回路が要り、未検証の回路が本体に入る。重ね合わせ自体は1982年のシャープ X1 にもあり、当時として不自然ではない（[baseline-1985.md](parts/baseline-1985.md)）。拡張基板として残す |
| 影響 | spec/hardware.md §04・§10、OI-041 |

## DR-014　設計方式は工場を持たないメーカーの作り方から生まれ、強みであり量産断念の原因でもある

| 項目 | 内容 |
|---|---|
| 日付 | 2026-11-25 |
| 決定 | 物語の正典を [story/architecture.md](story/architecture.md) のとおりとする。本機の設計方式（仕様書 §01）は、半導体工場を持たないメーカーが市販 IC を手を加えずに使い、IC ごとのつなぎ回路で組んできたやり方を、1983末〜84年の再設計で原則にまとめたもの。この方式により ES5503 の差し替えが間に合い、映像入力・ゲンロック・通信を拡張基板に分けられた。同じ方式が機能の追加を容易にし、部品点数と原価を押し上げて量産断念の主因になった。作中での方式の呼び名は決めない |
| 理由 | 仕様書の骨格（各 IC のネイティブポート、Data Fabric、予約ポート 11〜15、DOC 用アダプタ）に、物語上の由来を与える。違うバスの IC を IC ごとのアダプタでつなぐのは当時の実例がある（Apple IIGS の Sound GLU、[supply-ES5503.md](parts/supply-ES5503.md) §0）。アダプタが増えると原価が上がるのは工学的に正しく、量産断念の主因（原価）の説得力が増す |
| 却下した案 | 方式を物語と切り離した設計上の標語にとどめる：差し替えや拡張基板の物語と設計がつながらず、N3〜4（物語が設計に効く）の狙いに合わない |
| 影響 | story/architecture.md、story/main.md、story/sound-redesign.md、README。工場を持たない中堅メーカーの設計慣行の裏付けは調査中（[sources.md](sources.md)） |

## DR-016　68000 と ACRTC のインタフェース

| 項目 | 内容 |
|---|---|
| 日付 | 2026-11-25 |
| 決定 | (1) ACRTC の CS は、68000 のバスサイクルの S4 の立上りで登録して作る。(2) ACRTC の DTACK は CPU へ直結し、つなぎ回路（バスエラーのタイマーなど）には 2 段の FF で同期化した写しを渡す。(3) Data Fabric との DMA は 1 語ごとのサイクルスチールとし、各語の間で CPU のアクセスを優先する。DREQ と DMA 時の DTACK に 2 段、DONE に 1 段の同期化 FF を置く。(4) ACRTC の AR/STATUS・データポートに CLR・TAS などの読み書き一体の命令を使わないことを、ソフトの規約とする（BIOS・SDK の文書に書き、エミュレータで警告する）。DMA 中は CPU から ACRTC の FIFO にアクセスしない |
| 理由 | 1985年5月の HD63484 ユーザーズマニュアルの AC 特性からの計算（[host-acrtc-interface.md](parts/host-acrtc-interface.md)）。AS から直接 CS を作ると R/W のセットアップ 50 ns を満たせない（§4）。S4 で登録し DTACK を直結すると 2〜4 ウェイト（3 が約7割）、1 アクセス 6〜8 クロック（§5）。68000 は DTACK を内部で同期化し、1984年の日立の構成図も直結している（§6）。まとめて転送すると CPU を 28〜48 クロック待たせ、バスエラー判定の 64 クロックに対して余裕が小さい（§7.4）。CLR は読み出しと書き込みの別サイクルになり、回路で見分けにくい。同期化回路は TTL 約 8〜11 個で、Data Fabric の共通部に収まる（§7.6） |
| 却下した案 | CS を AS から直接作る：セットアップ不足。DTACK を CPU にも同期化して渡す：待ちが約1ウェイト増えるだけで利点がない。バースト転送：CPU の待ちがバスエラー判定に近づく。CLR・TAS をバスエラーにする：TAS は検出できるが CLR は難しく、規則が中途半端になる |
| 影響 | spec/hardware.md §05・§06・§07、OI-039。連続アクセスと書込み直後の読出しの追加待ち、FIFO が満杯・空のときの動作は OI-047 |

|---|---|
| 日付 | 2026-11-25 |
| 決定 | (1) FIFO はすべて 64 段にする。DSP の入力・出力は 64×16（67401×4 ずつ）、ADPCM の入力は 64×8（67401×2）。(2) 待つのは Data Fabric の側だけとする。一定の速さで読み書きする IC（DSP、MSM5205）の側は待てないので、ポートアダプタが動作を決める。DSP が空の入力 FIFO を読むと最後の語が返り、満杯の出力 FIFO への書込みは捨てられる。ADPCM の FIFO が空のときは 0x08（ニブル 0000 と 1000 が交互）を供給する。いずれも UNDERRUN／OVERRUN を記録し、DSP の状態ポートと 68000 側の bridge の STATUS（W1C）に見せる。(3) ADPCM のニブルは上位から使う。CTRL で、下位から使う動作と、空のときに置換しない動作（Bend）を選べる。(4) ADPCM の残量を 7-bit のカウンタで数え、半分空いたら割込みを出す。電源投入直後の 67401 の出力値は資料にないので [V]、エミュレータは 0x0000 とする |

## DR-019　DOC の子基板がないときの構成と、本体の DAC

## DR-040　エミュレータを Rust で書き、段階 1 を MSM5205 から始める

| 項目 | 内容 |
|---|---|
| 日付 | 2026-11-25 |
| 決定 | (1) エミュレータは Rust（edition 2024）で書く。`emulator/` を cargo の workspace にし、仕様書 §12 の層ごとに crate を分ける（まず chips 層の `fc85-chips`）。(2) IC ごとのコアは自前で書く。MAME などの既存実装はコードを写さず、台帳に書き起こした式とタイミングから書く。(3) 状態はすべて serde で保存・復元できるようにする（snapshot、Bend のパッチの undo）。(4) ホストの表示・音声・操作 UI のライブラリは、host 層に着手するときに決める（SDL3、egui が候補）。(5) 段階 1 は MSM5205 から始める。実装の文書は [impl/emulator.md](impl/emulator.md) |
| 理由 | ユーザーの判断（推奨の Rust を選んだ）。IC のコアを自前で書くなら、MAME と同じ言語である利点は小さい。V3（独立実装との比較）のためにも、既存のコードは写さないほうがよい。§11 のライブ運用には状態の snapshot とパッチの undo が要り、Rust は serde で全 IC の状態をまとめて保存・復元できる。cargo でビルドと試験が簡単で、ブラウザ向け（wasm）も出しやすい。MSM5205 は台帳に式と試験の値（DR-021）がそろっていて、外部の状態が少ない |

| 影響 | 仕様書 §12、impl/emulator.md（新規）、emulator/（新規）、CLAUDE.md、README.md |
