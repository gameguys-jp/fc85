## 2. 仕様

### 2.1 本台帳で使う AC 特性（8 MHz）

日立の 1985年のデータブック [D DB85 p.588–589] による。Motorola の 1983年4月版 [D M68 §8.6 p.8-4〜8-5] と同じ値。読み書きのサイクルの値（tCHSL、tAVSL、tCHRL、tASRV、tCLSH、tSHDO、tDICL、tSHDAH など）は host-acrtc-interface §3 にまとめたので、ここでは繰り返さない。

| No. | 記号 | 項目 | 8 MHz の値 |
|---|---|---|---|
| 1 | tcyc | クロック周期 | 125〜500 ns |
| 14 | tSL | AS の Low 幅 | 240 ns 以上 |
| 14A | — | DS の Low 幅（書込み） | 115 ns 以上 |
| 15 | tSH | AS・DS の High 幅 | 150 ns 以上 |
| 31 | tDALDI | DTACK↓ → 読出しデータ確定（非同期） | 90 ns 以下 |
| 33／34 | tCHGL／tCHGH | クロック↑ → BG↓／BG↑ | 70 ns 以下 |
| 35 | tBRLGL | BR↓ → BG↓ | 1.5〜3.5 クロック |
| 36 | tBRHGH | BR↑ → BG↑ | 1.5〜3.5 クロック |
| 37 | tGALGH | BGACK↓ → BG↑ | 1.5〜3.0 クロック |
| 38 | tGLZ | BG↓ → 制御・アドレス・データのバスが高インピーダンス（AS が High のとき） | 80 ns 以下 |
| 39 | tGH | BG の High 幅 | 1.5 クロック以上 |

| 43 | tVMLEH | VMA↓ → E↑ | 200 ns 以上 |

| 50／51 | tEH／tEL | E の High 幅／Low 幅 | 450 ns 以上／700 ns 以上 |
| 47 | tASI | 非同期入力のセットアップ（BERR、BGACK、BR、DTACK、IPL0–2、VPA） | 20 ns 以上 |

- DTACK と BERR が #47 を満たせば、#48 は 0 でよい。#47 を満たせば #31 は無視してよい（読出しデータは #27 tDICL を満たせばよい）[D DB85 p.589 注]。
- 非同期入力が #47 を満たせば、次の立下りで認識されることが保証される [D DB85 p.592]。満たさない入力も認識されることはある（host-acrtc-interface §3）。
- 電源投入時は 100 ms 以上のリセットが要る [D DB85 p.589 注]。

### 2.2 バスサイクル（S0〜S7）

クロックの半周期ごとに S0〜S7 と数え、S0 は立上りで始まる。待ちがなければ 4 クロック（8 MHz で 500 ns）。待ちは Sw を 2 つ（1 クロック、125 ns）ずつ入る [D M68 p.4-6〜4-9; DB85 p.596–599]。

| 状態 | 読出し | 書込み |
|---|---|---|
| S0 | FC を出す。R/W を High にする | 同じ |
| S1 | アドレスを出す | 同じ |
| S2 | AS↓、UDS・LDS↓ | AS↓、R/W↓ |
| S3 | — | データを出す |
| S4 | S4 の終わりの立下りで DTACK を見る。認識されなければ待ちを入れ、以後の立下りごとに見る | UDS・LDS↓。DTACK の扱いは読出しと同じ |
| S5 | — | — |
| S6 | 装置がデータを出す | — |
| S7 | S7 に入る立下りでデータを取り込み、AS・UDS・LDS↑。S7 の終わりでバスを離す | S7 に入る立下りで AS・UDS・LDS↑。S7 の終わりでバスを離し、R/W を High にする |

- DTACK は S4 から、VPA と BERR は S0 から、立下りごとに見る [D DB85 p.610]。
- AS↓ から DTACK までの時間に上限はない。応答がなければ CPU は待ち続けるので、外部のタイマーで BERR を出す [D M68 §4.1.6 p.4-3, §4.4 p.4-23]。
- 同期式の回路では、DTACK・BERR・HALT をクロックの立上り（S4 など）で出す [D DB85 p.593; M68 §4.3 p.4-21]。
- データストローブ：UDS は D15–D8（偶数番地）、LDS は D7–D0（奇数番地）。ワードは両方 [D M68 表4-1 p.4-2]。
- 読み・変更・書きのサイクル（TAS）は、AS を下げたまま読みと書きを続ける [D M68 §4.2.1.3 p.4-10]。この間はバスを渡さない（BGACK の条件に AS の High があるので、推定）。
- ワード・ロングワードを奇数番地で扱おうとすると、バスサイクルを出さずにアドレスエラー（ベクタ 3）になる [D M68 §5.3.10 p.5-11〜5-12]。
- 1 アクセスの所要と ACRTC への待ちの数は host-acrtc-interface §5（S4 で CS を登録する構成で 2〜4 ウェイト）。

### 2.3 DTACK・BERR・HALT の組合せ

| 外部の入力 | 結果 | 根拠 |
|---|---|---|
| DTACK だけ | 通常の終了 | [D M68 表4-4 p.4-21] |
| BERR だけ（DTACK なし） | サイクルを打ち切り、S9 で終える。バスエラー例外（ベクタ 2、$000008） | [D DB85 p.610; M68 §4.2.4 p.4-18] |
| DTACK と BERR を同時 | バスエラー（表4-4 の場合 4）。例 A は、番兵のタイマーが DTACK と BERR を同時に出す構成 | [D M68 p.4-21〜4-22] |
| BERR と HALT | 再実行（re-run）。BERR を HALT より 1 クロック以上前に外す。TAS は再実行しない | [D M68 p.4-18] |
| HALT だけ | 現在のサイクルを終えて止まる。HALT を外すと再開する。1 サイクルずつ進める用途に使える | [D M68 p.4-19] |

- BERR を保つ間、アドレスとデータのバスは高インピーダンス [D M68 §4.2.4.1 p.4-18]。
- BERR を DTACK と併用するときは、BERR を DTACK の 20 ns 以上前に出す（#48）。両方が #47 を満たせば 0 でよい [D DB85 p.588–589]。
- バスエラーの例外はグループ 0 で、7 語を積む（状態語、アクセスアドレス、命令レジスタ、SR、PC）[D M68 §5.3.9 p.5-10〜5-11]。
- 二重バスフォルト：バスエラー・アドレスエラー・リセットの例外処理中に、もう一度バスエラーかアドレスエラーが起きると止まり、HALT を出力する。戻すのはリセットだけ。リセット後の最初の命令の前のバスエラーも同じ [D M68 p.4-20]。
- HALT 中の FC は、一部のマスク（R9M、T6E、BF4）では高インピーダンスになる [D M68 表4-3 注 p.4-5]（Motorola のマスク名。日立品との対応は未確認 [V]）。

### 2.4 割込み（IPL0–2、IACK、オートベクタ）

| 項目 | 内容 | 根拠 |
|---|---|---|
| 要求 | IPL0–2 にレベルを符号化して入れる（3 本とも High で要求なし、3 本とも Low でレベル 7） | [D M68 §4.1.5 p.4-3] |
| 受付 | 命令の境界で、要求のレベルが SR の割込みマスクより高いときに受け付ける。レベル 7 はマスクできず、レベルが 7 に変わったときに受け付ける | [D M68 §5.3.2 p.5-7] |
| IPL の保持 | IACK サイクル（FC＝111）が始まるまで IPL を変えない | [D M68 §4.1.5 p.4-3]。DB85 の信号の説明 [p.593] にはこの文がない |
| IACK サイクル | FC＝111 の読出しサイクルで、A1–A3 に受け付けたレベルを出す。UDS と LDS を両方出す | [D M68 p.5-7〜5-8 図5-5・5-6] |
| 応答 1：DTACK | 装置が D0–D7 にベクタ番号を出す | [D M68 p.5-7] |
| 応答 2：VPA | オートベクタ。レベル 1〜7 がベクタ 25〜31（$64〜$7C）。サイクルは E に同期する（§2.5） | [D M68 p.5-7; DB85 p.594, p.613] |
| 応答 3：BERR | スプリアス割込み（ベクタ 24、$60） | [D M68 §5.3.4 p.5-9; DB85 p.613] |
| 未初期化 | 68000 系の周辺が初期化前に返す番号はベクタ 15 | [D M68 §5.3.3 p.5-9; DB85 p.613] |
| 受付後 | SR を写し、スーパーバイザにし、トレースを外し、マスクを受け付けたレベルにする | [D M68 §5.3.2 p.5-7] |
| 例外処理の時間 | 44(5/3) クロック。IACK を 4 クロックと仮定した値 | [D DB85 p.661 表39; M68 表7-16] |
| オートベクタの時間 | IACK が 10〜19 クロックになるので、50〜59 クロック（8 MHz で 6.25〜7.375 µs） | 計算（§2.5） |
| 回路例 | 74LS148 で要求を IPL に符号化する例、オートベクタのタイミング | [D DB85 p.624 図49, p.625 図50] |

### 2.5 6800 系周辺（E・VPA・VMA）と HD6850

| 項目 | 内容 | 根拠 |
|---|---|---|
| E | CLK の 1/10。Low 6 クロック、High 4 クロック。バスサイクルと無関係に回り続ける。8 MHz で 800 kHz | [D DB85 p.594; M68 §4.1.7 p.4-4]（値は MC6850 §3.3） |
| VPA | アドレスのデコードと AS から作る。CPU は VPA を認識すると E に同期したサイクルに切り替える | [D M68 §6.1 p.6-2; DB85 p.619] |
| VMA | VPA に応えてだけ出る。周辺の CS はアドレスと VMA から作る | [D M68 §4.1.7 p.4-4, §6.1 p.6-2] |
| VPA の解除 | AS↑ の後 1 クロック以内に外す（#44 は 0〜120 ns） | [D M68 §6.1 p.6-3; DB85 p.589] |
| 最良の場合 | VPA の認識が E↑ の 3 クロック前。待ち 6 クロック、計 10 クロック | [D M68 図6-2; DB85 p.621–622 図45] |
| 最悪の場合 | VPA の認識が E↑ の 2 クロック前（1 周期待つ）。待ち 15 クロック、計 19 クロック | [D M68 図6-3; DB85 p.621–622 図46] |
| 所要 | 10〜19 クロック＝1.25〜2.375 µs（8 MHz）。E の位相が一様なら平均 14.5 クロック | 計算 |
| 連続アクセス | E の 60/40 のデューティで、VPA のサイクルを続けて実行できる | [D M68 §6.1 p.6-2] |
| 1 MHz の周辺 | 8 MHz の CPU でも使える | [D DB85 p.619] |
| 接続例 | HD6821 PIA と HD6850 ACIA。VPA は AS とアドレスのデコード、CS は VMA とアドレス、E は CPU の E | [D DB85 p.623 図48] |

- 所要の計算：S0 から VPA を認識する S4 の終わりの立下りまで 2.5 クロック。認識から E↑ まで d クロック（d＝3〜12。2 以下なら次の E を待つので d＋10）。E の High 4 クロック、S7 の半クロックを足して 2.5＋d＋4＋0.5＝10〜19（計算）。
- オートベクタの IACK も同じサイクルなので、IACK は 10〜19 クロック（計算）。
- 本機の HD6850 は上位バイトレーン（D15–D8、偶数番地、UDS）に置く（仕様書 §05）。

### 2.6 バス調停（BR・BG・BGACK）と 68000S マスク

| 項目 | 内容 | 根拠 |
|---|---|---|
| 要求 | 外部の装置が BR を出す（ワイヤード OR）。CPU は始めたサイクルを終えてからバスを離す | [D M68 §4.2.2.1 p.4-13] |
| 許可 | CPU は内部で同期した後すぐに BG を出す。サイクルを始めると決めて AS をまだ出していないときだけ、AS を出すまで BG を遅らせる | [D M68 §4.2.2.2 p.4-13] |
| 受領 | 要求した装置は、BG を受け、AS・DTACK・BGACK がすべて High になってから BGACK を出す | [D M68 §4.1.4 p.4-3, §4.2.2.3 p.4-13; DB85 p.593] |
| 取り下げ | BGACK を出さずに BR を外すと、CPU は処理を続ける（雑音への備え） | [D M68 §4.2.2.1 p.4-13] |
| 同期化 | #47 を満たせば 1 クロック以内に同期する。S0 で AS より前に BR が来ると、BG は 2 番目の立上りまで遅れる | [D M68 §4.2.3 p.4-14 図4-17] |
| 状態遷移 | Motorola は、調停の状態遷移をマスク（R9M、T6E、BF4、CC1、DL6 と、GN7 以降）で分けて示す | [D M68 図4-13 p.4-15] |

日立は、1985年のデータブックの付録「THE 68000S MASK SET」で、68000S マスクでの 2 つの修正を書いている [D DB85 p.661–663]。

| 項目 | 68000S より前のマスク | 68000S | 回避条件（前のマスク） |
|---|---|---|---|
| (1) バス調停 | BR を外した状態で BGACK を 1 クロックだけ出し、BGACK↑ の 1 クロック後に BR を出し直すと、BG と AS が同時に出る（図58） | 修正。新たに #37A tBGKBR（BGACK↓ → BR↑）が 20 ns 以上（8 MHz）。BR と BGACK が #47 を満たせば無視してよい。満たさないときは BR を外す前に BGACK を出す（表40） | BR は BGACK↓ の 1 クロック以上後に外す。BGACK を 1 クロックだけにしない。BR の出し直しは BGACK↑ の 2 クロック以上後。または HD68450 を使う（HD68450 は BGACK の 1 クロック後に BR を外すので起こらない） |
| (2) RTE・RTR | 2〜4 番目のバスサイクルでバスエラーが起きると PC が失われる（図59・60） | 修正 | 日立は「68000S より前のすべての HD68000」に当たると書く |

- 1985年に出荷された HD68000-8 がどちらのマスクかは書かれていない [V]。回避条件は 68000S でも満たすので、両方を満たす調停回路にすれば区別は要らない（推定）。
- (2) はスタックの読出しでバスエラーが起きる場合だけで、主 RAM にスタックを置けば通常は起きない（推定）。

### 2.7 リセットと停止

| 項目 | 内容 | 根拠 |
|---|---|---|
| 外部からのリセット | RESET と HALT を同時に 10 クロック以上 Low（#56）。電源投入時は 100 ms 以上 | [D M68 §4.2.5 p.4-20〜4-21; DB85 p.589, p.610] |
| リセット後の動作 | スーパーバイザのプログラム空間の $000000 から SSP、$000004 から PC を読む。S を立て、T を外し、割込みマスクを 7 にする | [D M68 §5.3.1 p.5-6〜5-7] |
| RESET 命令 | CPU が RESET を 124 クロック Low にする。CPU 自体はリセットされない（周辺だけをリセットする） | [D M68 p.4-21; DB85 p.610] |
| 停止の出力 | 二重バスフォルトで止まると HALT を Low にする（RESET・HALT は双方向） | [D M68 p.4-4, p.4-20] |

## 5. 仕様書との照合

| 仕様書の記述 | 判定 | 根拠・修正案 |
|---|---|---|
| §04 HD68000-8「16-bit外部データ、24-bitアドレス、非同期バス、DTACK、バス調停信号」「8 MHz（16 MHz÷2）」 | 一致 | [D DB85 p.585, p.588] |
| §05「リセット時の初期SP/PCはBoot ROMの先頭8 byte」（Boot ROM は 000000） | 一致 | SSP は $0、PC は $4 から読む [D M68 §5.3.1]。ベクタ表（000000–0003FF）も Boot ROM に入るので、割込みと例外の飛び先は ROM で決まる。ソフトで差し替えるなら、ROM のハンドラから RAM の飛び先表へ飛ぶ形にする案 [P]（推定） |
| §05「8-bit ICは上位バイトレーン」 | 一致 | UDS・偶数番地 [D M68 表4-1]。HD6850 は VPA のサイクルで読み書きする（§2.5） |
| §05「未割当・不正幅アクセスは有限時間でバスエラー（初期実装は64 CPUサイクル以内を目標）」 | 一致（補足 3 点） | ①最長の正常なサイクルは、VPA の 19 クロック（計算、§2.5）と ACRTC の待ち（host-acrtc-interface §5・§7.4）で、64 クロックに収まる。②奇数番地のワードアクセスは CPU の中のアドレスエラーで、バスに出ない（§2.2）。グルーが見る「不正幅」は、8-bit IC へのワードアクセス（UDS と LDS が両方 Low）になる（推定）。③IACK サイクル（FC＝111）にも同じタイマーを効かせると、応答のないレベルはスプリアス割込み（ベクタ 24）になる。タイマーが IACK を除くと CPU が止まり続ける（§2.4）。§05 に「IACK も対象」と書く案 [P] |
| §05「ACRTCのAR/STATUS・データポートには、CLR・TASなどの読み書き一体の命令を使わない」（DR-016） | 一致（補足） | TAS は再実行もされない [D M68 p.4-18] |
| §06 Data Fabric（CPU のバスを借りるかは書かれていない） | 未決 [V] | 借りるなら BR・BG・BGACK の 3 線を使う。68000S より前のマスクでも安全な条件（§2.6）：BGACK を 2 クロック以上出す、BR は BGACK↓ の 1 クロック以上後に外す、BR の出し直しは BGACK↑ の 2 クロック以上後。BGACK を出す前に AS・DTACK・BGACK の High を確かめる。決める必要がある |
| §09 INPUT_IRQ_STATUS・ENABLE（IRQ のレベルは書かれていない） | 未決 | IRQ の出し手（ACRTC、ACIA、Data Fabric、DSP bridge、ADPCM bridge、DOC、入力）にレベルを割り当て、IACK の応答（オートベクタか、ベクタ番号か）を決める必要がある。MIDI の受信は 1 バイト 320 µs（31.25 kbit/s、10 ビット）なので、ACIA は 320 µs（2,560 クロック）以内に読む必要がある（計算）。1985年の日立の回路例は 74LS148 で符号化する [D DB85 p.624 図49] |
| §12 エミュレータ | 補足 | リセットの例外のクロック数は DB85 と M68 で違う（34 と 40、§2.8）。オートベクタの割込みは 50〜59 クロックで、E の位相で決まる（§2.4・§2.5）。E を CPU クロックの 1/10 の独立したカウンタとして持つ |
| MC6850.md §3.3「VPAサイクルのクロック数…およそ10〜18クロック程度 [V]」 | 修正 | 10〜19 クロック（1.25〜2.375 µs）（計算、§2.5）。図6-3 の待ち 15 クロックに、待ち以外の 4 クロックを足す |

## 6. 未解決事項

1. 1985年に出荷された HD68000-8 のマスク（68000S か、それより前か）。DB85 の付録は 68000S の修正を説明するが、切り替えの時期は書いていない。
2. リセットの例外処理のクロック数（DB85 は 34、M68 は 40）。実チップで測る。
3. DB85 の信号の説明に「IPL を IACK まで保つ」の文がない理由（省略か）。本台帳は M68 に従う。
4. HD68000-8 の 1985年の価格と国内の流通。
5. Data Fabric が CPU のバスを借りる場合、1 語あたりの調停の所要（BR → BG → BGACK、BGACK↑ → 次の BR）。仕様書で調停の方式を決めてから計算する。
6. MAME・fx68k が、マスクごとの違い（§2.6）と E の位相（§2.5）をどう扱うか。
7. HALT 中に FC が高インピーダンスになるマスク（M68 表4-3 注）と、日立品のマスクの対応。
