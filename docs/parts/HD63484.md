接続上の注意
- ACRTC のホストデータバスは1系統だけ。Fabric の DMA 中に CPU が ACRTC を CS で選ぶことは禁止されている [D U85 p.49]。サイクルスチール転送中は MPU が FIFO に触れてはならない [D U85 p.66]。そのため Fabric ポートアダプタは、転送中の CPU アクセスを待たせるか、有限時間でバスエラーにする必要がある [P]。
- 68000 の UDS/LDS で CS を作ると待ちが増える。遅延 AS で作ると待ちは減る [D AN86 p.134]。
- DACK と CS は同時に L にしない。RS と R/W は DACK を有効にする前に確定させる [D U85 p.50]。

### 3.3 「256×192、4bpp、NTSC、ACRTC 8 MHz」は成立するか

4bpp では1語が4画素。デュアルアクセスかつ GAI＝+1 なら、4×2CLK ごとに4画素なので、ドットクロック＝2CLK になる [D: 計算、U85 p.17, p.73]。単一アクセスで GAI＝+1 にすると、ドットクロックは 2CLK の2倍になる [D: 計算]。2CLK＝8 MHz では、ドットクロックの選択肢は 8 または 16 MHz（GAI を変えれば 4 MHz も可）に限られる。

8 MHz で 256 画素を出すと有効幅は 32 µs で、NTSC の有効走査期間約 52.6 µs の 61% しかない [D: 計算]。仕様書の組み合わせ（§07 l.182, l.201）はそのままでは**横に細い画面**になる。

| 案 | 2CLK | メモリサイクル | ドットクロック | HC（周期） | 水平周波数 | 262ライン時のフレーム | 256画素の幅 | 1フレーム中の描画用メモリサイクル |
|---|---|---|---|---|---|---|---|---|
| A | 8.000000 MHz | 250.0 ns | 8.000 MHz | 254（63.50 µs） | 15.748 kHz | 60.107 Hz | 32.0 µs（52.6 µs の 61%） | 約 49,282（全体の 74%） |
| **B（推奨）** | 5.369318 MHz（21.47727 MHz÷4＝1.5 fsc） | 372.5 ns | 5.369 MHz | 171（63.69 µs、342ドット） | 15.700 kHz | 59.923 Hz | 47.7 µs（91%） | 約 29,108（65%） |
| C | 7.159091 MHz（2 fsc） | 279.4 ns | 7.159 MHz | 228（63.69 µs） | 15.700 kHz | 59.923 Hz | 35.8 µs（68%） | 約 42,994（72%） |

すべて [D: 計算]。条件はデュアル（インタリーブ）アクセス、GAI＝+1、4bpp、RAM＝0、VC＝262、表示 64 語×192 ライン。描画用メモリサイクルは「全メモリサイクル − 表示読出し − リフレッシュ（HSW−1）×262 − 属性出力 262」で見積もった。

- 案B は 1ライン＝228 fsc（色副搬送波の整数倍）で、色信号とドットの位相関係がラインごとに固定される。TMS9918（5.37 MHz、342ドット、262ライン）と同じ組み立て方だが、これは記憶による比較で、本調査では原典を確認していない [V]。
- 案B のピクセル縦横比は約 1.14（横長）、案A は約 0.77 [D: 計算]。
- fsc に同期した 2CLK と整数の HC では、NTSC 規格の 15.734 kHz（227.5 fsc/ライン）は作れない。案B では HC＝170.6 が必要になる [D: 計算]。
- 8 MHz 以外を使う理由：(1) 256画素が画面幅に収まる、(2) 色副搬送波と同期できる、(3) DRAM の速度条件が緩む（§3.6）、(4) -6 品でも動く。欠点は描画速度が 2CLK に比例して 0.67 倍になることで、直線は 0.745 µs/画素になる [D: 計算、H1 表1 の 0.5 µs×8/5.37]。

### 3.6 VRAM（DRAM）の速度条件

| 項目 | 内容 | 根拠 |
|---|---|---|
| 150 ns DRAM、読み書き共通の CAS タイミング | メモリサイクルの半分（＝2CLK の1周期）に 225 ns 必要で、2CLK は約 4.4〜4.5 MHz が上限 | [D AN86 p.84–85]（IC復元用・後年資料） |
| CAS を読み書きで最適化した場合 | さらに速くできるが、具体的な上限値は記載なし | [D AN86 p.85] |
| 日立の設計例 | HD63484-8 を 2CLK 5.03 MHz で使用。HM50464-12×4（128 KB）、デュアルアクセス、4bpp、ドットクロック 20.126 MHz（640×400） | [D AN86 p.130 表1-3]（IC復元用・後年資料） |

案A（8 MHz）では 2CLK の1周期が 125 ns しかなく、1985年の DRAM で組める根拠は見つからない [V]。SRAM（RAM＝1）なら可能性はあるが、128 KiB 分の高速 SRAM は高価になる [V]。案B（186 ns/2CLK）は 120 ns 級 DRAM と CAS の最適化で成り立つ見込みが高い [V]。150 ns 品で成り立つかは未確認。HM50464 が1985年に入手できたかも未確認で、4164（64K×1）×16 も候補になる [V]。

### 4.5 16-bit 語の中の画素の並び

左端の画素は語の LSB 側にある [D U85 p.163–165 図6.14(a)(b)(c)]。4bpp の場合は次のとおり。

| 語のビット | 15–12 | 11–8 | 7–4 | 3–0 |
|---|---|---|---|---|
| 画素（左から） | 3 | 2 | 1 | 0 |

MAME も表示時に `data & mask` で LSB 側から取り出し、`data >>= bpp` で次の画素に進む [D M1 l.2142–2190]。68000（ビッグエンディアン）から見ると、偶数番地のバイトが画素3・2、奇数番地のバイトが画素1・0 になる。上位ニブルを左の画素とする一般的な形式とは逆なので、CPU や DSP で素材を作るときは変換が要る [D: U85 図6.14 からの帰結]。外付けのシフトレジスタも LSB 側から出力する構成にする [P]。

表示ではアドレスが MWR ずつ増えるほど画面の下へ進む [D M1 l.2147]。一方、DWT などの +Y 方向はアドレスが減る方向（画面の上方向）になる [D U85 p.188 DWT 方向図; M1 l.1057]。

### 4.7 Data Fabric から VRAM への連続転送

結論：連続転送には DWT／DRD／DMOD と DREQ・DACK・DONE を使う。Fabric は HD68450 の単一アドレスモード相当の DMAC としてふるまう [P]。RD／WT は1語ごとにコマンド語が要り（WT は FIFO へ2語、8 サイクル）、DWT（約6サイクル/語、FIFO へ1語）より遅い [D: 計算、U85 p.173]。

DWT の手順（データDMA）
1. CCR に DDM＝1 を設定する。DRC＝0（バースト：DREQ はレベルで、1要求あたり最大8語）か DRC＝1（サイクルスチール：1語ごとにパルス）を選ぶ [D U85 p.66–67]。
2. WPR で RWP（Pr0C/Pr0D）に書込み開始の語アドレスと画面番号を設定する [D U85 p.192 図C9-1]。
3. DWT AX, AY を発行する。x＝|AX|+1 語、y＝|AY|+1 行の矩形で、各行の間隔はその画面の MWR になる [D U85 p.187]。AX・AY は負の値も取れる。+Y はアドレスが減る方向なので、画面の上から下へ書くには AY を負にする [D U85 p.188 図; M1 l.1057]。
4. ACRTC が DREQ を出し、Fabric は CS ではなく DACK を L にしてデータを渡す。R/W は反転極性（H＝ACRTC へ書込み）で、DTACK を待つ [D U85 p.49–50]。
5. 終了時に ACRTC が DONE を出力する。データDMA は外部から DONE で終わらせることはできないので、中断するときは CPU が CCR の ABT を使う [D U85 p.50, p.66]。RWP は終端位置に更新される [D U85 p.187]。

- DRD：実行前に読出しFIFO を空にしておく。DDM＝0（プログラム転送）で DRD を使うと、最後の語の後も待ち続けるため、ABT で終わらせる [D U85 p.128]。
- DDM＝0 なら、DWT/DRD/DMOD のデータを CPU が FIFO 経由で直接やり取りできる [D U85 p.128]。
- コマンドDMA（CDM＝1）は、コマンド列を Fabric から流し込む用途に使える。終了は DONE 入力か CDM のクリア [D U85 p.66]。コマンドDMA の中に DMA 転送コマンドを含めてはならない [D U85 p.66]。
- コマンドDMA の方式について U85 は記述が矛盾している。p.28 と p.66 ではサイクルスチール、p.50 では「バーストのみ」と書かれている。p.66 の注記（DRC に関係なくサイクルスチール）を正とみなす [V]。
- 仕様書§06 の「初期は任意stride不可」は、Fabric 側の RAM ポートの制約としては成り立つ。ACRTC 側は MWR 単位の矩形転送がネイティブで、任意の幅の矩形を連続転送できる [D U85 p.187]。

| BCR（r90–r91） | BON1（bit 15–12）、BOFF1（bit 11–8）、BON2（bit 7–4）、BOFF2（bit 3–0）。単位は 4 フィールド。BON＝0 なら BLINK はいつも L、BOFF＝0 なら いつも H | [D U85 p.91–93] |

### (7) 表示と描画のバス

| 事項 | 内容 | 出典 |
|---|---|---|
| ACP（OMR bit 13）＝0 | 表示優先。単一アクセスでは、表示期間は描画を止め、帰線の間に描く。インタリーブでは表示と描画が交互にバスを使い、同時に進む。重ね合せでは、空いたウィンドウのサイクルで背景を描ける | [D U85 p.70] |
| ACP＝1 | 描画優先。表示期間にも描く（表示と描画がぶつかって画面がちらつく） | [D U85 p.70] |
| RAM（OMR bit 7）＝0 | HSYNC の L の間（最後のサイクルを除く）は DRAM のリフレッシュの時間で、描画できない。1 なら描画できる | [D U85 p.70、p.72] |
| 属性の時間 | HSYNC の L の最後のサイクルは、ACP・RAM に関係なく描画に使わない | [D U85 p.70] |
| STR（OMR bit 14）＝0 | 表示と描画を止め、DISP・CUD・VSYNC は H、HSYNC は L、MAD にはリフレッシュの番地を出す。CRT の信号の時間の基準を戻す。1 に戻すと、止めた描画のコマンドを続ける | [D U85 p.70] |

### (8) U85 に書いていないこと [V]

- ラスタの途中で表示のレジスタを書いたとき、いつから効くか。
- SPL の値と画面の対応（上・基本・下の番号をそのまま出すか、ウィンドウのときに何を出すか）。
- ウィンドウの間、背景の表示番地が進むか。
- 横のズームで同じ番地を繰り返すサイクルに、表示の読出しをするか（描画に使えるか。§7 の 9）。
- GCR の CXE・CYE の位置を含むか（両端を含むか）。
- 電源投入時の DCR の値。
