## 0. 要旨

| 問い | 結論 |
|---|---|
| ホストバスのタイミングの根拠 | 1985年5月のユーザーズマニュアル（U85）の AC 特性（p.314–316）とタイミング図（p.318–321）で確認できる。1985年のデータブック（DB85）の HD63484 は 2 頁の概要（ADVANCE INFORMATION）で AC 特性はない。1985年8月のデータシート（HDS8508）は、確認できた転載が初頁だけで AC 特性は未確認 [V] |
| DTACK の出方 | CS↓ を 2CLK の立上り（T1）で認識し、次の立上り（T3）から 70 ns 以内に DTACK↓。つまり認識から 1 周期＋70 ns 以内 [D U85 p.314, p.318–319]。待ちが増えるのは「2CLK が MPU より遅く連続アクセスするとき」と「書込みの直後の読出し」の 2 つだけと書かれている [D U85 p.28] |
| 68000 に入る待ち（AR/STATUS・データポート共通） | CS を S4 の立上りで登録して作り、DTACK を直結すると 2〜4 ウェイト（中央値の条件で 3 が約 7 割）。DTACK に 2 段の同期化を入れると 3〜6（16 MHz と 8 MHz の組合せなら 3〜5）。1 アクセスは 6〜8 クロック（750〜1,000 ns）になる（計算、§5） |
| CS の作り方 | AS に直結すると R/W のセットアップ（50 ns）を満たせない（68000 の R/W は AS↓ の 20 ns 後まで確定しない）。S4 の立上りで登録した CS が最も素直（計算・推定、§4） |
| DTACK の同期化 | 68000 は DTACK を内部で同期化し、ACRTC はデータを DTACK より先に確定させる。日立の 1984年の構成図も DTACK を直結する。CPU へは直結でよい。同期化が要るのは、DTACK を同期式のグルー（バスエラーのタイマーなど）に入れる場合だけ（推定、§6） |
| Data Fabric（16 MHz 系）との DREQ・DACK・DONE | 2CLK 系から入る DREQ・DTACK に 2 段の FF、DONE に 1 段の FF（DTACK で取り込む）が要る。DACK・R/W・データは ACRTC がセットアップ付きで受けるので、Fabric 側の順序を守れば同期化は不要。1 語のハンドシェイクは 438〜750 ns で、DWT の内部速度（約 1.12 µs/語）より速い（計算、§7） |
| 回路の規模 | TTL で約 8〜11 個（FF 約 8 個、PAL 1〜2 個、バッファ 4〜5 個）。ゲート換算で約 150〜250。review-digital §4.1 の「共通部 600〜1,000 ゲート」に収まる見込み（推定、§7.6） |

| 項目 | 値 | 根拠 |

| CPU | HD68000-8、16 MHz÷2＝8 MHz、周期 125 ns | 仕様書 §04・§07（DR-003、DR-008） |
| ACRTC | HD63484-8、2CLK＝21.47727 MHz÷4＝5.369318 MHz、周期 186.24 ns | 仕様書 §04・§07（DR-003、DR-004） |

日立の 1984年の構成図でも、2CLK は映像側の CPG（クロック発生回路）から ACRTC とビデオ制御回路に配られ、ACRTC は DTACK で HD68000 に、DREQ・DACK・DONE で HD68450 DMAC につながる [D H1 図1]。1985年のデータブックの構成図も 68000・HD68450・ACRTC を同じシステムバスに置く [D DB85 p.713]。ホストと 2CLK を別のクロックにするのは、日立が想定した使い方である（推定）。

## 2. HD63484 のホストバスのタイミング

### 2.1 MPU サイクル（-8 品）

AC 特性 [D U85 p.314] と図 T-2・T-3 [D U85 p.318–319] による。図の T0〜Tn は 2CLK の半周期ごとの状態で、T1 は 2CLK の立上り、T2 は立下り、T3 は次の立上りで始まる（図からの読み取り）。

| 項目 | 記号 | -8 の値 | 何から何まで | 根拠 |
|---|---|---|---|---|
| R/W セットアップ | tRWS | 50 ns 以上 | R/W 確定 → CS↓ | [D U85 p.314 No.6; p.318–319] |
| R/W ホールド | tRWH | 0 ns 以上 | CS↑ → R/W 変化 | [D U85 p.314 No.7] |
| RS セットアップ | tRSS | 50 ns 以上 | RS 確定 → CS↓ | [D U85 p.314 No.8] |
| RS ホールド | tRSH | 0 ns 以上 | CS↑ → RS 変化 | [D U85 p.314 No.9] |
| CS セットアップ | tCSS | 40 ns 以上 | CS↓ → T1 の立上り。CS↑ → Tn の立上り | [D U85 p.314 No.10; p.318 図T-2] |
| CS の High 幅 | tCSH | 60 ns 以上 | CS↑ → 次の CS↓（表の名称は「CS Hold Time」） | [D U85 p.314 No.11; p.318 図T-2] |
| 最小サイクル | n＝5 以上 | CS↓ を T1 で認識し、CS↑ を T5 以降の立上りで認識する | [D U85 p.318–319] |
| 読出しデータの確定 | tRDAC | 80 ns 以下 | T2 の始まり（2CLK の立下り）→ データ確定 | [D U85 p.314 No.14; p.318] |
| 読出しデータの保持 | tRDH | 10 ns 以上 | CS↑ → データ変化 | [D U85 p.314 No.15] |
| 読出しデータのオフ | tRDZ | 60 ns 以下 | CS↑ → 高インピーダンス | [D U85 p.314 No.16] |
| DTACK↓ の遅れ | tDTKZL | 70 ns 以下 | T3 の始まり（2CLK の立上り）→ DTACK↓ | [D U85 p.314 No.17; p.318–319] |
| データ確定 → DTACK↓ | tDTKDL | 0 ns 以上 | 読出しではデータが DTACK より先に確定する | [D U85 p.314 No.18] |
| DTACK↑ | tDTKLH | 60 ns 以下 | CS↑ → DTACK を High に引き上げる | [D U85 p.314 No.19] |
| DTACK のオフ | tDTKZ | 100 ns 以下 | CS↑ → 高インピーダンス | [D U85 p.314 No.20] |
| 書込みデータのセットアップ | tWDS | 40 ns 以上 | データ確定 → CS↑（データは CS の立上りで取り込む） | [D U85 p.314 No.23; p.319 図T-3; p.49] |
| 書込みデータの保持 | tWDH | 10 ns 以上 | CS↑ → データ変化 | [D U85 p.314 No.24] |

- DTACK はオープンドレインで、HD68000 と HD68450 の非同期バスにそのまま合う [D U85 p.49]。
- 「DTACK は 1〜1.5 2CLK で返る」[D U85 p.28] は、図では「CS を認識した立上り（T1）から 1 周期＋70 ns 以内」（186〜256 ns）にあたる（計算）。CS↓ から測ると、CS のセットアップ待ち（40〜226 ns）が加わり 226〜482 ns になる（計算）。
- 読出しと書込みで DTACK の時刻は同じ。AR・SR・FIFO（データポート）のどれにアクセスしても同じ図による。レジスタの種類による違いは U85 に書かれていない [D U85 p.28, p.318–319]。
- 待ちが増える条件 [D U85 p.28]：
  - (a) 2CLK が MPU のクロックよりかなり遅く、ACRTC へのアクセスが連続するとき（前のサイクルの内部処理で遅れる）。増える量は書かれていない [V]。
  - (b) 書込みの直後に読出しが来るとき（バスの向きを変える準備）。U85 は「通常の MPU には書込みの直後に読出しをする命令はない」とする。
- 同期式バスの MPU では DTACK を開放してよいが、待ちが起こりうるなら DTACK から READY を作る [D U85 p.28]。

### 2.2 FIFO（データポート）の扱い

| 項目 | 内容 | 根拠 |
|---|---|---|
| FIFO の状態 | SR の WFR（書込み FIFO に空きあり）、WFE（空）、RFR（読出し FIFO にデータあり）、RFF（満杯）。読み書きとも 8 語 | [D U85 p.61–62] |
| 満杯・空のときのアクセス | U85 は SR の確認でアクセスしてよいかを判断する書き方で、満杯の FIFO への書込みで DTACK を遅らせるとは書いていない。そのときの動作は未確認 [V] | [D U85 p.62] |
| DMA 中の禁止事項 | DACK が L の間に CS を L にしてはならない。サイクルスチール転送中は MPU が FIFO に触れてはならない | [D U85 p.49, p.50, p.66] |

### 2.3 DMA サイクル（-8 品）

AC 特性 [D U85 p.314–315] と図 T-4（ACRTC → メモリ）・T-5（メモリ → ACRTC）[D U85 p.320–321] による。DACK は MPU サイクルの CS に当たり、同じ T 状態で進む。

| 項目 | 記号 | -8 の値 | 何から何まで | 根拠 |
|---|---|---|---|---|

| DMA の R/W セットアップ | tDRWS | 50 ns 以上 | R/W 確定 → DACK↓。R/W の極性は反転し、H で ACRTC への書込み | [D U85 p.314 No.27; p.50] |
| DMA の R/W ホールド | tDRWH | 0 ns 以上 | DACK↑ → R/W 変化 | [D U85 p.314 No.28] |
| DACK セットアップ | tDAKS | 40 ns 以上 | DACK↓ → T1 の立上り。DACK↑ → Tn の立上り | [D U85 p.314 No.29; p.320] |
| DACK の High 幅 | tDAKH | 60 ns 以上 | DACK↑ → 次の DACK↓ | [D U85 p.314 No.30; p.320] |

| DMA 書込みデータ | tDWDS／tDWDH | 40 ns 以上／10 ns 以上 | データ確定 → DACK↑／DACK↑ → データ変化 | [D U85 p.315 No.45–46; p.321] |

## 3. 68000 側の条件（8 MHz 品）

Motorola の 1983年4月版 [D M68 §8.6 p.8-4〜8-5] と、日立の 1985年のデータブックの HD68000 [D DB85 p.588] は同じ値。

| 項目 | 記号 | 8 MHz の値 | 根拠 |
|---|---|---|---|
| クロック立上り → AS・DS↓ | tCHSL | 0〜60 ns | [D M68 p.8-4 No.9–10; DB85 p.588] |
| アドレス確定 → AS↓ | tAVSL | 30 ns 以上 | [D M68 p.8-4 No.11] |
| クロック立上り → R/W↓ | tCHRL | 70 ns 以下 | [D M68 p.8-4 No.20] |
| AS↓ → R/W 確定 | tASRV | 20 ns 以下 | [D M68 p.8-4 No.20A; DB85 p.588] |
| クロック立下り → AS・DS↑ | tCLSH | 70 ns 以下 | [D M68 p.8-4 No.12] |
| AS・DS の High 幅 | tSH | 150 ns 以上 | [D M68 p.8-4 No.15] |
| DS↑ → 書込みデータ無効 | tSHDO | 30 ns 以上 | [D M68 p.8-4 No.25; DB85 p.588] |
| 読出しデータのセットアップ | tDICL | 15 ns 以上 | [D M68 p.8-4 No.27] |
| AS・DS↑ → DTACK↑ | tSHDAH | 0〜245 ns | [D M68 p.8-4 No.28] |
| DTACK↓ → データ確定（非同期時） | tDALDI | 90 ns 以下 | [D M68 p.8-4 No.31] |
| 非同期入力のセットアップ | tASI | 20 ns 以上 | [D M68 p.8-5 No.47] |

動作 [D M68 p.4-9 図4-8、p.4-23 §4.4.2、p.6-2]：
- 読出しでは AS と UDS・LDS が S2 で出る。書込みでは R/W が S2 で L になり、データが S3 で出て、UDS・LDS は S4 で出る。
- DTACK は S4 の終わりのクロック立下りで見る。tASI を満たせばその立下りで認識され、次の立下りでデータを取り込む。認識されなければ 1 クロック（125 ns）ずつ待ちが入る。
- tASI を満たさない入力も、認識される可能性はある（認識されないとは保証されない）。
- 非同期入力は内部で 1 クロック以内に同期化される [D M68 p.4-14 §4.2.3]。

## 4. CS の作り方（計算・推定）

| 作り方 | R/W セットアップ（50 ns 要） | RS セットアップ（50 ns 要） | 書込みデータの保持（10 ns 要） | 判定 |
|---|---|---|---|---|
| A. AS とアドレスのデコードで作る | R/W は AS↓ の 20 ns 後まで確定しない。CS↓ を AS↓ から 70 ns 以上遅らせないと満たせない（計算） | アドレスは AS↓ の 30 ns 前に確定。デコードに 20 ns 以上の遅れが要る（計算） | CS↑ が DS↑ から 20 ns 以内なら満たす（計算） | 不適（遅延素子を足せば可） |
| B. UDS・LDS とデコードで作る | 書込みでは UDS・LDS が S4 で出るので満たす（R/W↓ → DS↓ は 80 ns 以上 [D M68 p.8-4 No.22]） | 読出しでは UDS・LDS が AS と同時なので、A と同じく 20 ns 以上の遅れが要る（計算） | A と同じ | 書込みは可、読出しは条件付き |
| C. S4 の立上りで CS を登録し、AS↑ で落とす | R/W は S2 の立上りから 70 ns 以内に確定。CS↓ は S4 の立上り（その 125 ns 後）＋FF の遅れなので、55 ns 以上の余裕（計算） | アドレスは S1 の立下りから 70 ns 以内に確定。余裕 117 ns 以上（計算） | CS↑ を AS↑ から 20 ns 以内に落とせば満たす（計算） | 推奨（推定） |

- C は CPU と同じ 16 MHz 系の同期回路なので、Data Fabric との調停（DACK が L の間は CS を出さない）も同じ回路で作れる（推定）。
- 日立の後年の応用ノートは「UDS・LDS を使わず遅らせた AS で CS を作ると待ちが減る」と書く [D AN86 p.134]（後年）。C はこの「遅らせた AS」の一つの形（推定）。
- 書込みデータの保持：ACRTC は CS↑ でデータを取り込み、10 ns の保持を要る。68000 のデータは DS↑ の 30 ns 後まで保証される。CS↑ が DS↑ より 20 ns を超えて遅れると足りない（計算）。PAL（A 品で 25 ns [D MMIPAL83 p.3-12]（review-digital））を CS↑ の経路に入れる場合は、データバッファで保持を延ばすか、CS を FF のクリアで直接落とす（推定）。

## 5. 68000 に入る待ちサイクル数（計算）

### 5.1 計算の条件

- 68000 の S0 の立上りを 0 ns とする。DTACK を見る立下りは 312.5＋125k ns（k＝待ちの数）。
- ACRTC は CS↓ の後、40 ns のセットアップを満たす最初の 2CLK の立上りで認識し（T1）、次の立上りから 0〜70 ns で DTACK↓ を出す [D U85 p.314, p.318]。
- 68000 は DTACK↓ から 20 ns 後以降の最初の立下りで認識する [D M68 p.8-5 No.47]。
- 2CLK と CPU クロックの位相は 0〜1 周期の一様分布とし、3,000 点で調べた。
- 最小は、遅れを最小（tCHSL 0 ns、デコード 10 ns、FF 5 ns、tDTKZL 0 ns）とし、セットアップを満たさない入力も認識される場合。最大は、遅れを最大（tCHSL 60 ns、デコード 30 ns、FF 40 ns、tDTKZL 70 ns）とし、セットアップを満たして初めて認識される場合。中央値の条件は各遅れの中央値（tDTKZL 35 ns）。
- デコード・FF の遅れは 74LS 級を仮定した値（推定）。
- 2 段の同期化：「8 MHz」は CPU クロックの立上りで 2 段。「16 MHz＋8 MHz」は 1 段目を 16 MHz、2 段目を CPU クロックの立上り。FF のセットアップ 20 ns、遅れ 25 ns と仮定。
- 待ちが増える条件 (a)(b)（§2.1）は含まない。

### 5.2 結果

| CS の作り方 | DTACK | 待ち（最小〜最大） | 中央値の条件での分布 | 平均 |
|---|---|---|---|---|
| C. S4 で登録（推奨） | 直結 | 2〜4 | 2：5%、3：67%、4：28% | 3.2 |
| C. S4 で登録 | 2 段（8 MHz） | 3〜6 | 4：38%、5：62% | 4.6 |
| C. S4 で登録 | 2 段（16 MHz＋8 MHz） | 3〜5 | 3：5%、4：67%、5：28% | 4.2 |
| B. UDS・LDS（書込み） | 直結 | 2〜5 | 3：57%、4：43% | 3.4 |
| B. UDS・LDS（書込み） | 2 段（8 MHz） | 3〜6 | 4：24%、5：67%、6：9% | 4.9 |
| A. AS 直結（参考。§4 で不適） | 直結 | 1〜4 | 2：57%、3：43% | 2.4 |

すべて計算。

- 推奨の構成（C・直結）で、ACRTC への 1 アクセスは 6〜8 クロック（750〜1,000 ns）。通常のメモリアクセス（4 クロック）より 2〜4 クロック長い（計算）。
- 待ちの数は 2CLK と CPU クロックの位相で決まり、アクセスごとに変わる。2 つの水晶が独立なので、実機では再現性がない（推定）。
- 2 段の同期化は、平均で約 1 ウェイト増える（計算）。

### 5.3 後年の資料との比較

日立の 1986年の応用ノートは「MPU の CLK と 2CLK が同じ周波数なら、通常 3〜4 ウェイト」と書く [D AN86 p.132]（後年）。同じ条件（どちらも 8 MHz）を本書の方法で計算すると、B（UDS・LDS）で 1〜4、中央値の条件で 2〜3 になる（計算）。AN86 の値は本書の計算の上側に一致する。AN86 は CS の作り方とデコードの遅れを書いていない [V]。

### 5.4 ソフトウェアから見た量（計算）

- CPU が FIFO に 1 語ずつ書く場合（DDM＝0）：`MOVE.W (A0)+,(A1)` は 12 クロック [D M68 p.7-5 表7-4]。待ち 3 を足して 15 クロック（1.875 µs）。展開したループで約 1.07 MB/s。DBRA のループでは約 0.64 MB/s（DBRA 10 クロックを足す）。WFR の確認は含まない。
- DMA の DWT は ACRTC 側で約 6 サイクル/語（1.12 µs/語、1.79 MB/s）[HD63484.md §3.8]。CPU で書くより速い。

### 5.5 注意（推定）

- `MOVE.L` で AR（+0）と DATA（+2）を続けて書くと、ACRTC へのアクセスが AS の High 150 ns を挟んで連続する。U85 の条件 (a) に当たる可能性がある [V]。実チップで確かめる。
- 68000 の CLR はメモリのオペランドを書く前に読む。表7-8 の CLR（メモリ）は 8(1/1) に実効アドレスの計算時間を足す形で、表7-3 の実効アドレスの計算時間はオペランドの読出しを含む [D M68 §7.2 表7-3・表7-8]。データポートに CLR を使うと読出し FIFO を 1 語消費する。TAS は AS を下げたまま読みと書きを続けるので、ACRTC の 1 サイクルの形に合わない [D M68 p.4-10 §4.2.1.3]（合わないことは推定）。どちらも ACRTC には使わない。

## 6. DTACK の同期化

| 観点 | 内容 | 根拠 |
|---|---|---|
| 直結できるか | できる。68000 は非同期入力を内部で同期化する。ACRTC は読出しデータを DTACK より先に確定させる（tDTKDL ≥ 0）ので、68000 の tDALDI（90 ns）も満たす。日立の 1984年の構成図も DTACK を直結する。後年の応用ノートも「クロックの差は待ちで吸収されるので、ACRTC は HD68000 と同期する必要がない」とする | [D M68 p.4-14 §4.2.3, p.8-4 No.31; U85 p.314 No.18, p.49; H1 図1; AN86 p.132]（AN86 は後年） |
| 同期化が要る場合 | DTACK を同期式のグルー（バスエラーのタイマー、ポートアダプタの順序回路）でも使う場合。その回路への入力だけを 2 段の FF で同期化する | 推定 |
| 同期化のコスト | 平均で約 1 ウェイト増える（§5.2） | 計算 |
| バスエラーのタイマー | 日立は、BERR の回路を決めるときに 68000 の CLK と 2CLK の位相差を考えるよう注意している | [D AN86 p.133 注1]（後年） |

推奨（推定）：CPU の DTACK は直結（ワイヤード OR）。グルーが DTACK を見る必要があるときは、写しだけを同期化する。仕様書 §05 のバスエラー（64 CPU サイクル以内）は、通常の待ち（2〜4）に対して十分長い。

## 7. Data Fabric（16 MHz 系）との DREQ・DACK・DONE

### 7.1 信号と同期化の要否

| 信号 | 向き | 同期化 | 理由 |
|---|---|---|---|
| DREQ | ACRTC → Fabric | 要る（2 段 FF） | 2CLK の立下り・立上りから出る [D U85 p.320–321]。Fabric の順序回路の入力 |
| DTACK（DMA の READY） | ACRTC → Fabric | 要る（2 段 FF） | T3 から出る [D U85 p.315 No.36]。Fabric はこれで DACK を上げる |
| DONE（データ DMA の出力） | ACRTC → Fabric | 1 段の FF で足りる（推定） | DONE↓ は最後の語の T1 から 50 ns 以内で、DACK↑ まで変わらない [D U85 p.315 No.40–41]。同期化した DTACK を見た時点では、DONE は 136 ns 以上前に確定している（計算）。DTACK を合図に 1 段で取り込める |
| DACK | Fabric → ACRTC | 不要 | ACRTC がセットアップ（40 ns）付きで 2CLK の立上りで見る。CS と同じ扱い [D U85 p.314 No.29] |
| R/W（DMA） | Fabric → ACRTC | 不要 | DACK↓ の 50 ns 前に確定させる [D U85 p.314 No.27]。16 MHz の 1 状態（62.5 ns）前に出せば足りる（計算） |
| データ | 双方向 | 不要 | 書込みは DACK↑ の 40 ns 前から 10 ns 後まで保つ [D U85 p.315 No.45–46]。読出しは DTACK を同期化した後に取り込めば確定している（推定） |
| DONE（コマンド DMA の入力） | Fabric → ACRTC | 不要 | DACK が L の間に 2CLK 2 周期（372 ns、16 MHz で 6 状態）以上入れる [D U85 p.315 No.43] |
| IRQ | ACRTC → 割込み回路 | 不要（推定） | 68000 の IPL は内部で同期化される [D M68 p.4-14 §4.2.3] |

CPU と Fabric は同じ 16 MHz から作る（DR-003）。CPU の ACRTC アクセスと Fabric の DMA の調停は同期回路で組め、非同期の境界は ACRTC のピンだけになる（推定）。

### 7.2 1 語のハンドシェイク（計算）

条件：Fabric の出力は 16 MHz の立上り＋20 ns で変わる。DTACK を 2 段の FF（16 MHz、セットアップ 10 ns）で同期化し、その次の状態で DACK↑。DACK は 1 状態（62.5 ns ≥ tDAKH 60 ns）High にしてから次の DACK↓。

| 項目 | 値 |
|---|---|
| DACK↓ から次の DACK↓ まで | 438〜750 ns |
| DACK の L の幅 | 375〜688 ns |
| ハンドシェイクだけで決まる上限 | 1.33〜2.29 M語/s（2.7〜4.6 MB/s） |
| DWT の ACRTC 内部の速度 | 約 6 サイクル/語＝1,117 ns/語（1.79 MB/s）[HD63484.md §3.8] |
| 8 語のバースト | 3.5〜6.0 µs（68000 の 28〜48 クロック）。ハンドシェイクだけの値 |

ハンドシェイクと同期化の遅れは、DWT の速度を制限しない（計算）。

### 7.3 DREQ の取りこぼしと二重応答（計算）

サイクルスチールでは、ACRTC は T1 の立上りから 50 ns で DREQ を上げる [D U85 p.320–321]。Fabric は 2 段の同期化の後、遅くとも T1＋約 185 ns（50＋セットアップ 10＋2 状態 125）で DREQ↑ を見る。一方、次の DACK↓ を出せるのは、DTACK（T3＝T1＋186 ns 以降）を同期化して DACK を上げ、1 状態待った後で、早くても T1＋約 330 ns。Fabric は DREQ↑ を見てから次を判断できる。バーストの最後の語の DREQ↑ の時刻は U85 の図にない [V]。サイクルスチールと同じなら同じく安全。

### 7.4 DMA 中の CPU アクセス（計算・推定）

- DACK が L の間は CS を出せない。サイクルスチール中は FIFO に触れない [D U85 p.49, p.66]。SR・AR へのアクセスは DACK が High の間なら禁止されていない [D U85 p.49]。
- 語ごとに CPU を優先させれば、CPU の待ちは 1 語のハンドシェイク（最大 750 ns＝6 クロック）＋通常の待ち（2〜4）で、最大 10 クロック程度（計算）。
- バースト（最大 8 語）の間 CPU を待たせると、28〜48 クロックが加わる（計算）。仕様書 §05 のバスエラー（64 クロック）には収まるが、余裕は小さい。
- 推奨（推定）：Fabric は語ごとに CPU を優先させる。サイクルスチール中の FIFO へのアクセスはポートアダプタがバスエラーにする。

### 7.5 本機の構成との関係

ACRTC のホストデータバスは 1 本だけなので、CPU 側と Fabric 側を切り替えるポートアダプタを置く [HD63484.md §2]。日立の構成（H1 図1）では DMAC が 68000 のバスを借りる。本機の Fabric は、各 IC のメモリバスを直結せず、DMA の異常をホスト全体の停止に波及させない（仕様書 §06）。Fabric が 68000 のバスを借りるかどうかは仕様書に書かれていない [V]。ACRTC のデータバスを CPU のバスから分けて Fabric 側と切り替える構成なら、DMA 中も CPU は ACRTC 以外にアクセスできる（推定）。§7.6 の部品数はこの構成を仮定した。

### 7.6 回路の規模（推定）

| 機能 | 部品の目安 | 個数 |
|---|---|---|
| CS の登録（§4 の C） | 74LS74 の半分＋ゲート | 0.5〜1 |
| DREQ・DTACK の 2 段 FF、DONE の取り込み（FF 5 個） | 74LS175（4 FF）×2、または 74LS74 ×3 | 2〜3 |
| ポートアダプタの順序回路（DACK、R/W の切替、CPU と Fabric の調停） | PAL16R4／16R6 級 | 1〜2 |
| R/W・CS の切替 | 74LS157 または 74LS125 | 1 |
| データバスの切替（CPU 側と Fabric 側） | 74LS245 ×2（CPU 側）、74LS245 または 74LS374 ×2（Fabric 側） | 4 |
| 合計 | | 約 8〜11 |

- ゲート換算（2 入力 NAND、D-FF 1 個 6〜8 ゲート、review-digital §4.1 と同じ置き方）で、FF 約 8 個で 50〜65、順序回路と切替で 100〜180、計 150〜250 程度（推定）。
- review-digital §4.1 の「共通部（ホスト I/F、調停、トリガー同期、バス切替ほか）600〜1,000 ゲート」の内訳に入る規模（推定）。ゲートアレイ化しても FF と少数のゲートで済む。
- 74LS74 の遅れ（CLK → Q）を 25〜40 ns とすると、16 MHz（62.5 ns）の 2 段同期化は成り立つが、余裕は小さい。速い経路には 74S74 を使う案がある [O]（推定）。
