### 2.1 外部プログラムRAMと 68000 からのロード回路 [P]

前提となる事実：
- DSP 本体にバス解放（HOLD）や WAIT/READY のピンはない。T1 は「このプロセッサは wait 状態に入れない」と明記している [D T1 6-3]。
- CLKIN の周期は最大 150 ns（周波数で 6.67 MHz 以上）が条件なので、クロックを止めて待たせることもできない [D T2 A-14]。
- RS を Low にすると、DEN・WE・MEN は High に固定され、D15–D0 は Hi-Z になる。PC と A11–A0 は次の完全なクロック 1 周期の後に 0 へクリアされるが、**Hi-Z にはならない** [D T1 2-19, 2-23; T2 A-22 注7]。
- T1 は外部プログラムRAMの初期化方法として、二つを挙げている：DSP 自身がブートROMから読み込む方法と、独立したコントローラからデュアルポートで書く方法 [D T1 5-18]。

回路案：
1. DSP bridge（0x220000–）に CTRL.RESET を置く。1 のとき RS を Low にする。RS は CLKOUT に同期して出す。
2. CLKOUT で 8 サイクル以上数えたら、STATUS.PRGBUS を 1 にする。根拠は tw(R) が 5 サイクル以上必要なことと、td11 ≤ tc/2+50 ns、tdis(R) ≤ tc/4+50 ns [D T2 A-22]。8 という値は [P]。
3. PRGBUS が 1 の間：DSP の A11–A0 側バッファを切り、68000 の A12–A1 を RAM の A11–A0 へ通す。68000 のデータバスは 74xx245 相当で RAM とつなぐ。/OE と /WE は 68000 の R/W と UDS/LDS から作り、バイトレーンごとに書き込めるようにする。
4. PRGBUS が 0 のときに 0x280000–0x281FFF へアクセスすると、DTACK を返さずバスエラーにする。仕様書 §05 の「64 CPU サイクル以内」の規則に合わせる。
5. RESET を解除すると、RS が上がってから 1 クロック周期後に 0 番地から実行を始める [D T2 A-22 注9]。立ち上がりのタイミングにより、実行開始は 1 サイクル前後ずれうる [D T2 A-22 注10]。
6. 注意：T2 A-22 注12 に「書き込みサイクル中の RS は不正な書き込み番地を生むことがある」とある。そのため RAM の /WE を RESET でマスクし、RS の立下りは CLKOUT に同期させる [D T2 A-22 注12] / 対策は [P]。

- ロード所要時間：68000 の MOVE.W (An)+,(An)+ を 4096 回繰り返すと約 6 ms [V]（12 クロック/語として試算）。
- [O] DSP を止めずに差し替える方法：DSP 側の常駐ローダが「IN で受け取り、TBLW で書く」を繰り返す。1 語あたり約 9〜10 サイクルとして試算すると、4K 語で約 8 ms [V]。ただし TBLW では 0–7 番地を書けない（§2.2）。
- [O] TMS320M10 にマスクROMのローダを入れる方法：その場合、外部RAMとして使えるのは 1536–4095 番地の 2560 語に減る [D T1 2-11]。

### 2.2 I/O ポート割当案（仕様書 §07 のアダプタ）[P]

| 方向 | PA | 内容 |
|---|---|---|
| IN | 0 | 入力 FIFO から POP（Data Fabric port 3 → DSP）。16 bit |
| IN | 2 | 状態：入力 FIFO の語数・空フラグ、出力 FIFO の満杯フラグ、コマンド到着、アンダーラン／オーバーランの記録 |
| IN | 3 | メールボックス（68000 → DSP のコマンド引数） |
| OUT | 1 | 出力 FIFO へ PUSH（DSP → Data Fabric port 4）。16 bit |
| OUT | 2 | コマンド／応答（DSP → 68000 のメールボックス、68000 への IRQ 要求、エラーフラグのクリア） |
| BIO | — | 入力 FIFO が空でない（同期 FF 経由） |
| INT | — | 68000 からの呼び出し（コマンド到着） |

- IN と OUT は別のストローブ（DEN と WE）で区別されるので、同じ番号の入力ポートと出力ポートは別の回路にできる [D T1 2-16]。
- **OUT と TBLW は外部信号では区別できない**。デコードしなければ、OUT がプログラムRAMの 0–7 番地を上書きし、TBLW が周辺に書き込む。デコードしても、TBLW で 0–7 番地だけを書くことはできない [D T1 2-18; T1 3-67 注]。0 番地と 2 番地はリセットと割込みのベクタなので [D T1 2-11]、プログラムRAMの /WE を必ず「A11–A3≠0」でゲートする [P]。
- DSP は待てないので、空の FIFO を IN で読むと、決めた値（例：直前の値または 0x0000）を返し、アンダーランフラグを立てる。満杯の FIFO への OUT はデータを捨て、オーバーランフラグを立てる。どちらも状態ポートと 68000 側に見せる [P]。DSP のソフトは BIO または状態ポートを確認してから IN/OUT する。T1 の FIFO インタフェース例も BIO を使っている [D T1 6-2, 6-3; T3 4-2]。

## 3. タイミング

以下、tc = tc(C) は CLKOUT の周期で、20.000 MHz のとき 200 ns。各サイクルは CLKOUT の立下りから始まる [D T2 A-16〜A-21 の図]。

### 3.1 クロック [D T2 A-13, A-14]

| 項目 | TMS32010 | TMS32010-25 |
|---|---|---|
| 水晶周波数 | 6.7–20.5 MHz | 6.7–25.0 MHz |
| tc(MC)（CLKIN 周期） | 48.78–150 ns | 40–150 ns |
| tc(C)（CLKOUT 周期）最小 | 195.12 ns | 160 ns |
| td(MCC)（CLKIN↑ から CLKOUT↓） | 25–60 ns（特性値、未試験） | 25–60 ns |

- CLKIN と CLKOUT の間の遅延は「規定しない。最大 1 サイクル変わり、温度依存が大きい」とされ、これに依存する設計は避けるよう書かれている [D T1 2-20]。
- 本機では DSP を独立したクロック領域とし、他の領域とは CLKOUT 基準の同期回路でつなぐ [P]。

### 3.2 外部メモリ・周辺インタフェース（1985-10 版データシート）[D T2 A-16]

| 記号 | 内容 | 最小 | 最大 |
|---|---|---|---|
| td1 | CLKOUT↓ からアドレス確定 | 10 ns† | 50 ns |
| td2 / td4 | CLKOUT↓ から MEN↓ / DEN↓ | tc/4−5† | tc/4+15 |
| td3 / td5 | CLKOUT↓ から MEN↑ / DEN↑ | −10† | 15 |
| td6 / td7 | CLKOUT↓ から WE↓ / WE↑ | tc/2−5† / −10† | tc/2+15 / 15 |
| td8 | CLKOUT↓ から出力データ確定 | — | tc/4+65 |
| td9 / td10 | データバスの駆動開始 / 駆動終了 | tc/4−5† / — | — / tc/4+30† |
| tv | CLKOUT↓ 後の出力データ保持 | tc/4−10 | — |
| tsu(D) | CLKOUT↓ 前のデータセットアップ（要求） | 50 | — |
| tsu(A-MD) | MEN↓ / DEN↓ 前のアドレスセットアップ（要求） | tc/4−45 | — |
| th(D) | CLKOUT↓ 後のデータホールド（要求） | 0 | — |

†：特性値で、試験はしていない。アドレスは WE↑・DEN↑・MEN↑ の時点で確定している（注4）。データは MEN↑・DEN↑ で取り去ってよい（注5）。

**外部プログラムメモリに必要なアクセス時間** [D: 計算]：
- アドレスからデータまで：tc − td1(max) − tsu(D) = 200 − 50 − 50 = **100 ns**（20.000 MHz）。20.5 MHz では 95.1 ns、-25 品では 60 ns。
  - T1 本文の「100 ns 未満のアクセス時間が必要」と一致する [D T1 2-12, 5-18]。
  - 1987 年資料も同じ式 td1 + ta(A) + tsu(D) = tc(C) を示している [D T4 6-2] 後年資料。
- MEN↓ からデータまで（/OE 系）：200 − (50+15) − 50 = **85 ns**（20.000 MHz）、81.3 ns（20.5 MHz）。
- アドレス経路に §2.1 の分離バッファが入るので、その遅延を差し引く。遅延を約 10–20 ns と仮定すると [V]、**アドレスアクセス 80 ns 級の SRAM** が目安になる [V]。
- 1983 年の T1 の例は、データ拡張用に IMS1420（16K×1、70 ns SRAM）、プログラム用に TBP28S166 を使っている [D T1 6-3 図6-3]。4K×16 を組むのに適した 1985 年の SRAM の型番・価格・個数は未確認 [V]。
- バス衝突の目安 [D: 計算]：
  - OUT・TBLW でデータバスを駆動し始めるのは CLKOUT↓ から 45 ns 以降、その前のフェッチの MEN↑ は最大 15 ns。よって RAM の出力オフ時間は 30 ns 以下が必要。
  - OUT の後、DSP がバスを離すのは最大 80 ns、次のフェッチの MEN↓ は最小 45 ns。この重なりの扱いは実回路で確認する [V]。

### 3.3 IN / OUT（各 2 サイクル）[D T1 2-16, 2-17, 3-30, 3-47; T2 A-20, A-21]

| 命令 | サイクル1（実行 1 サイクル目） | サイクル2 |
|---|---|---|
| IN dma,PA | A2–A0＝PA、A11–A3＝0。MEN は High、DEN は Low。サイクル末の CLKOUT↓ でデータを取り込む | MEN Low（次命令のプリフェッチ） |
| OUT dma,PA | A2–A0＝PA、A11–A3＝0。MEN は High、WE は Low、データを出力 | MEN Low（次命令のプリフェッチ） |

- 周辺に必要な応答時間 [D: 計算, 20.000 MHz]：
  - IN：DEN↓ から 85 ns 以内、PA 確定から 100 ns 以内にデータを出す。ホールドは 0 ns。DEN↑ の後、次の MEN↓（最小 45 ns）までにバスを離す。
  - OUT：WE の Low 期間は最小約 75 ns。WE↑ までのデータセットアップは 75 ns 以上、WE↑ 後のデータ保持は 25 ns 以上。
- 1 語の転送は 2 サイクル（400 ns）なので、最大で毎秒 250 万語。T1 の「40 Mbit/s」と整合する [D T1 1-2] / [D: 計算]。
- T2 の図では、DEN と WE は「IN／OUT 命令のプリフェッチ」サイクルの次のサイクルに出る [D T2 A-20, A-21]。T1 6-1 の「ポート番号は命令の 2 サイクル目に出る」はプリフェッチを 1 番目と数えた表現で、矛盾しない [V]。

### 3.4 TBLR / TBLW（各 3 サイクル）[D T1 2-17, 3-64, 3-66; T2 A-18, A-19]

| サイクル | TBLR | TBLW |
|---|---|---|
| 1 | MEN Low。PC+1 をダミーでフェッチし、結果は捨てる。PC をスタックに積み、ACC の下位 12 bit を PC に入れる | 左と同じ |
| 2 | MEN Low。アドレス＝ACC の下位 12 bit。読んだ語を dma に書く。PC をスタックから戻す | WE Low。アドレス＝ACC の下位 12 bit。dma の内容をデータバスに出す。PC をスタックから戻す |
| 3 | MEN Low。次命令をフェッチ | 左と同じ |

- TBLR と TBLW は 4 段のハードウェアスタックを 1 段使う。そのため、これらを使うときに入れ子にできるサブルーチンと割込みは 3 段までになる [D T1 2-14]。
- 番地の計算も含めると、プログラムメモリを使ったデータ拡張は最短 4 クロック（800 ns）、平均 6 クロック（1200 ns）程度 [D T1 5-17]。

### 3.5 リセット（RS）[D T1 2-19, 2-22; T2 A-22]

| 項目 | 値・状態 |
|---|---|
| tw(R) | 5 tc(C) 以上 |
| tsu(R) | CLKOUT 基準で 50 ns 以上。RS はクロック周期のどの時点で入ってもよく、この値は同期動作を保証する最小値（注6） |
| td11 | RS から DEN↑・WE↑・MEN↑ まで最大 tc/2+50 ns（特性値） |
| tdis(R) | RS からデータバスの切り離しまで最大 tc/4+50 ns（特性値） |
| リセット中の信号 | DEN・WE・MEN は High、D15–D0 は Hi-Z。A11–A0 と PC は次の完全な 1 周期の後に 0 へクリアされ、**出力を続ける** |
| リセット中の内部状態 | 割込み禁止（INTM＝1）、INTF クリア、OVM は**変わらない**。ACC・AR・ARP・DP・T・P・データRAM の扱いは記述がない → 未確認 [V] |
| 解除 | RS↑ から 1 周期後に 0 番地から実行を再開（注9）。RS の入る位相により時間がずれる（注10） |
| CLKOUT | リセット中も出続ける（タイミング図による） |

### 3.6 INT / BIO [D T1 2-18, 2-19, 6-4; T2 A-23, A-24]

| 項目 | INT | BIO |
|---|---|---|
| tf（立下り時間） | 最大 15 ns | 最大 15 ns |
| tw（パルス幅） | tc(C) 以上 | tc(C) 以上 |
| tsu | CLKOUT↓ の 50 ns 前まで | CLKOUT↓ の 50 ns 前まで |
| 非同期入力の扱い | 74ALS74 で CLKOUT↑ に同期させる推奨回路あり | 同じ |

- **INT**：
  - 立下りエッジは INTF にラッチされ、Low レベルでも要求になる。
  - INTM＝0 のとき 2 番地へ分岐する。分岐の際に PC を積み、INTM をセットし、INTF をクリアする。
  - 割込みが待たされる条件は三つ：複数サイクル命令の終了まで、MPY/MPYK の次の命令の終了まで、EINT の次の命令の終了まで。
  - 割込み受付時の流れは、N+2 をダミーでフェッチした後に 1 ダミーサイクルを置き、002 番地をフェッチする（図2-12）。
  - DINT 中も割込みはラッチされ続ける。DINT や EINT は INTF に影響しない。
- **BIO**：BIOZ 命令（2 語・2 サイクル）で調べる。毎サイクルサンプルされ、ラッチはない。BIOZ のどのサイクルでサンプルされるかは未確認 [V]。

### 3.8 演算予算（20.000 MHz、毎秒 500 万サイクル）[V]（サイクル数は [D]、規模の目安は試算）

> 注（2026-11-25）：映像は DR-002 で約 59.92 Hz に改めた。1 フレームあたりのサイクル数は約 83,400 のまま変わらない（5,000,000 ÷ 59.92 ≒ 83,445）。

- 映像 1 フレーム（59.94 Hz）あたり約 83,400 サイクル。8 kHz 音声 1 サンプルあたり 625 サイクル [D: 計算]。
- **FIR**：
  - 1 タップは LTD＋MPY（または MPYK）の 2 サイクル＝400 ns。
  - T1 5-16 の例（入力、ZAC、LT、MPY、(LTD,MPY)×(N−1)、APAC、SACH、出力、B）から数えると、N タップで **2N＋9 サイクル/サンプル**になる [D T1 5-15, 5-16 と Table 3-2 から計算]。
  - 割込みでサンプルを受けると約 18 サイクル/サンプルが加わる（T1 の例では 2.9%）[D T1 6-4, 6-5]。
  - リピート命令はない。ループは BANZ（2 サイクル）か、命令を展開して書く [D T1 3-6, 3-7]。
- **8 kHz 音声**：
  - 演算だけで見ると N ≤ 約 300 タップ。
  - 実際の上限は内部RAMで決まる。係数を RAM に置く MPY 方式では、遅延線と係数で 2N 語 ≤ 144 なので **約 64 タップ**。
  - 係数を MPYK の即値（13 bit 符号付き、−4096〜4095）にすれば遅延線だけになり、**約 120 タップ**まで。遅延線は 128 語のページ0に置く [D T1 3-44 MPYK]。
  - LTD/DMOV がページ0 からページ1 の境界（127→128）を越えるときの動作は未確認 [V]。
- **32 kHz**：156 サイクル/サンプルなので、演算上限は約 70 タップ。
- **128×96 画像（12,288 画素）**、1 画素 1 語で入出力する場合：

| 処理 | 目安（サイクル/画素） | 1 枚あたり | 最大フレームレート |
|---|---|---|---|
| 点処理（IN, LT, MPYK, PAC, SACH, OUT, BANZ） | 約 10 | 約 12.3 万サイクル（25 ms） | 約 40 Hz |
| TBLR による変換表引き | 約 11 | 約 27 ms | — |
| 横 3 タップ | 約 16 | 約 39 ms | 約 25 Hz |
| 3×3 畳み込み | 約 30 | 約 37 万サイクル（74 ms） | 約 13 Hz（演算のみ） |

  - §07 の「15 Hz 捕捉」に 3×3 を実時間でかけるのは成立しない。7.5 Hz 程度なら可能。
  - 3×3 では 128 画素の行 3 本（384 語）が内部RAMに入らない。Data Fabric のストライド転送で 3 行分を列順に送るか、プログラムRAMを行バッファにして TBLR/TBLW（各 3 サイクル）で使う必要がある。
- **I/O と Data Fabric の帯域**：DSP の IN/OUT は最大で毎秒 250 万語。仕様書 §07 の Fabric 試算（16 bit 幅で 2.4 MB/s、つまり毎秒 120 万語）の方が先に上限になる [D: 計算]。

## 4. レジスタ・命令

### 4.1 レジスタ [D T1 2-4〜2-15; T2 A-5 ブロック図]

| レジスタ | 幅 | 内容 |
|---|---|---|
| ACC | 32 bit | ALU とアキュムレータ。オーバーフローモード（OVM）では最大・最小値で飽和する |
| P | 32 bit | 乗算結果 |
| T | 16 bit | 被乗数 |
| AR0, AR1 | 16 bit | 間接アドレスに使うのは下位 8 bit。自動増減とループ判定（BANZ）は下位 9 bit だけで、上位 7 bit は変わらない |
| ARP | 1 bit | AR0 と AR1 のどちらを使うか |
| DP | 1 bit | データページ（0：0–127、1：128–143） |
| PC | 12 bit | プログラムカウンタ |
| スタック | 12 bit×4 段 | PUSH/POP は ACC の下位 12 bit と入れ替える。あふれると最も深い段が失われる |
| ST | — | OV, OVM, INTM, ARP, DP。SST で保存する |

- SST を直接アドレスで実行すると、DP に関係なくページ1に書く [D T1 2-15]。
- LST では INTM を変えられない。INTM を変えるのは EINT と DINT だけ [D T1 2-14, 2-15]。
- 保存形式のビット配置：bit15＝OV、14＝OVM、13＝INTM、8＝ARP、0＝DP、その他は 1 [D T1 2-15 図2-7（判読は一部）; M1 L111]。

### 4.2 アドレッシング [D T1 3-1, 3-2; T2 A-7, A-8]

- **直接**：命令の下位 7 bit（dma）と DP を合わせて番地にする。
- **間接**：bit7＝1。AR[ARP] の下位 8 bit を番地にする。bit5 で増、bit4 で減、bit3＝0 のとき bit0 を新しい ARP にする。
- **即値**：LACK（8 bit 符号なし）、LARK、MPYK（13 bit 符号付き）、LARP、LDPK [D T1 5-17, 3-44]。
- 間接アドレスで 144〜255 番地を指したときの動作は未確認 [V]。

### 4.3 命令の概要と DSP 用の命令 [D T1 3-5〜3-7, 3-41, 3-43, 3-44, 5-14〜5-16]

- 乗算は LT（T にロード）、MPY または MPYK（P＝T×オペランド）、PAC・APAC・SPAC（P を ACC に移す・加える・引く）の組み合わせ。
- LTA は LT と APAC を、LTD は LT・APAC・DMOV を 1 サイクルで同時に行う。
- MPY/MPYK の直後の命令の間は割込みが入らない。T1 は、MPY/MPYK の後に PAC・APAC・SPAC・LTA・LTD のどれかを置くよう推奨している。
- 0x8000×0x8000 の結果は 0xC0000000 になる（正しい値は出ない）[D T1 3-43]。
- ABS で 0x80000000 は、OVM＝0 なら 0x80000000 のまま、OVM＝1 なら 0x7FFFFFFF になる [D T1 3-9]。
- シフタ：入力側は 0–15 bit の左シフトで、符号を拡張する。SACH の出力側は 0・1・4 bit [D T1 1-2, 2-5〜2-7]。1985-10 版データシートは「0 to 16-Bit Barrel Shifter」と書いている [D T2 A-3]。16 bit シフトは ADDH/SUBH/ZALH 系を含めた表現と推定する [V]。
- 命令の上位バイトによる分類（デコーダ実装用）[D M1 L809–851。T1 Table 3-2 と照合済み：IN, OUT, TBLR, TBLW, BIOZ, MPYK, DMOV, LTD, MPY]：

### 4.4 初期化の定型 [D T3 4-1]

- リセットで決まらない状態は、すべてソフトで設定する前提にする [P]。

## 追補（2026-11-25）

OI-021（TI 資料と MAME のサイクル数）と OI-034（IMS1420 の構成）を調べた結果。1983〜85年の TI 資料（T1・T2・T3）を正とし、項目ごとに判定する。T4（1987年）は後年の資料で、復元の補助にだけ使う。本文は書き換えず、食い違う箇所への注をこの節に置く。新しい資料 ID は末尾の「追補の資料一覧」を参照。

### A. OI-021：サイクル数の判定

| 項目 | TI 資料（1983〜85年） | MAME（M1） | 判定 |
|---|---|---|---|
| 条件分岐（BANZ、BGEZ、BGZ、BIOZ、BLEZ、BLZ、BNZ、BV、BZ）の不成立 | 各命令の頁はすべて「Words: 2、Cycles: 2」で、成否で分けた値はない [D T1 3-16〜3-24; T2 3-16〜3-20; T3 3-16〜3-24]。命令一覧の表も 2 [D T1 3-6; T2 A-10] | 表の値は 1。成立したときだけ `add_branch_cycle()` で 1 を足す。不成立は 1、成立は 2 [M1 L404–498, L806, L841–842, L855–857] | **TI を正とし、成否によらず 2**。2 語の命令は 2 語目（分岐先の番地）をフェッチするので、不成立でも 1 サイクルでは終わらない（推定）。MAME の注釈（L806）も「成立したとき 2」と書くだけで、不成立の 1 の根拠は示していない |
| 割込みの受付 | 図2-12：N+2 をダミーでフェッチした次のサイクルが「DUMMY CYCLE」で、そこで 002 番地をフェッチし、その次で 002 の命令を実行する。受付で増えるのは 1 サイクル [D T1 2-19 図2-12] | `Ext_IRQ()` が 3 サイクルを返す（PUSH 2＋DINT 1。注釈は「PUSH and DINT operation ?」）[M1 L983–994] | **TI を正とし 1**。MAME の 3 は注釈のとおり推測の値 |

| BIO のサンプル | 毎サイクルサンプルし、ラッチしない [D T1 2-18 §2.9]。CLKOUT↓ の 50 ns 前のセットアップ [D T2 A-23〜A-24]。非同期の入力は 74ALS74 で CLKOUT↑ に同期させる回路を推奨 [D T2 A-24] | BIOZ を実行する時点の値で判定 [M1 L440–448] | BIOZ のどのサイクルで見るかは 1983〜85年の資料にも T4（後年）にもない [V]。分岐先のフェッチは 2 サイクル目なので、判定は 1 サイクル目のうちと考えられる（推定）。エミュレータは「BIOZ の 1 サイクル目の CLKOUT↓ で見る」とする案 [P]。外部で同期させれば、実チップとの差は最大 1 サイクル（200 ns）（推定） |

T1 6-4〜6-5 の割込み処理の例は、負担を「18/625＝2.9 %」とする [D T1 6-4〜6-5]。列挙された命令を表3-2 で数えると、BGZ が成立する経路で 19、不成立で 20 になり（計算）、18 と合わない。内訳も書かれていないので、受付のサイクル数や分岐の不成立のサイクル数を決める根拠には使えない（推定）。

エミュレータへの反映（案）[P]：条件分岐は成否によらず 2、割込みの受付は 1 ダミーサイクル（図2-12 の流れ）、リセットは TI の状態にする。MAME と比べるとき（V3）は、この 2 点の差を既知の差として扱う。

| 富士通の 1984年の互換表 | IMS1420 を MB8168（4K×4）に対応させる | [D FUJ84 PDF p.6]（review-digital の資料） |

| TI の 1987年版の同じ図 | 「16K X 16 DATA RAM (IMS1420) (16 UNITS) (4K X 1 70-NS SRAM)」。本文は「up to 16K words of static RAM (IMS1420)」 | [D T4 PDF p.220]（後年） |

結論：
- **IMS1420 は 4K×4**。INMOS 自身の 1981〜83年の資料と富士通の互換表が一致する。
- TI の図6-3 の「IMS1420」と「16K×1」は図の中で食い違う。16 個で 16K×16 を組み、A13–A0 を直接つなぐ構成に合うのは 16K×1 品で、INMOS では IMS1400 系にあたる（推定）。1987年版は「4K×1」と書き換えたが、これも 16K×16・16 個と合わない（後年）。
- 仕様書の DSP プログラム RAM（HM6168H-55、4K×4、DR-008）には影響しない。IMS1420-55・MB8168-55 は同じ 4K×4・55 ns 級の代替候補になる [O]（ピンの互換は未確認 [V]）。

### C. 本文への注

- 注（2026-11-25）：§3.2 の「IMS1420（16K×1、70 ns SRAM）」は TI の図6-3 の表記をそのまま写したもの。IMS1420 は 4K×4 で、図の「16K×1」の部品は IMS1400 系と考えられる（推定）（追補 B）。
- 注（2026-11-25）：§3.7 の「TI の表では分岐の成否によらず 2 サイクル」は、各命令の頁（T1・T3 の 3-16〜3-24）でも同じ（追補 A）。
- 注（2026-11-25）：§6.2 の「条件分岐のサイクル」の判定は「TI を正とし 2」、「割込み受付」の判定は「TI を正とし 1」とする（追補 A）。
