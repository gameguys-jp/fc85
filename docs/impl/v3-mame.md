# V3：MAME との照合

IC のコアを、独立した実装（MAME）と同じ入力で動かし、結果を比べる（検証 V3）。コアは台帳（`docs/parts/`）と原典から書いたもので、MAME のコードは写していない（DR-040）。ここでは、照合のやり方と、見つかった差の扱いを書く。

|---|---|---|

| HD63484 | MAME `src/devices/video/hd63484.cpp` | まだ |

## 02　やり方

- **入力の列**は、リポジトリの `tools/v3/<IC>_vectors.py`（Python の標準ライブラリだけ）で作る。乱数の種と件数を引数で渡すので、同じ列を作り直せる。
- **照合の相手**は、リポジトリの外のフォルダ（以下 `<v3>`）に置く。MAME のソースを取ってきて、MAME の枠組みの最小限の代わり（`emu.h` など）と一緒に C++ で組み、入力の列を実行して結果を書き出す。MAME のソース、組んだもの、出力はリポジトリに入れない。
- **照合**は、リポジトリの `emulator/crates/chips/tests/<IC>_v3.rs`。環境変数 `FC85_V3_DIR` に `<v3>` を渡すと、入力と相手の出力を読んで、コアを同じ入力で動かして比べる。ないときは何もせずに合格する。

```
FC85_V3_DIR=<v3> FC85_V3_VERBOSE=2 cargo test --release -p fc85-chips --test tms32010_v3 -- --nocapture
```

`FC85_V3_VERBOSE` は、食い違いの種類ごとに出す例の数。

食い違いは、次の 3 つに分ける。

| 分類 | 意味 | 扱い |
|---|---|---|
| (a) コアの誤り | 資料に書いてあるのに、コアが違う | コアを直し、資料の頁と単体試験を付ける |
| (b) MAME の誤り | 資料、または MAME 自身のほかの命令と食い違う | `<v3>` の側で MAME のソースに手元の直しを当てて照合を続けるか、既知の差として数える。直しはリポジトリに入れない |
| (c) 資料にない動作 | どちらが正しいか、資料では決められない | 既知の差として数え、実チップでの確認（V4）の候補にする。MAME の動作が実機の測定に基づくときは、コアをそれに合わせ、V4 の候補にもする |
| (d) 資料と測定の食い違い | MAME が実機の測定に基づいて、資料と違う動作をする | 測定に基づく方を取ってコアを直し、資料と違うことを台帳と [emulator.md](emulator.md) §03 に書く。V4 の候補にする |

既知の差は、照合の試験の中に、分類と根拠を付けて書く。既知の差でない食い違いがあれば、その場合（入力の 1 件）はそこで止め、命令と項目の組で数える（その先は状態がずれるので比べない）。

## 03　TMS32010

### 比べるもの

1 命令ごとに、PC、ACC、P、T、AR0、AR1、状態語、スタック 4 段、サイクル数と、その命令のバスの出来事（IN、OUT、TBLW の書込み）、変わったデータ RAM の語を比べる。入力の 1 件は、データ RAM 144 語、IN のポート 8 つの値、BIO、プログラムの 512 語（命令の形を重みにした乱数）。

MAME の側は、1 回の呼出しで 1 命令だけ実行する（`m_icount` を 0 にして `execute_run`）。MAME のリセットは OVM を 1 にするが、本機のコアは TI の資料どおり OVM を変えない（台帳 §3.5、追補 A）。照合では MAME の状態語をコアの初めの状態（0x3EFE）にそろえる。データ RAM は 0〜143 番地で、144〜255 番地は読むと 0、書込みは捨てる（どちらも同じ）。

### 結果（2026-11-26）

| 列 | 件数 × 命令 | 一致 |
|---|---|---|
| 種 1985 | 5000 × 24 | 既知の差のほかはすべて一致。2 件は既知の差（7F の群）で打ち切り |
| 種 2026 | 20000 × 48 | 既知の差のほかはすべて一致（959175 命令）。31 件は既知の差（7F の群）で打ち切り |

### 差と分類

| 項目 | 分類 | コア | MAME | 根拠 | 扱い |
|---|---|---|---|---|---|
| SAR を間接で使い、自分の AR を増減するとき | (a) | 増減の後の値を書く（直した） | 同じ | T3 3-55〜3-56 の WARNING（AR0＝10 で `SAR AR0,*+` は 10 番地に 11、`SAR AR0,*-` は 9）[D] | 以前のコアは「資料にない」として増減の前の値を書いていた。試験 `sar_of_the_stepped_ar_stores_the_new_value` |
| ADDH の OV | 一致 | 32 bit の和の桁あふれ（SUBH と同じ） | 同じ | T3 3-11 の演算は (ACC)＋(dma)×2^16 で、SUBH（T3 3-62）と同じ形 [D] | mame0289 のタグの版は、足す値をいつも正とみなしていた。master の f5e3f955888e で直った |
| ADDH の OVM＝1 の飽和 | (b) | 累算器を 0x7FFFFFFF・0x80000000 にする | 上位の語だけを 0x7FFF・0x8000 にし、下位の語を残す | T1 §2.2.1.1 のあふれのモードは、累算器を最大・最小の値にする [D]。MAME のほかの加算の命令も 32 bit で飽和する | 手元で直して照合 |
| SST を間接で使うときの次の ARP | (b) | 指定どおりに変える | 変えない | T3 3-59 の書式 `SST {*\|*+\|*-}[,<ARP>]` [D] | 手元で直して照合 |
| 条件分岐が飛ばないときのサイクル数 | (b) | 2 | 1 | 各命令の頁は成否によらず 2（台帳 追補 A、DR-032）[D] | 既知の差（4 万件ほど）。実測は V4 |
| 未定義の命令のサイクル数 | (c) | 1 サイクルの NOP | 0 サイクルで何もしない | 資料にない [V] | 既知の差 |
| 7F の群の未定義の語（7F83 など） | (c) | 1 サイクルの NOP | 下位 5 bit だけで解読し、7FA0〜7FFF を 7F80〜7F9F の命令として実行する | 資料にない [V] | 既知の差。状態がずれるので打ち切る |
| DMOV・LTD で 255 番地を指すとき | (c) | 写さない | 0 番地へ回り込んで写す | 資料にない（台帳 §7 の 6）[V] | 既知の差。MAME の RAM にそろえて続ける |
| SUBC の OV | 一致 | 変えない | 変えない（OV の式はあるが、条件がいつも偽） | T1 の命令の頁は OV に触れない | 以前の emulator.md の「MAME は SUBC で OV を立てる」は誤りだった |

### 比べていないもの

- 割込み：MAME は受付に 3 サイクル、コアは 1 ダミーサイクル（台帳 追補 A、DR-032）。照合の入力に INT は入れない。
- リセットの途中と RS の幅、サイクルの中のバスのストローブ（MAME は命令の単位で動く）。
- 144〜255 番地の読み書き：MAME の側は割り当てのない番地として 0 を返す形にしたので、実チップの動作は比べていない。

### V4（実チップ）の候補

1. 条件分岐が飛ばないときのサイクル数（台帳 §7 の 5）。
2. 未定義の命令（7F の群の解読を含む）の動作とサイクル数。
3. 144〜255 番地を指したときと、DMOV・LTD が 255 番地から写すときの動作（台帳 §7 の 6）。
4. SST を間接で使うときの番地。T3 3-59 は、直接の番地をページ 1 とし、例に `SST DAT1` と `SST *,1`（AR＝1）を並べる。間接もページ 1 になるのか、AR の下位 8 bit なのかは書いていない（コアと MAME はどちらも AR の下位 8 bit）[V]。

## 04　MSM5205

### 比べるもの

V̄C̄K̄ の立下り・立上りの時刻、取込みの時刻と、取込みの後の予測値・ステップ番号を、発振クロックの単位で比べる。入力の 1 件は、S1・S2・4B のピン、取込みごとのデータと RESET（取込み 300〜400 回）、S1＝S2＝H のときは外から V̄C̄K̄ を動かす半周期（3〜199 クロック。取込みまでの 6 クロックより短い場合も含む）。データは、乱数の列と、同じ向きの大きい差分を続けて予測値を端まで振る列を混ぜる。

MAME の側は、MAME の時刻の仕組みの代わりに、クロック 1 つずつ進む簡単な予定表で、V̄C̄K̄ と取込みのタイマを動かす。データと RESET は、両方の側とも、最初の V̄C̄K̄ の立下りの後の立上りごとに次の語を入れる（本機のブリッジが立上りで次のデータをラッチするのに合わせた。台帳 §3.2）。時刻は最初の立下りから数える。電源投入の直後の V̄C̄K̄ のレベルは、MAME が L、コアが H で、初めの半周期がずれる（どちらも資料にない [V]）。

MAME の 3-bit モードは、D3〜D1 の 3 bit を下に詰めて `data_w` に渡す決まりなので、照合の道具がそう渡す。中では D0 を 0 にした 4 bit として扱い、コアと同じになる。

### 結果（2026-11-26）

| 列 | 件数 × 取込み | 一致 |
|---|---|---|
| 種 1985 | 2000 × 300 | クリップで比べて、すべて一致 |
| 種 2026 | 10000 × 400 | クリップで比べて、すべて一致。回り込み（本機の標準）では 48 件が一致し、残りは、相手がクリップした取込みから食い違う（既知の差） |

### 差と分類

| 項目 | 分類 | コア | MAME | 根拠 | 扱い |
|---|---|---|---|---|---|
| 予測値のあふれ | (b) | 12 bit で回り込む（本機の標準）。クリップも選べる | −2048〜+2047 でクリップする | データシートは回り込み（台帳 §4.4、DR-021）。MAME の注釈も、MSM5205 にあふれを防ぐ回路はないと書く | クリップで照合し、回り込みでの食い違いは既知の差として数える |
| 周期の途中で S1・S2 を変える | (c) | 周期の中の位置を保つ | V̄C̄K̄ のタイマを、変えた時点から半周期で始め直す | 資料にない [V] | 照合の入力では変えない。コードを読んで分かった差 |
| 電源投入の直後の V̄C̄K̄ | (c) | H | L | 資料にない [V] | 最初の立下りで時刻をそろえる |

MSM5205 のコアの式は、台帳に MAME の実装を読んで書き起こしたものなので（台帳 §4.2）、この照合は、書き起こしとコードの組み立ての誤りを調べるもので、式そのものの正しさは確かめない。式が実 IC と合うかは V4（台帳 §7）。

## 05　ES5503

### 比べるもの

DOC サイクル（E の 1 周期）ごとに、訪れたオシレータの番号、波形の番地と読んだ値、訪れた後のアキュムレータ・制御・波形データ・音量、SIG±（符号付きの波形値×音量）、IRQ を比べる。リフレッシュのサイクルと、走査していないサイクルは、種類を比べる。入力の 1 件は、波形 RAM 128 KiB（両方の側に同じ式の xorshift で作り、0 の混ざる割合を 4 通りに変える）、有効数（1〜32）、32 個のオシレータの初めのレジスタと、1〜199 サイクルおきのホストのアクセス（制御・ほかのレジスタ・0xE1 への書込みと、0xE0 の読出し）で、4000 サイクル動かす。ホストのアクセスはサイクルの後（E High の窓）に入れ、0xE0 を読んだ値も比べる。

MAME の側は、MAME の時刻の代わりにクロックを 8 ずつ進め、`run_to` で 1 スロットずつ動かす。SIG± は、MAME が足し合わせるミックスの差分から取る。最上位のオシレータを 3 倍して足す分は、割って戻す。音量は、MAME v3.1 の非線形の表（IIGS の測定）を直線（音量×256）に置き換えて比べる。本機のコアは単純な乗算で（E1 p.6）、非線形の特性はコアの外で足す扱いにしている（下の「比べていないもの」）。レジスタの崩れは、コアの側を止める（4000 サイクルでは MAME の崩れ（1.5 秒）は起きない）。

### 結果（2026-11-26）

| 列 | 件数 × サイクル | 一致 |
|---|---|---|
| 種 1985 | 200 × 4000 | すべて一致（80 万行） |
| 種 7 | 2000 × 4000 | すべて一致（803 万行。0xE0 の読出し 27,677 回、うち提示のあったもの 20,848 回。止まったオシレータが動き出した訪問 38,246 回） |

### 差と分類

初めの照合では、すべての件が 1 サイクル目から食い違った。コアは E1 の文に従い、資料にない細部だけを MAME から書き起こしていたが、MAME v3 は IIGS の実機の測定（DOCGRADE）に基づいて、E1 と違う動作や、台帳に書いていなかった細部を持っていた（台帳 §6 の精度上の注意 1）。次の項目は、測定に基づく方を取ってコアを MAME に合わせ、照合が一致するまで直した（[emulator.md](emulator.md) §03、台帳 ES5503.md 追補 2026-11-26）。

| 項目 | 分類 | 以前のコア | 今のコア（MAME） | 根拠 |
|---|---|---|---|---|
| 走査の始まり | (c) | 0xE1 に書くと 0 番から | リセットでカウンタが 21 になり、22 番から 31 番を回って 0 番へ | 資料にない [V] |
| リフレッシュ中の 0xE1 | (c) | 影響しない | 残りのリフレッシュをやめ、カウンタの次から続ける | 資料にない [V] |
| M0＝1・H＝1 の巻き戻し | (c) | 止まっているのを見つけた訪問ですぐ | その次の訪問で。CPU が動かし直すと、ワンショット・スワップは頭から、フリーラン・同期は続きから | E1 p.8 は時期を書かない [V] |
| 同期の偶数番 | (c) | 端数を残す | 端数を捨てて 0 から | E1 p.8 は奇数番のことだけを書く [V] |
| スワップと、ワンショットの組 | (c) | 偶数番・奇数番とも、止まると相手を起こす | 偶数番だけが起こす。止まっている偶数番は、組の奇数番がスワップで止まっているのを見て動き出す。そのときワンショットの偶数番は止まらない | E1 p.8 の「次のオシレータ」の読み方 [V] |
| 割込み | (d) | E1 p.7 どおり：IE＝0 の完了をテーブルに残し、IE を 1 にすると渡す。OIR は先入れ先出し | 要求は IE＝1 のときだけ立ち、1 件ずつ走査の順に提示する。制御の書込みで、待っている要求が消える。提示したサイクルのうちの読出しでは消えない | E1 p.7 と違う。1986 年の ERS より実機の測定を取った [V] |
| 見えないビットの初めの値 | (c) | （なかった） | 電源投入と崩れで、前の停止と要求のビットも 1 | 資料にない [V] |

(b) に当たるもの（MAME の誤り）は見つからなかった。

### 比べていないもの

- 音量の特性：MAME v3.1 の非線形の表（IIGS の測定。台帳 §4.5）。コアは単純な乗算で、表は直線に置き換えて比べた。特性は同じ式を `es5503::volume_level` に書き、board 層のアナログの S/H で使う（[emulator.md](emulator.md) §03）。式の値は単体試験（`the_doc_volume_follows_the_measured_curve`）で台帳の手計算と比べた。
- レジスタの崩れ：コアは保持時間の分布（emulator.md §03 の「レジスタの保持」）、MAME は 1.5 秒で全ビット 1。MAME はオシレータのどれかのレジスタに書くと、そのオシレータの全部を新しくする（コアは書いたレジスタだけ）。
- A/D、波形 RAM のリフレッシュの行（MAME は扱わない）、出力のパイプラインの段数、チャンネルごとのサンプルホールドと加算、最上位のオシレータの 3 倍（コアはリフレッシュの 2 サイクルの間 SIG± を保つ形。emulator.md §03）。
- ホストのアクセスの時刻：両側とも、サイクルの間の 1 点だけ。

### V4（実チップ）の候補

1. 割込みの規則：E1 p.7 のテーブルと先入れ先出しか、MAME の 1 件ずつの提示か。
2. 走査の始まり、巻き戻しの時期、スワップ・ワンショット・同期の組の規則。どれも IIGS の個体の測定で、1984〜85 年の個体で同じかは分からない（台帳 §7 の 4）。
3. 音量の特性と、最上位のオシレータの 3 倍。
4. レジスタの保持時間（emulator.md §03 の [P]）。

## 06　`<v3>` の中身

リポジトリには入れない。作り直すときの手がかりとして書く。

| ファイル | 中身 |
|---|---|
| `fetch.sh` | MAME のタグのソースから、照合に使うファイルを取ってくる |
| `fetch_master.sh`・`fetch_commit.py` | §01 の master のコミットのソースを取ってくる（`master/`）。照合はこちらを使う |
| `shim/` | MAME の枠組みの最小限の代わり（デバイス、番地の空間、メモリの読み書きの口、波形 ROM の読出しの口、タイマをクロック 1 つずつ進める予定表、音声の流れの空の口）。MAME のコードは写していない |
| `es5503/harness.cpp`・`run.sh`・`cmp.sh` | ES5503 の照合。音量の表を直線に置き換え、1 スロットずつ動かして書き出す |
| `msm5205/harness.cpp`・`run.sh`・`cmp.sh` | MSM5205 の照合（TMS32010 と同じ形） |
| `tms32010/patch.py` | §03 の (b) の手元の直しを当てた写しを作る |
| `tms32010/harness.cpp` | 写しを組み込み、入力の列を 1 命令ずつ実行して書き出す |
| `tms32010/run.sh` | 入力の列を作り（`tools/v3/tms32010_vectors.py` に件数・命令の数・種を渡す）、組んで動かす |
| `tms32010/cmp.sh` | 照合の試験を動かす |
